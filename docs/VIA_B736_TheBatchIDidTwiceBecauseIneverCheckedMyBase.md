## 二 · 十條條款,一條都沒攔住它

令二要的是「更新模組或修正模組都要有嚴格的把關擊斃機制」。我做了 `CGC_MDL187`,十條條款:

| 條款 | 律 |
|---|---|
| KILL-01 語法 | 改動過的 `.py` 必須 `ast.parse` 得過 |
| KILL-02 尾版律 | 出了新 `_vNNNN`,同名舊版必須一個位元都沒動 |
| KILL-03 正本 | `references/intake/` 底下不准改 |
| KILL-04 不可動 | 批345 Celeritas/AegisNexus · 金融機構 SSOT |
| KILL-05 L70 | `.ps1` 未經操作員逐次許可不得改 |
| KILL-06 L50 | 新增行不得 `import ta·lib` |
| KILL-07 同意閘 | 不得把同意閘設成放行值、不得寫死金鑰 |
| KILL-08 自測 | 改動過的引擎要有 `--selftest` 且 rc 誠實 |
| KILL-09 檢號 | 不得**新增**撞號(既有撞號記債) |
| KILL-10 翻令留痕 | 刪掉既有 `chk` 檢名要留得出痕 |

**十條全過。** 我那批廢掉的改動,十條一條都沒中——
因為它們**全部只問「這次改了什麼」,沒有一條問「你改的是不是當下那一版」。**

所以有了第十一條:

> **KILL-11 基線時效** —— 新出的 `_vNNNN` 必須正好接在**預設分支當下的尾版**之後。
> 撞號(mine == tail)/ 舊號(mine < tail)/ 跳號(mine > tail+1)一律擊斃。
> 找不到預設分支參照時記進 `unmeasured`,整體降 `PARTIAL` rc2,**絕不報 PASS**。

它的三個正控就是照我這次犯的錯的形狀擺的:夾具開一條落後一個 commit 的分支,
再去建一個預設分支已經有的版號。負控是「正好接在尾版之後不准擊斃」——
一道連正常升版都攔的閘會被關掉,而**被關掉的閘等於沒有閘**。

這個病不是第一次發作。`CGC_MDL064_SelftestGrid_v0493` 自己的表頭就記著 LL334:
側線取用了 v0492 與批734,本線只能跳號到 v0493、改號批735。**同一個病的前一次。**

> **LL445:落後的基線會讓「改得很乾淨」變成「完全是廢的」。**

## 三 · 這道閘第一次真判,判到的是它自己

閘的十二檢自測全綠之後,我拿它去判本批自己的改動。它當場擊斃了自己三次,
三次都是同一族的病:**量文字不量碼**。

**第一次:** `KILL-06` 咬中 `CLAUSES` 裡那句「不得 import ta·lib」的**說明文字**;
`KILL-09` 咬中自測沙盒夾具裡那串 `'chk("① a", 1)'` **字串字面**。
註解裡提到相依不是相依;字串裡長得像呼叫的不是呼叫。
檢號改走 AST、字面改走 `tokenize` 遮蔽。

**第二次(被自己的正控咬出來):** 全遮之後正控只剩 `KILL-06`,`KILL-07` 沉默了——
同意閘的放行值本身就是字串字面,連字串一起遮,代設同意閘**變成漏判**。
那是我親手開的一個 fail-open 洞,被正控接住。

**第三次:** 不遮 docstring,連「說明這條規則」的那句話也被判成違規。

這兩次把一件事逼了出來:**「字串」不是一種東西,是兩種。**

| | 是什麼 | KILL-06 遮? | KILL-07 遮? |
|---|---|---|---|
| docstring / 裸字串 | **散文**(說明) | 遮 | 遮 |
| 右值字串 | **值**(放行值住這裡) | 遮 | **不遮** |

按語意分開遮才對——而不是為了讓自己過關把條款放鬆。三個洞各補一格成對檢釘住。

**還有一個漏,是第一輪自測五格同時紅逼出來的:**
`git diff` **從來不列未追蹤檔**。一道判「改動」的閘若只看 diff,
最該攔的那一類——「新出一支 `_vNNNN`」「整支全新的模組」——在 `git add` 之前一個都看不到。

> **LL448:`git diff` 從來不列未追蹤檔。**
> **LL449:量文字不量碼。**
> **LL450:「字串」不是一種東西,是兩種。**

`CGC_MDL187` 最終:**18 檢 OK 18 · FAIL 0**。

## 四 · 令三:HTML U/I 實測結果報告

`CGC_MDL188_BatchResultReport_v0100`。**它不是把數字抄成網頁**——
報告裡每一個數字都在產頁的當下現場量:自測真的跑一次、擊斃閘真的判一次、
ADJ 對照真的拿 duckdb 算一次。

兩條設計律,各有一格檢釘住:

- **總判取最差那一格,不取平均。** 四綠一紅 = RED。
  把五格裡的四格綠平均成「大致綠」,就是這棵樹一直在打的假綠。
- **量不到的格子要留在表上寫 ABSENT,不是從表上消失。**
  一張省略了量不到那幾格的報告,看起來會比實際情況漂亮(L57 誠實分母)。

驗證它真的在判而不是在附和:第一次實跑,它把「全格子」那一列判成 **RED**,
因為當下最新的存證是舊的那一跑(OK 345 · FAIL 2)。**它讀的是真存證,不是我的說法。**

> **LL452:報告的總判要取最差那一格,不取平均。**

`CGC_MDL188` 最終:**7 檢 OK 7 · FAIL 0**。
