# 文字與表格重建失敗指南

本指南是 `config/reconstruction_rules.json` 的人類可讀版本。原則只有三個：可證明才修、無證據不合併、不完整不補造。

## 文字整理失敗的 20 個因素

| 代碼   | 因素                | 常見結果                   | 控制方式                           |
| ------ | ------------------- | -------------------------- | ---------------------------------- |
| `T001` | 長段落缺標點        | 多個句意被視為單句         | 長度與標點密度檢測；只標 REVIEW    |
| `T002` | 標題黏入正文        | 標題行含完整句與後續正文   | 標題終止符與長度檢查；禁止自動拆字 |
| `T003` | 標題標記遺失        | 短獨立行被當成普通段落     | 短行候選；只提出建議               |

| `T005` | 重複標題歸屬不清    | 內容掛到錯誤同名章節       | 標題路徑與位置共同識別             |

## 如何分類切割，讓資料成為資訊

| 階段   | 輸入                      | 產出                               | 不可跨越的邊界                             |
| ------ | ------------------------- | ---------------------------------- | ------------------------------------------ |
| 保護   | 原始行                    | no-touch ranges                    | front matter、code、HTML、inline code、URL |
| 區塊   | 可解析行                  | heading/list/quote/table/paragraph | 明確 Markdown marker、空白行、fence        |
| 句子   | paragraph/quote/list text | sentence IDs                       | 版本號、小數、縮寫、括號、URL              |
| 關聯   | sentence + heading stack  | heading path                       | 不跨標題、表格、程式碼或引用邊界           |
| 資訊化 | sentence/table row        | 六類 information units             | 每筆必須可回指來源行與 SHA-256             |

標題與下一句只有在 Markdown 本身已表明從屬關係時才建立「父子關聯」，內容本身不會被字串相接。短行像標題但缺少 `#` 時，只產生 REVIEW 候選，不直接升格。

## 如何驗證已修正且沒有新問題

1. 輸入守門：UTF-8、fence、front matter、表格 shape 必須可解析。
2. 前後守門：標題、連結、圖片、程式碼、inline code、HTML 與正文內容雜湊一致。
3. 重建守門：句子 fingerprint、表格 matrix SHA-256、block sequence 一致。
4. 零幻覺守門：`merge_operations = 0`、`fabricated_cells = 0`。
5. 多解析器守門：remark、markdown-it-py、Pandoc、markdownlint、rumdl、PyMarkdown 交叉檢查。
6. 冪等守門：同一輸入執行第二次必須 `unchanged`，SHA-256 不再變動。
7. 故障注入：故意改連結、句界、表格欄數或 matrix value，必須被拒絕且原檔不變。
8. 批次守門：1、4、16 worker 結果一致；每檔 sidecar 不互相覆蓋。
9. 證據守門：每個資訊單元可回溯 `source_sha256 + source_lines + block_id`。
10. 發布守門：只有 PASS 可自動寫回；REVIEW 人工確認；FAIL 保留報告與候選檔。

## 進一步強化方向

- PDF／掃描文件加入頁碼、BBox、OCR 字信心與欄聚類，才能安全處理跨頁與合併格。
- 建立領域術語 SSOT，將縮寫、人名、版本格式與單位白名單版本化。
- 對大量文件建立重複頁首頁尾指紋，降低 OCR 污染。
- 將 REVIEW 樣本回饋成測試 fixture；規則先經回歸測試，才可升級為自動修復。
- 在 CI 固定工具版本、執行 strict＋冪等兩輪，並保存 JSON 報告與雜湊鏈。
