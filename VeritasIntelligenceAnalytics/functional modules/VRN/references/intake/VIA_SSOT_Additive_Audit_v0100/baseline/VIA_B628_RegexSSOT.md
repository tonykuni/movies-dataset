## 二 · 券商欄 GREEN 0 / YELLOW 59 的真因,不是同義字不夠

矩陣那一欄的判準是「非空且**來源標明出自正典冊**」。實測 81 份:

```
broker_src  →  FILENAME_MAP 61 份 · 空 19 份 · DENY 1 份
```

查下去,overlay 裡有這麼一行:

```python
r["src"] = "FILENAME_MAP" if r.get("src") == "CANON" else (r.get("src") or "FILENAME_MAP")
```

`resolve_broker()` 明明回 `src="CANON"`(**正典冊命中**),這一行把它改寫成 `FILENAME_MAP`。
那 61 份**全是正典冊命中**,標籤在出門前被換掉。

> 檔名是**通道**,正典冊是**權威**。兩件事壓進同一個字串,權威就被通道蓋掉。

`overlay v0102` 拆成 `channel` / `authority`,`src` 合成 `FILENAME_MAP+CANON`:

```
券商    GREEN 0 → 61   ·   YELLOW 59 → 0
矩陣總計 GREEN 237 → 298 ·  YELLOW 69 → 8
```

**加一千條同義字,那一欄還是黃的。**

## 三 · 兩本規則進冊(`VRN_FieldRules_SSOT` · 樞紐 `SUP_MDL749 v0107`)

### 台股代號:原式與修正式兩份都留

你給的「被動股票 ETF `^(00\d{3})$`」是**五碼**。而 `0050` 是**四碼**、`006208` 是**六碼**。
拿九型逐一去比:

```
0050 / 0056 / 006208  →  九型一個都歸不進去
```

那幾檔正是批401 特地補過價格來源的。位數筆誤不會讓正則報錯,只會讓它**安靜地不匹配**。

所以冊上兩份都在:`as_given`(你的原文,逐字不改)與 `corrected`(位數改成 `00\d{2,4}`),
自測 ㉔ 就是拿 `0050` 照那個洞。**位數是可以量的事實,不是同義字裁定**,但原式留著給你對照(LL90)。

九型歸屬實測:`2330` 一般個股 · `0050`/`006208`/`00878` 被動股票 ETF ·
`00757A` 主動股票 · `00679B` 被動債券 · `00675L` 槓桿 · `00632R` 反向 · `00635U` 期貨 · `00713T` 平衡。

### 日期十二式有序表 —— 十五種寫法實測全中

```
20251202 · 1141202 · 251202                      (純數字三式,舊行為零回歸)
2025-12-02 · 2025/12/2 · 2025年12月2日            (西元帶分隔 / 中文)
114-12-02 · 民國114年12月2日 · 114年12月2日        (民國)
25/12/02                                          (兩碼年帶分隔)
2025年12月 · 114年12月                            (年月 → gran=MONTH)
民國114年                                         (只有年 → gran=YEAR)
2 Dec 2025 · Dec 2, 2025                          (英文月)
```

**年月和只有年,不補成一日。**把 `2025年12月` 補成 `2025-12-01` 是捏造一天出來——
不會有紅燈,只會有錯結論。`parse_date_any()` 回 `gran: DAY|MONTH|YEAR`,呼叫端自己決定收不收;
`ENG073` 的報告日只收 `DAY`。

**順序是判準的一部分**:DAY 級一律排在同 era 的 MONTH/YEAR 之前,
否則 `2025年12月2日` 會被 `AD_MONTH` 先吃成年月。
