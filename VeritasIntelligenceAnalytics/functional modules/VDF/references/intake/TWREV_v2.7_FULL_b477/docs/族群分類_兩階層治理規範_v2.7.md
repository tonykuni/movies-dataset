## 1. 為什麼要兩階層

扁平族群表有三個結構性問題:

1. **顆粒度不一致** — 「半導體」和「AI 導軌」放在同一層排名，等於拿一個產業比一個零件。
2. **無法對齊思考路徑** — 實務上先看「AI 伺服器這條鏈強不強」，再往下看「是機殼強還是導軌強」。
3. **重複計數** — 3711 同時在封測與 CoWoS；扁平表加總時同一家公司被計入兩次。

兩階層解法:

```
L1 parent (12 大類)  →  L2 group (46 子族群)  →  個股
```

**L1 加總必須依個股去重**，去重時保留角色最高者 (L > P > G)，龍頭不會被降級。
這條規則有專屬測試 `t_groups_parent_dedupe`：同一檔跨兩子群時，
去重加總 15.4% vs 未去重 19.0%，測試直接斷言不得等於未去重值。

## 5. 矩陣呈現

三層可展開: **L1 大類 → L2 子族群 → 個股**。
L1 的「龍頭／子群」欄顯示子群數，L2 顯示龍頭名稱，兩者共用同一組 grid 欄位定義。

### 對齊的結構性保證 (本次一併修掉兩個潛伏 bug)

縮排**只能加在名稱格**，不能加在整列的 padding —
否則彈性名稱欄被擠壓的量與縮排量在窄螢幕不再相等，後面每個數值欄都會橫移。

三個共用變數把表頭與所有資料列綁在同一個來源:

```css
.gmx{ --pad:12px; --ind:20px; --gap:8px; --gc: ... }
/* 各斷點只改這四個變數, 不再逐選擇器覆寫 padding/gap */
```

修掉的兩個舊 bug (原本只影響產業階層與國際對照區塊):

1. ≤1120px 時 `.ghd` 與 `.grp>summary` 的左右內距不同步 → 整列橫移 3px。
2. ≤640px 時 `.hrow` 的 grid gap 沒跟著縮 (8px vs 6px) → 逐欄累積漂移。

**驗證方式**: Playwright 座標量測，4 個矩陣 (族群/週期/產業階層/國際對照)
× 10 種寬度 (1440→360px)，比對表頭與每一列每一個數值欄的 x 座標，
容差 1px，並確認 `scrollWidth == clientWidth` (零橫向捲軸)。
本版結果: **678 個格位、錯位 0、hscroll 0，全數通過**。

## 6. 測試 (20 項，全過)

本次新增兩項:

- `族群 兩階層` — parent 全覆蓋、階層必須是樹 (一個子族群不得跨兩大類)、

  加總 YoY 等於去重值且**不等於**未去重值、`n_subgroups` 於去重前計算。
