# 台股月營收動能引擎 (Taiwan Stock Monthly Revenue Engine) v2.7

抓取 + 分析 + 儀表板的月營收系統。資料來源為官方 **MOPS 公開資訊觀測站**,
涵蓋全上市 (TWSE) + 上櫃 (TPEX),歷史以 parquet 累計保存。

三大分析層:
1. **三層動能模型** — 累計YoY (主判準) → 多月YoY趨勢 → MoM vs 季節性
2. **真突破偵測** — 創歷史新高 + 年增強,**且排除低基期假象**
3. **族群層** — 兩階層族群 (12 大類 / 46 子族群) × 實證營收動能 + 全市場週期六大類分流

---

## 1. 真突破偵測 (v2.0 新增, 本引擎最核心的濾網)

### 要解決的問題

```
YoY = 本月營收 / 去年同月營收 − 1
```

分母(去年同月)若異常低迷,YoY 會被灌得很漂亮,但公司實際營收可能只是
**回到原本的水準**,根本沒有創新高。一家去年崩掉一半的公司,今年只要回到原點,
YoY 就是 +100%。**只看 YoY 排序,前段會全是這種假象。**

### 五道關卡 (全過才算真突破)

| # | 關卡 | 檢查什麼 | 為什麼 |
|---|------|---------|--------|
| 1 | **ATH** | 當月營收 = 歷史最高 | 等級面證明:客觀上比過去任何一個月都大,基期低不低都不影響「現在是史上最強」 |
| 2 | **持續性** | 近12月滾動營收(TTM)創歷史新高 **且** TTM年增率 ≥ 門檻 | 排除單月一次性訂單;也排除「單月很強但整年其實是平的」 |
| 3 | **YoY 強** | 單月年增率 ≥ 門檻 (預設 30%) | 成長力道 |
| 4 | **基期不低** | (a) 去年同月在歷史分布的百分位 ≥ 40%<br>(b) 去年同月 / 其前12月中位數 ≥ 0.90 | **直接檢查分母健康度** — 去年那個月是不是塌陷的 |
| 5 | **兩年 CAGR** | 跳過去年基期,直接比兩年前,年化 ≥ 15% | 若成長只是從谷底反彈,兩年 CAGR 會很難看 |

**未過關者不會被丟掉**,而是歸入「假突破」清單並標明**是哪一關擋下的** —
這份反面清單本身就是濾網有效的證明(實測中被擋下的假突破 YoY 高達 +249%,
遠高於所有真突破的最高 +71%)。

週期股 (原物料) 一律排除:其營收由價格驅動,ATH 常是價格高點而非需求強度。

### 輸出欄位 (`data/breakout.csv`)

`verdict` (真突破 / 假突破·低基期 / 假突破·兩年無成長 / 高YoY·未創新高 /
單月暴衝·TTM未創高 / 創高·YoY未達門檻 / 排除·週期股)、
`score` (突破強度 0-100)、`g1_ath`…`g5_cagr` (各關卡通過與否)、
`ath_margin` (超越前高 %)、`ath_streak` (連續創高月數)、
`ttm_yoy`、`base_pct` (基期百分位)、`base_ratio` (基期比)、`cagr_2y`。

## 2. 安裝與使用

```bash
pip install -r requirements.txt

python -m twrevenue.cli demo      # 免連網: 合成資料跑通全流程 (含突破偵測)
python -m twrevenue.cli fetch     # 抓 MOPS 全市場 -> parquet/duckdb 增量
python -m twrevenue.cli analyze   # 三層分析 + 真突破 + 族群
python -m twrevenue.cli report    # 產生 HTML 儀表板
python -m twrevenue.cli run       # fetch + analyze + report 一條龍
python -m twrevenue.cli breakout  # 終端輸出真突破名單 + 假突破對照組
python -m twrevenue.cli groups    # 顯示 + 驗證族群分類
python -m twrevenue.cli selftest  # 11 項內建測試 (含突破偵測 3 項驗收)
```

> **關於抓取**:首次 `fetch` 抓 36 個月 × (上市/上櫃) × (國內/KY) ≈ 上百頁,
> 每次請求間隔 5 秒,約需 10–20 分鐘屬正常。抓過的月份會快取,之後每月只補抓一個月。

### 累計增量資料庫

- `data/revenue.parquet` — **SSOT**,歷來所有月份與個股永久累積 (不只 36 個月),
  主鍵 `(stock_id, year, month)` 去重,公司更正月營收時以最新公告覆蓋。**冪等**:重跑淨增 0。
- `data/revenue.duckdb` — SQL 查詢層,每次更新自 parquet 重建 `monthly_revenue` 表。
- 三層動能分析用「最近 `months_back` 個月」視窗;**真突破偵測用完整歷史**
  (歷史越長,ATH 判定越可靠)。

## 3. 三層動能模型

| 層級 | 判準 | 角色 | MOPS 官方欄位 |
|------|------|------|--------------|
| Layer 1 | 累計 YoY | 主判準 · 年度錨點 | 累計營業收入－前期比較增減(%) |
| Layer 2 | 多月 YoY 趨勢 | 成長品質 | 營業收入－去年同月增減(%) |
| Layer 3 | MoM vs 季節性 | 動能拐點 | 營業收入－上月比較增減(%) |
| 輔助 | 2 年 CAGR | 修正基期扭曲 | 由當月營收序列計算 |

**分級**:優選 / 觀察 / 警戒 / 排除(週期)。
**型態**:穩定成長 / 成長趨緩 / 季節性緩成長 / 高波動訂單 / 見頂衰退 / 原物料週期。
**綜合動能分數** = Layer1 45% + Layer2 35% + Layer3 20% (透明加權,可稽核)。

## 3b. 台灣產業分類階層 (SSOT · TWSE/TPEX 整合)

```
L1 大類   電子 / 非電子 / 金融          (台股慣用三分法)
L2 中類   電子八大次產業 · 原物料 · 民生消費 · 機電工業 · 運輸 · 生技醫療 …
L3 小類   TWSE / TPEX 官方產業別 (正規化後的正式名)
```

### 為什麼需要正規化

TWSE 與 TPEX 的產業別名稱不一致,不處理會讓同一種產業在兩個市場被切成兩群:

| 類型 | 例子 |
|---|---|
| 後綴差異 | 建材營造 / 建材營造**業** · 金融保險 / 金融保險**業** · 貿易百貨 / 貿易百貨**業** · 其他 / 其他**業** |
| 歷史更名 | 觀光事業 → 觀光餐旅 |
| **上櫃專有** | 文化創意業 · 農業科技業 · 電子商務 (TWSE 官方 33 類**不含**這三類) |
| 歷史混類 | 化學生技醫療 (舊代碼 07,後拆為化學工業+生技醫療業)<br>電子工業 (舊代碼 13,後拆為半導體業…其他電子業八類) |

**歷史混類一律標記 `ambiguous` 且不強制拆解** —— 硬歸到化學工業會把生技股誤判成
原物料週期股(實際踩過的坑)。

引擎共管理 **38 個正式產業別 + 35 組同義字**,`normalize()` 比對順序:
精確 → 別名 → 去空白/括號 → 補「業」字。VIA 族群簡稱(半導體、鋼鐵、金融…)
也一併吃進同一套正規化,因此族群層與產業層可以互相對齊。

### 階層彙總

儀表板「產業分類階層」區塊:L1 三大類 → 點開看 L2 中類 → 再點開看 L3 官方產業別,
四層欄位嚴格對齊。每層都給:加總累計YoY / 加總YoY (營收加權)、動能分數、廣度、
優選家數、**週期股家數**。原物料與運輸中類會整組掛「週期」徽章、不給動能分數。

`twrevenue/taxonomy.py` 為此層 SSOT;`audit()` 提供自我稽核(別名指向合法、
階層完整、無正式名/別名衝突),已納入 `selftest`。

## 4. 族群層與週期分流

`twrevenue/groups.csv` = 族群分類 SSOT,**兩階層 (two-level)**:
**12 大類 (L1 parent) / 46 子族群 (L2 group) / 235 檔**,
每檔標註大類、子族群、角色 (L 龍頭 / P 第二梯隊 / G 落後)、市場、來源、狀態。

```
L1 半導體     → L2 晶圓代工 / IC設計 / 封測 OSAT / 測試介面·探針卡 / CoWoS /
                   ABF 載板 / 矽晶圓 / 第三代半導體 / 記憶體 / 半導體設備 /
                   半導體材料·耗材 / 半導體通路·代理 / 矽智財 IP /
                   ASIC 設計服務 / 台積電擴廠                        (15 子族群)
L1 AI 伺服器  → L2 AI OEM/ODM / AI 機殼·機櫃 / AI 導軌·滑軌 / 液冷·水冷板 /
                   散熱 / BBU 備援電池 / CPO 共封裝光學              (7 子族群)
```

- **加總表現** = 族群營收加權 YoY (Σ本期營收 / Σ去年同期 − 1),比中位數更能反映體量
- **L1 加總依個股去重**:同一檔跨多個子族群 (如 3711 同在封測與 CoWoS) 只計一次;
  去重保留角色最高者,龍頭不會被降級
- **龍頭確認** = 龍頭營收動能是否 ≥ 族群中位;**✘ 背離** 代表龍頭營收沒跟上
- 矩陣三層展開:**L1 大類 → L2 子族群 → 個股**;週期大類置底標示、不參與動能排名

**`status` 欄 — SSOT 生命週期 (只增不減,任何一列都不刪)**

| status | 意義 | 納入分析 |
|---|---|---|
| *(空)* | 生效 | ✔ |
| `flagged` | 歸屬有疑慮 (誤植 / 關聯薄弱) | ✘ |
| `excluded` | 歸屬正確但**規模稀釋** (該題材佔自身營收過低,加權後失真) | ✘ |
| `superseded` | 已被更細的子族群完全取代 (避免與細分結果重複計數) | ✘ |

`superseded` 受測試保護:其成員必須全數出現在某個生效子族群,否則 selftest 失敗
(細分零遺漏)。`python -m twrevenue.cli groups` 會列出所有保留但不納入分析的列。

**週期分流 · 全市場六大類** (依 MOPS 產業別自動歸類,零遺漏):

| MOPS 產業別 | 週期類 |
|---|---|
| 水泥工業 | 水泥 |
| 鋼鐵工業 | 鋼鐵 |
| 塑膠工業、油電燃氣業 | 石化 |
| 化學工業 | 化工 |
| 航運業 (貨櫃代號清單) | 貨櫃航運 |
| 航運業 (散裝代號清單) | 散裝航運 |
| 航運業 (其餘) | 航運其他 |
| 橡膠、造紙、玻璃陶瓷 | 其他週期 |

航空 (2610/2618/2646) 豁免。週期股改看:價格YoY / 庫存YoY / 產能利用率 / 毛利率YoY。

## 5. 資料來源

```
https://mops.twse.com.tw/nas/t21/{market}/t21sc03_{民國年}_{月}_{i}.html
  market : sii=上市(TWSE), otc=上櫃(TPEX)
  民國年 : 西元 − 1911     i : 0=國內公司, 1=國外KY公司
  編碼   : Big5
```
每月營收於**次月 10 號前後**公布,故「最新可抓月份」= 上個月。
股票代號規則:四碼數字、第一碼不可為零 (`^[1-9][0-9]{3}$`),排除 00xx ETF 與 6 碼 TDR。

## 6. 每月 1–10 號工作流

- **Day 1–3** 抓取更新 → parquet/duckdb 增量合併
- **Day 4–6** Layer1:累計YoY ≥ 10% 且未連續下滑
- **Day 7–8** Layer2:連續 ≥3 月 YoY 正、平均YoY ≥ 15%、低波動
- **Day 9** Layer3 季節性 + 族群/週期分流 + **真突破偵測**
- **Day 10** 產出結論 + 規則檢討(是否過度依賴單月?**基期百分位與基期比是否檢查過?**)

## 7. 已知限制

- 月營收只反映營收面,不含毛利率/ROE。優選池與真突破名單建議再疊獲利指標。
- 週期股的價格/庫存/產能利用率不在 MOPS 月營收內,需另接資料源。
- 「化學生技醫療」(上櫃混類) 刻意不自動歸週期,避免誤殺生技股。
- 若 MOPS 再次遷移網域,請更新 `config.fetch.base_hosts`。

> 本工具為量化篩選輔助,非投資建議。
