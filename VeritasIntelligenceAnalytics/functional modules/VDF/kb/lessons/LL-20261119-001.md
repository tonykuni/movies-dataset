## 1. 異常特徵

批次歸檔腳本呼叫 DuckDB 讀取正在寫入的 `.jsonl` 日誌檔時，在 Windows 環境下拋出 `WinError 32` 或 `PermissionError`，導致當日 Parquet 歸檔任務中斷。

## 2. 根本原因

Windows 檔案系統對開啟中的檔案施加獨佔鎖定。寫入端尚未關閉，歸檔端就讀同一個路徑。

## 3. 解決方案

1. 寫入端依批次切分檔名。
2. 歸檔端先 `os.replace` 成 `.sealed`。
3. 捕捉 `PermissionError` 並跳過仍被佔用的檔。DuckDB 只讀 `.sealed`。

## 4. 驗證指標

- 連續 7 日日誌中 `WinError 32` 次數為 0。
- Parquet 筆數與 `.sealed` 行數誤差為 0。

## 5. 預防機制

禁止直接對未封口的 `.jsonl` 執行 `COPY TO PARQUET`。
