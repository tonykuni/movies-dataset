==========================================================================================
 Veritas WorkOps · 合規版總覽 README
 原則:郵件只「佐證」 · 控管表「治理」 · 你核准才生效 · 不自動寄 · 不自動寫回
==========================================================================================

這個資料夾是一整套「個人工作生產力」工具,全部在你自己的權限、你自己的電腦上跑。
不需要安裝任何東西(PowerShell 與瀏覽器是 Windows 內建)。

------------------------------------------------------------------------------------------
 一、檔案總表
------------------------------------------------------------------------------------------
  Invoke-VeritasMailOps.ps1          ★ 主力:一支打通全流程(掃描/對帳/草稿/範本)
  START_MailOps_OneScript.cmd        ★ 雙擊啟動上面那支(單鍵數字選單)
  Veritas_MailOps_Standalone.html    ★ 視覺化 Dashboard(雙擊用瀏覽器開,離線零安裝)
  Invoke-VeritasMailOps-TrackingDrafts.ps1   追蹤信草稿引擎(單獨版;主力已內含同功能)
  START_TrackingDrafts.cmd           雙擊啟動單獨版草稿引擎
  START_Veritas_MailOps.cmd          舊版選單(SafeLocal 掃描路線)
  README_TrackingDrafts.txt          草稿引擎的細節說明
  VIA_WorkOps_收斂地圖.html           一頁式路線圖(可列印)
  VIA_WorkOps_主力包與對照卡.html     主力包清單+合規對照卡(可列印)

 二、每日 SOP(合規版,滑鼠為主)
------------------------------------------------------------------------------------------
 第 0 步(只做一次):
   雙擊 START_MailOps_OneScript.cmd → 按 [5] 範本
   → 自動建立 templates\ 範本庫、recipients.csv、control_sheet.csv 範例
   → 用 Excel 打開 control_sheet.csv,換成你真實的專案清單(代號/名稱/狀態/最後更新)

 每天下班前 10 分鐘:
   [1] 掃描   → 只讀你自己的 Outlook,匯出 out\mails.csv / pending.csv / stakeholders.csv
              (只觀察,不動任何一封信:不標已讀、不搬移、不刪除)
   [2] 對帳   → 控管表 × 郵件佐證 → out\reconcile.csv + out\proposals.csv
              (只產生「建議」;你的 control_sheet.csv 一個位元組都不會被改)
   打開 proposals.csv → 逐列在 Decision 欄填「採納 / 不採納」
   → 採納的,由你自己改回控管表(這一步永遠是人做,不是程式做)
   [3] 追蹤信 → 對「待覆核」的案子建草稿(○選擇題範本,對方幾乎免打字)
              → Outlook 撰寫視窗跳出來 → 你檢視、微調 → 你親自按「傳送」
   隔天早上:
   [4] 補追殺 → 還沒回的,建「再次追蹤」草稿,同樣你親自寄

 或改用視覺化路線:
   雙擊 Veritas_MailOps_Standalone.html
   → 「載入」頁:把 control_sheet.csv + out\ 裡的 CSV 一起拖進去
   → 「對帳校準」頁(⚖):矩陣顯示六種信心徽章,滑鼠勾選「採納」
   → 匯出 reconcile_proposals_approved.csv(只含你核准的),自行套回控管表
   → 「範本庫管理」頁:編範本、匯出 TPL_*.html 給草稿引擎用

------------------------------------------------------------------------------------------
 三、六種信心徽章(對帳結果怎麼讀)
------------------------------------------------------------------------------------------
  一致          郵件佐證與控管表相符 → 不用動
  控管表過期    對方有更新的來信,你的表還停在舊日期 → 建議更新「最後更新日」
  待覆核        你寄出去等回覆 ≥3 天 → 建議追蹤(接 [3]/[4] 建草稿)
  需人工判讀    表上寫「已完成」但之後還有往來 → 自己看一下是哪種情況
  無佐證        這段期間郵件裡完全沒出現這個案 → 可能要主動問一下
  資料不全      控管表這列缺代號或狀態 → 把表補齊

------------------------------------------------------------------------------------------
 四、合規界線(這套工具「保證不做」的事)
------------------------------------------------------------------------------------------
  x 不自動寄信、不自動回信 —— 一律只建「草稿」,永遠由你本人按傳送(程式不呼叫 .Send())
  x 讀信只讀 —— 不搬移、不刪除、不修改、不標已讀、不動任何既有郵件
  x 不自動改控管表 —— 只輸出建議清單,採納與否、動手改表的永遠是你
  x 不用 Graph/OAuth/API/網路 —— 全程本機,只透過你已登入的 Outlook
  x 不繞過 IT —— Outlook 安全提示照常出現;公司政策封鎖 COM 就停止,不嘗試繞過
  x 不夾帶 BCC 追蹤碼、不監看同事信箱 —— 追蹤靠信件原生的主旨/案號對接

  為什麼這樣設計:同樣的產能(結構化追蹤、進度收割、專案儀表板),
  拿掉的只有「暗抄、自動寄、避開 IT」——那些風險本來是你的職涯在扛。

------------------------------------------------------------------------------------------
 五、疑難排解
------------------------------------------------------------------------------------------
  「無法連上 Outlook COM」  → 先打開傳統版 Outlook(Classic),再執行
  Outlook 跳安全提示        → 正常現象,點允許即可;工具不會也不該壓制它
  [2] 對帳說沒有郵件佐證     → 先跑 [1] 掃描,或到 Dashboard 載入你既有的匯出檔
  中文亂碼                  → 所有 CSV 都是 UTF-8(BOM);用 Excel「資料→從文字/CSV」匯入
