# VeritasAutoPlot：資料轉專業分析圖的核心工具

**VeritasAutoPlot（VAP）是內建分析能力的資料視覺化工具，主流程為「資料 → 分析 → 專業分析圖 → 分析堆圖 → 可重用模板 → Dashboard」。** VIA、SSOT、Registry 和日誌是支援層，不是 VAP 的主操作介面。前次以 VIA 15 能力與 SSOT VisualMaintainer 為主的工作台只能作為可參考元件，不能代表完整 VAP。

本輪以三份新附件為準，原樣抽取 `ssot/vap_spec.json` 與 `ssot/vap_chartlib.json`，兩者維持使用者提供的 v1.0.0；原規則、圖碼、changelog 和 Alpha 亂碼均未擅改。新增 `vap_core` 僅實作規範載入、檢查及安全參數解析，不是金融分析或繪圖引擎。23 項核心契約測試通過，不代表 28 型圖表或分析指標已完成。

## 六個產品核心

### 1. 資料工作區

輸入 DataFrame、CSV、Parquet、JSON、Excel、DuckDB 或 VDF Dataset；Google Sheet 透過來源 Adapter 進入，而不是讓每個圖各自擷取遠端資料。先辨識時間、Ticker、分類、數值、單位、頻率及價格調整基礎，再檢查缺值、重複、異常與來源版本。來源矩陣是產圖的起點，不是另一套治理資料庫。

「直接載入欄位」與「計算衍生指標」必須分開。檔案已有 Sharpe 欄位，可標為外部提供值並繪圖；VAP 自行計算 Sharpe，則需完整公式、視窗、無風險利率及年化契約。不能因欄名存在就聲稱內建分析已完成。

### 2. 內建分析引擎

分析引擎負責趨勢、分布、相關、技術分析、風險績效、策略比較與財務／共識資料整理。計算結果應帶有來源、公式、參數、期間、單位、頻率、資料品質以及 actual / derived / estimated / missing 標記，再交給圖表引擎。

附件要求 SMA / EMA / BB、滾動報酬、滾動相關、Sharpe、Sortino、MaxDD、區間高低、耗時、復原時間、Alpha／超額報酬及 Rank-IC 驗證等分析表達。它們不是單純圖表樣式。完整分析功能需有可重現計算與測試，不能用一張曲線代替指標驗證。

滾動視窗、報酬口徑、年化因子、最低樣本與零分母處理尚未全部定義。未定的金融參數不得靜默套入預設值；可先處理規則已明確的資料剖析與基本圖型，待分析政策版本確定後再啟用相應計算。

### 3. 專業分析圖引擎

图型由 `VAP-CH-01` 至 `VAP-CH-28` 唯一識別，規範與圖庫從 SSOT 讀取，不將數值散寫於頁面。單張圖可有單軸或雙軸、多序列、事件、基準線、說明與互動。X 軸不一律是日期：分類圖需要 label、散點需 x/y、回測圖可能使用 lag、雷達需 metric、地圖需 geometry。

附件的 8 類共 28 型，圖码 24 在基本面群、25 在滾動績效群；分類順序不代表圖碼遺失。正式圖庫已驗證全數唯一，尚未驗證其對應計算與渲染。

- 單軸 5 型：折線、面積折線、直條、橫條、散點。
- 堆疊 3 型：堆疊面積、堆疊直條、百分比堆疊。
- 個別 2 型：個別小圖、並列直條。
- 雙軸 2 型：底色面積×對比折線、條＋線。
- 進階 4 型：事件矩陣、相關熱力圖、區間量測、地圖×數據。
- 滾動績效 8 型：滾動報酬、滾動相關、移動夏普、Sharpe×Sortino、風險雷達、Alpha、經濟日曆、回測驗證。
- 技術分析 3 型：當日走勢＋量、K線×SMA/EMA/BB×量、現貨×期貨。
- 基本面 1 型：共識總覽。

### 4. 分析堆圖引擎

**單張圖內的數值堆疊，與多張分析圖的垂直堆圖，是兩種不同能力。** 前者例如堆疊面積／百分比條；後者例如價格 → 成交量 → 動能 → 風險，多張圖沿同一時間位置垂直排列。Small Multiples 則是面板比較，可採 2×2；不能混為同一個堆疊開關。

分析堆圖需支援共用時間軸、縮放與游標同步、每圖獨立左右軸、穩定 plot_id / stack_id、上／下新增、拖曳排序及面板收合。交易日序列與跨頻資料對齊由資料層決定，再把同一時間座標交給每張圖，不能各圖自行裁切後看起來對齊。

資料歷史起点 1920、預設展示起点 2007 是範圍政策，不是資料保證；展示裁切不得先刪掉計算所需歷史。混頻資料必須保留發布／可用時間，避免將月度結果提前帶入回測。價格補值只在經確認的價格分類及交易日政策下啟用並标記來源；成交量不補值。

### 5. 分析模板引擎

模板不是固定截圖，而是可重用的「分析配方＋資料角色＋圖型參數＋堆图結構＋版面」。例如價格／成交量／基準是邏輯來源角色，不直接把本次選檔生成的隨機 Dataset ID 寫死。新資料載入後，先檢查角色與必要欄位，再自動重綁、重新計算、產圖與更新，綁定失敗要清楚顯示，不沿用舊圖冒充更新。

template_id、plot_id、stack_id、dashboard_id 分開；新增版本保留歷史，不因拖曳改 ID。配置來源優先序建議為：正式 Spec → 圖庫特定 override → 已核准分析政策／模板版本 → 驗證過的操作設定。這是待落地的配方契約，不宣稱附件已定義完整模板 Schema。

線粗固定 1 與可調範圍 0.5–6 的關係尚有歧義。本輪解析器預設固定 1，拒絕改成其他值並提示政策未決；不是永久取消滑鼠調整需求。bar.gapFactor 的 `tight` 是名稱選擇器，解析成 0.86，但保留原 preset 字典，不以字串覆蓋整個設定。

### 6. Dashboard 組裝與輸出

Dashboard 可組合分析圖、堆圖、KPI、表格、事件與資料觀察，跨卡共用日期／Ticker／來源篩選。畫面中心應是分析結果，左面板是資料、分析模組、圖型、雙軸規格、堆图、模板與匯出操作。SSOT／健康／Logs 是次級頁籤或抽屜，不能佔據主體。

附件要求互動 HTML、白底 4× PNG、print-based PDF 與可編輯 PPTX。前次輸出的静態 SVG HTML 不等於互動 HTML；前次 VIA 架構 PPTX 不等於 VAP 圖表匯出能力。正式支持各格式之前，需針對同一圖驗證軸、圖例、中文字、透明度、註記、metadata 與編輯性，不能以不相關簡報代替驗收。

輸出沿用專案契約：`plots / insights / data_profile / asset_registry`。每圖保留 asset_id、asset_type=plot、source_data_reference、generation_timestamp、visualization_type、parameters_used；洞察需使用實際數值，未知道幣別、頻率或價格調整基礎時不能補造金融結論。

## 前次工作台的可保留與必修項目

可保留：來源搜尋與篩選、CSV／JSON 基礎剖析、左面板、拖曳／按鈕排序、穩定圖號、模板版本、metadata 與空資料狀態。這些是元件基礎，不是 28 型完整支援。

必修：樣式直接寫死為線粗 1.8／opacity 0.95／area alpha 0.16，與新正式 Spec 的 1／0.9／0.75 不一致；SVG 採日曆時間線性距離，尚非交易日序列；散點目前仍以時間欄作 X，不能算一般 x/y 散點；缺少分析計算、圖庫唯一碼、真正區間量測與同步 zoom。模板目前保存 volatile sourceId，新來源重新選取需人工重綁，尚非可攜分析配方。以上本轮沒有修改舊 UI，避免把新契約草草插入並破壞既有使用資料。

## 核心落地與驗收順序

本輪完成的是 **M0 規範與契約基座**：兩份原樣 SSOT、28 型宣告檢查、參數解析、能力狀態區分及 23 項核心測試。所有圖型在本輪能力紀錄中仍為 `declared_only`，不冒稱計算或渲染完成。

下一階段 **M1 資料與分析**：恢復或重建真實 VDF Adapter、統一 Dataset／Indicator 契約與資料品質；以參考值測試已明確定義的計算，保留金融參數及時間可用性。**M2 專業圖與堆图**：先完成基本／分類／雙軸圖與交易日時間層，再加入複雜圖型，逐項提供渲染與互動證據。**M3 模板與 Dashboard**：邏輯來源重綁、分析配方、版本與更新流程。**M4 匯出與 UI**：格式驗收後再調整專業 Muji×Seaborn 外觀。

每阶段都按「分析準備 → 安全實作 → 驗證並安排下一輪」進行。不得先畫出 28 張示範圖就宣稱完成，不在無資料時造出行情，不把待定公式默認为可用，也不在未授權情況下改動 Windows 檔案。

## 單指令使用

在包內目錄執行 `python check_vap_core.py`，不需第三方套件；它只驗證規範與解析契約，寫入 `core_validation/`，不啟動服務、不連線、不改原始 SSOT 或前次 UI。

查詢單型：`python -m vap_core --chart VAP-CH-07`。回傳該圖定義、解析後規範、來源 hash、使用參數与 `declared_only`；這是下一階段圖表引擎可接入的設定，不是已產圖結果。
