# 標準 Prompt:語音會議紀錄 → Raw Data → 可用資訊 → 資料庫
版本 v1.0 · 可重複使用模板。用法:整段複製,只填兩個【】,貼給任何 AI。

---

```
【任務】語音轉文字會議紀錄的完整結構化處理(四階段,逐階段輸出)

■ 待處理逐字稿:
【貼上語音轉文字原稿】

■ 階段 1|修復(Raw Data → Clean Data)
1. 校正語音辨識錯字:同音字、人名、專有名詞(不確定者標 ※待確認,禁止默默猜測)
2. 還原口語為書面:刪贅字(呃、就是、然後),保留原意,禁止增添原文沒有的資訊
3. 回報修復統計:總字數 / 修正處數 / ※待確認數(覆蓋率證明,少於原文 80% 須說明)

■ 階段 2|結構化(Clean Data → Structured Data)
輸出「會議事件表」,每列一個事件,欄位固定:
| 序 | 時間點 | 發言人 | 類型 | 內容摘要 | 負責人 | 期限 | 案件編號 |
- 類型限四值:決議 / 行動項 / 資訊 / 爭議
- 行動項必須有負責人與期限;缺者填 [未指派]/[無期限] 並列入階段 4 警示
- 案件編號從內文比對(格式:【填入你的案件關鍵字對照,例:案01=料號X】),比對不到填 待歸類

■ 階段 3|資料庫化(Structured Data → Database)
1. 輸出 UTF-8 CSV(欄位同上表,可直接匯入)
2. 輸出對應 SQLite INSERT 語句,目標表:
   MEETING_EVENT(seq, ts, speaker, etype, summary, owner, due_date, case_code)
   (與 email_super_engine 的 E07_ACTION 欄位對齊:行動項可直接轉入)

■ 階段 4|挖掘鉤子(Database → Mining)
1. 行動項統計:總數 / 有主有期限數 / 缺主缺期限數(缺=風險)
2. 每位負責人承接數(超載預警:單人 >40% 標紅)
3. 決議 vs 行動比(只有決議沒有行動=空轉會議訊號)
4. 與上次會議未結行動的比對欄位建議(供 process mining 串接)

■ 自檢閘門(輸出前必過):
□ 原稿每段皆對應至少一列事件或明確標記「寒暄/無資訊」
□ 所有 ※待確認 與 [未指派] 已彙總列出
□ CSV 列數 = 事件表列數

■ 額外指示(選填):【例:輸出繁體中文 / 只要行動項 / 對齊 WorkMatrix 欄位】
```

---

**與工具鏈的接點**:階段 3 的 CSV 餵給 `email_super_engine.py --input`(.csv loader 直接吃);行動項欄位對齊 WorkMatrix,可直接貼矩陣。三道防遺漏關卡(覆蓋率回報 → 逐段對應 → 自檢閘門)與 FlowChain gate 同構。
