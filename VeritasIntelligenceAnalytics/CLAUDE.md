## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Rules:
- When graphify-out/graph.json exists, run `graphify query "<question>"` before your first grep, search or source-file read for a codebase question, and put this rule in every subagent prompt that explores code. Read raw files only for lines the graph or an earlier read already located. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
- A committed graphify-out/graph.json is rewritten whole on every build, so a large diff to it in a pull request is expected. Do not flag it as churn or suggest skipping the graph rebuild or its hooks.

## L121 OUTPUT SHAPE
- Never output a whole file. A change = thin-tail new-version file written to disk + unified diff (+/-) of only the changed hunk in the reply, max 40 lines.
- Reply = [FILES] [RUN] [DELTA] [NEXT]. No restating the request, no summaries of what was just done.
- Ponytail mode = lite. YAGNI never deletes existing VIA code (append-only law).

## L120 CONTEXT BUDGET
- Session-start injection ≤ 1500 tokens total: claude-mem ≤ 800 · skills Tier1 index ≤ 400 · everything else 0.
- This file is an index. Subsystem detail lives in `.claude/ctx/vcgc.md`, `vdf.md`, `vrn2.md`, `vap.md` and is read ONLY when a task names that subsystem.
- Never read `.venv`, `_superseded`, `__pycache__`, `*.parquet`, `*.duckdb`, `graphify-out/graph.json`, `RUN_*/` directories (see .claudeignore).

## L122 NAVIGATION
- Before reading any source file: `graphify query "<question>"` or `graphify explain "<symbol>"`. Read raw source only if the graph has no node, and then only the AST slice (accelerator 01), never the file.
- Before grepping: `graphify path A B`.
- Shell/test output never enters the reply raw. Lanes log to `RUN_<ts>/lane_N.log`; only the paste pack (≤300 lines, yellow/red, ends `NEXT:`) is read.

## L123 MEMORY RESET
- After every CLOSEOUT whose [DELTA] was written to `VIA_WorkflowLedger.jsonl`, the next session starts clean. Carry-over comes from claude-mem (validated observations only) and `VIA_AgentMemory.json`, not from scrollback.
- claude-mem stores only: confirmed decisions, approved architecture, verified gates. Wrap drafts and speculation in <private> tags.
- `VIA_AgentMemory.json` is the cross-AI handoff (Claude / Manus / ChatGPT / Gemini all read it first). It is generated by the VCGC `memory` verb from the ledger; never hand-edited.

## L124 EXTERNAL SURFACES (L0, outside context)
- Playwright, ChartDB, WordPress, GitHub MCP, Filesystem MCP produce files on disk. The reply gets ≤ 5 summary lines, never page bodies, never JSON dumps.
- Filesystem MCP scope = VIA roots only. GitHub MCP = read + draft PR text; push/merge stays manual (protected by Policy gate).
