## 三、這不是「有人竄改了 96 個檔」

一次壞 96 份,這種形狀通常不是九十六次竄改,是**一個動作一次打到全部**。
第一個嫌犯是批102 的全樹加速器橋注入 —— 驗了:**剝掉橋之後只救回 1 份**。
所以橋只是其中一段,另外還有一連串沒有重新封章的修改。

真正的根因是更簡單的一句話:

> **樹上沒有任何一支程式去比對那個 sha256。**

`CGC_MDL059_MasterHub` 把「凍結件零觸碰(freeze.lock)」寫成一條**政策字串**,
但沒有人去算。**一份沒有人驗的封章,守的東西早就不是它記的那一份。**
它是裝飾品,不是閘。

而這件事是怎麼被發現的?**是因為有人去替一支「沒人看的家族」寫檢。**
這正是任務 #72 的價值:不是為了讓覆蓋率的數字變好看,
是**每揭開一支沒人看的檔,底下就可能有一整類沒人看的東西**。

## 四、本批做的兩件

### ① `CGC_MDL180_FreezeSealAudit_v0100` —— 七檢,每檢帶控

只做一件事:**把那個 sha256 真的算一次,照實報**。
不重新封章(那是操作員的裁定)、不改被封的檔一個位元組、只讀。

五態誠實:`OK` / `STALE_BRIDGE` / `BROKEN` / `TARGET_MISSING` / `LOCK_UNREADABLE`。

**棘輪**(批708 LL387 同一式):現況 102 條入基線,照實報不算紅;
**基線外再冒出一支 BROKEN,或同一條的態變了,就是 RED。**
一道一上線就 96 盞紅燈的閘,跑三次就沒有人看它了;
但新的一支必須當場叫,不然這一欄只會越長越長。

七檢與它們的控:

| 檢 | 控 |
|---|---|
| ① 掃描面=全樹 − 具名排除,逐條印出吃掉幾份 | **負控**:注入一條吃掉整個 `70_VRN_Rules`,份數必須當場掉(102 → 82) |
| ② sha256 判準 | **正控**:乾淨的必須判 OK(永遠紅跟永遠綠一樣沒有判斷力) |
| ③ `STALE_BRIDGE` 判準**窄** | **負控**:內容不符又沒有橋標記的,必須照樣 BROKEN(不准「剝到相符為止」) |
| ④ 誠實態 | 封章指向不存在的檔=`TARGET_MISSING`,不當 OK 也不當 BROKEN |
| ⑤ 棘輪 | **負控**:`OK` 不受棘輪管轄,一個字都不准被改 |
| ⑥ 基線實跑量出來 | 列一條樹上沒有的,等於發一張永遠用不到的免死金牌 |
| ⑦ 零寫入 | 逐行掃**會執行的碼**(剝掉註解;自測造沙盒檔是許的) |

## 五、我**沒有**做的一件,和為什麼

封章的**純資料模組**(`VIS_VRN_*` 規則表)不可能靠「掛一站跑它」來覆蓋
—— 跑起來什麼都不做、rc0,**那是假綠**。它們該走 `EXEMPT` + 具名因由,
而那個因由只有在「**真的有人在稽核它**」時才成立(MDL180 就是那個人)。

但把 10 支改成 EXEMPT,會直接讓「還沒人看」從 85 掉到 75。
**那是用重新分類換數字,不是用覆蓋換數字。**
所以本批**不動 EXEMPT**:先把稽核做出來,分類**請操作員裁**。
