# VRN 按品質逐級擷取：速度、完整性與還原

狀態：依 2026-09-29 操作員補充需求整理的下一版路由規格；尚未啟用新的自動升級控制器，未宣稱重型 OCR 或吞吐量已實測。
本輪 VCGC／VDF Manager 修復另有實測收尾報告。已鎖定、成功的擷取核心與 Layout 工具版本保持原樣。

## 已核對的現況

- `SUP_MDL743_GenericLayoutHub_v0109` 沿既有鏈重用 v0104 的來源鎖、輸入證據核對、修復快取與功能目錄。
- `layout_repair_v0100/SUP_MDL743_LayoutFigures_v0100` 已按圖區的原生 token 判定是否需要 Tesseract，並快取 OCR 結果。不是每一頁全跑重型 OCR。
- `VRN_ENG072_FirstPageText_v0139` 已有非 OCR 失敗判準、第一頁裁切、直接 Tesseract、OCR 總預算、隔離環境／壞後端檢查及 300～350 DPI 升級。下一版必須重用這些能力，主要補齊年度財表的區域品質閘與共用路由，不重建另一套第一頁階梯。
- 舊 `SUP_MDL146_OcrRouter.py` 的 `route()` 按可用套件選擇工具，並未充分判定頁型；`extract()` 可將零字數或檔名錨點回為 `ok=True`。這是擷取完整性風險，不能把該欄位接成綠燈。舊檔本輪未修改。
- pdfplumber 是原生 PDF 文字與幾何／表格解析器，本身不提供 OCR；PyMuPDF 與 pdfplumber 也不能算兩個獨立掃描辨識器。

## 一個入口、四個可插拔職責

仍由 VCGC → VRN Manager → 既有擷取鏈啟動。新增路由應只負責「判頁／區域 → 排程既有 adapter → 驗證 → 升級或停止」，不複製擷取器。

| 職責 | 行為 | 可追溯資料 |
|---|---|---|
| 低成本判頁與分區 | 每頁讀原生文字、座標、影像覆蓋、旋轉、線段與欄間距；粗分文字、表格、圖、掃描或混合區 | 頁碼、bbox、頁型、分類理由與不確定性 |
| 路由與預算 | 依區域類型、失敗原因、已裝工具、資源上限選下一個引擎；通過即停止 | 階段、引擎版本、參數、耗時、升級原因 |
| 擷取後修復 | 沿用已鎖定修復核心；重建列欄、單位、跨頁表頭、閱讀順序 | 原文、原值、修復值、來源座標與轉換紀錄 |
| 品質閘 | 逐區檢查，再聚合成文件狀態；未處理／未知區域不得被平均分數掩蓋 | 缺漏、衝突、證據、燈號與下一步 |

## 初階到重型的路由

以下 DPI 與預算屬待實測起始設定，必須放進中央參數 SSOT；不是保證最佳值。

| 階段 | 適用情況 | 工具及範圍 | 升級條件 |
|---|---|---|---|
| 0：預檢 | 所有頁，混合頁按區域再分 | PyMuPDF 原生物件與低成本幾何；已有有效快取直接重用 | 文字層缺失、亂碼、圖區承載未讀資訊、表格錯位或不確定 |
| 1：原生單工具 | 原生文字／簡單表格 | PyMuPDF；表格可直接選既有 pdfplumber adapter。原生字形不必轉圖 OCR | 字／區域缺漏、閱讀順序錯、列欄不一致、必要欄位缺失 |
| 2：原生補強 | 複雜表格、左右或上下黏表 | 只對失敗 bbox 加 pdfplumber 與輕量幾何 Layout，先分左右，再辨各欄上下獨立表格 | 原生來源仍無法完整還原，或關鍵數字出現衝突 |
| 3：基本 OCR | 掃描或無可靠文字層的區域 | 選一個已註冊、可用 OCR；清楚大字可試 200 DPI，小字／密集財表可直接 300 DPI。裁切、旋轉校正按需啟用 | 品質不過且失敗原因適合增加解析度，才對該 bbox 升至 300／350 DPI |
| 4：重型補強 | 掃描表格結構、嚴重錯位、基本 OCR 持續缺漏 | PaddleOCR／PP-Structure 等隔離環境工具；按需開 Layout／表格子模組 | 仍有關鍵衝突才加入具不同失敗特性的第二或第三方法 |
| 5：保留疑點 | 到達預算、無工具、無改善或仍矛盾 | 保留原圖、原文、各候選值與缺失區域，交覆核 | 不編造值、不以多數決覆蓋原始證據、不標成完整成功 |

不強制每頁依序失敗五次。確定是掃描小字財表可以直接走適合的 300 DPI 路徑；確定是原生文字則保持原生。
提高 DPI 僅增加渲染取樣，不能恢復來源影像中已經不存在的細節。300 → 350 DPI 的像素量約增加 36%，實際耗時／辨識收益需量測。

## 單、雙、三工具例子

1. 清楚原生報告：PyMuPDF + 輕量品質閘即可；不必 OCR。
2. 原生年度財表：PyMuPDF 定位 + pdfplumber 區域表格；Layout 只分出必要的左右欄與上下表塊。
3. 掃描且表格複雜：基本 OCR 先讀字，失敗區交 Paddle 表格結構；第三方法只覆核仍衝突的關鍵數字，不重跑整份報告。

模型 Layout 與低成本幾何 Layout 分開計費、記時。頁內分區每頁要做便宜檢查，重型模型只處理不確定区域，避免抽樣漏掉少數異常頁。

## 完整性驗證與停止条件

- TEXT：每頁／每區有處理狀態；標題、內文、註解與金融資料區保留來源座標；查重、亂碼、閱讀順序和疑似未覆蓋區域。
- TABLE：左右、上下不同表各有獨立 ID；核對表頭年份、期間、幣別、單位、列標籤、列欄數和候選數字。缺值、零、破折號不互換。
- 財務關係：在會計範圍、幣別、單位、期間一致且適用時做資產＝負債＋權益等檢查；容許四捨五入。關係不符只回報，不自動改原值。
- 交叉比對：原始 PDF 字形／座標、第二解析器或 OCR 證據、跨頁或同文件另一張表。檔名只是旁證，不能取代頁內資料。
- 關鍵金額、期間與單位不能靠平均信心分數或三引擎多數決放行。獨立錯誤也可能一致；無足夠來源證據就留黃燈。
- 綠：必要區域和欄位均有可追溯證據且品質閘通過；黃：待補強、工具缺席、預算耗盡或有未解衝突；紅：檔損、執行異常、證據不匹配。
- 兩次升級沒有新增可信資訊就停止自動重試。各次輸出保留，不以較新但較差的結果覆蓋已通過區域。

## 資源與驗收

- 每文件只開啟一次，文字、幾何、render 與 OCR 結果分層快取；快取鍵包含輸入 hash、頁、bbox、引擎／模型版本、DPI、語言、前處理及品質規則版本。
- 同頁 render 共享；只裁切失敗區域。重型模型惰性載入、常駐工作者重用；CPU／GPU 各設併發和記憶體上限，經現有加速器與環境管理器控制。
- 測試樣本分原生／掃描／混合，以及單欄、多欄、上下疊表、小字、旋轉與品質差等組。抽樣可校準策略，不能代替每頁的低成本完整性檢查。
- 先用已成功鎖定的 PDF 與財報標準答案作回歸；再加少量有人工標註的困難掃描樣本。記錄關鍵儲存格完全正確率、漏區率、表格結構、衝突率、人工覆核率。
- 速度記冷／暖啟動、P50／P95 每頁秒數、整份耗時、峰值 RAM／VRAM、OCR／重型升級比例、快取命中率。沒有這組測量，不聲稱加速倍數。
- 接線驗收必含：乾淨原生文件重型調用＝0；一個壞區域只升級該區；零字數與檔名錨點不假綠；預算終止；失敗引擎不阻塞其他獨立文件；快取失效與來源／參數變更可追溯。
- 新控制器、adapter 契約、參數、regex／同義字映射與測試清單經 VCGC 中央註冊、編號；規則只增不減，有衝突才交原治理流程處理。

## 原廠依據

- pdfplumber：原生 PDF 字元、線段、表格及視覺除錯能力；本身不提供 OCR。https://github.com/jsvine/pdfplumber
- PyMuPDF：先判是否需要 OCR，按頁／影像區域處理並重用 TextPage。https://pymupdf.readthedocs.io/en/latest/recipes-ocr.html
- PaddleOCR：PP-StructureV3 可控制表格、版面相關與文件前處理子管線；應依任務選配。https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-StructureV3.en.md
