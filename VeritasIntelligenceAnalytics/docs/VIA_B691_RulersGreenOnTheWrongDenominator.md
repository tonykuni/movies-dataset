### ③ 梭 vs 獨立實作沒有分開 → ⑨

批340 的梭律:**梭 = 點源 Register 尾版 + 叫 `%~n0` 同名函式**。
自己去跑引擎的 `.cmd` 不是梭,是**第二個實作**。
量出來的分割是乾淨的:

```
bin/*.cmd  141  =  真梭 12  +  獨立實作 129
獨立實作   129  =  撞名 13(Register 也有同名函式 → L101 兩扇門)
                 + 116(只有 .cmd、Register 沒有同名函式 → 完全繞過短令這一層)
Register 函式 166 =  有真梭 12  +  有撞名的 .cmd 13  +  完全沒有 .cmd 141
死梭 0     ← 沒有任何一支梭指向不存在的函式
```

### ④ 撞號:**同名不等於同一份** → ⑫⑬

第一版問的是「這個 `家族_vNNNN` 有沒有同時長在兩條活線上」。答案是 **298 筆**,

前者不是撞號,是**一份檔長在很多條線上**(多半是 main 刪掉的舊檔還留在老分支)。

### ⑤ 同一份報告裡,兩個「缺梭」寫著不同的數字 → ⑮

```
短令·梭    齊 25 / 166 · 缺 141
[梭配對]   {'缺梭': 154, ...}
```

**141 和 154 同時印在同一頁上。** 兩欄都叫「缺梭」,但問的不是同一件事:

| 欄 | 問法 | 數 |
|---|---|---|
| 盤點 | 有沒有**同名 .cmd**(寬) | 25 有 / 141 無 |
| 梭配對 | 是不是**真梭**(嚴) | 12 有 / 154 無 |

兩個都對,可是**共用了一個詞**。改名之後再釘死恆等式:

```
有同名 .cmd  25  ==  真梭 12 + 撞名 13                      ← ⑮ 第一條
bin 全部 .cmd 141 ==  真梭 12 + 撞名 13 + 獨立無函式 116    ← ⑮ 第二條:**分割要蓋滿**
```

第二條是第一條逼出來的:只釘第一條,中間那 116 支會從兩欄的縫裡整個掉出去 ——
它們不是死梭(它們不是梭),是**繞過短令那一層的獨立入口**。
是不是缺陷要操作員裁(LL90),尺只負責讓它們不再隱形。

> 這就是 LL341 的小一號版本:不是同一個判準被抄成兩份檔,
> 是同一個名字被兩把尺共用。照樣會讓看報告的人讀到互相矛盾的數字。

### ⑥ 一句**假的修法**:「跑 registry-sync 就好」 → ⑯

第一版的「可代跑」寫著:

```
[可代跑] via-vcgc registry-sync --apply  (冊上未登 · 93 支)
```

跑完 `--apply`,再跑一次 plan:

```
[VCGC 元件自動編號冊] PLAN · 活元件 6090 · **新 0** · AST錯 0
盤點                冊 缺 **92**
```

**它說沒有新的,而冊外還有 92 支。** 那 92 支不是「還沒跑」,
是 VCGC `live_components()` 的掃描規則**根本沒走到**(逐支查過:任何 category 都不在冊上)。
所以原本那句話等於指一條死路 —— 跟 `via-tools` 那個幽靈令一樣的病(L89)。

→ 冊那一步**必須帶 caveat**,而且「冊外」那一群要**另列一條**,不准併進可代跑裡充數。
→ ⑯ 用結構不變量釘死這件事(不是釘今天的數字,LL332)。

### ⑦ 而第七個尺病不在我這裡 —— 是我的新引擎把它照出來的

新引擎一上樹,全格子多紅一盞:`CGC_MDL164 制度健全度稽核`,
⑰「自我指涉閘(LL133 棘輪)」報**基線外 +1**,而那一支就是 `CGC_MDL178`。

逐字查命中處:

```

_SR_ANSWER 命中 referenc                                          ← 出現在哪裡?
   EXCLUDE = ("__pycache__", "_superseded", "RetiredEngines", "references/intake", …)
```

那是 **L77 要求每一支掃描器都要帶的排除清單**裡的一個**路徑字串** ——
不是「這支在回答誰引用 X」。樹上 **302 支**檔帶著同一個字串。

> **L77 的合規,本身踩中了 LL133 的偵測式。** 兩條律經由一個 regex 對撞。

處理方式有三條路,只有一條是誠實的:

| 做法 | 為什麼不行 / 行 |

| 把 `CGC_MDL178` 加進 `SELFREF_BASELINE` | ✗ 那份名單寫的是「**既有債**」。把一個**誤判**塞進債務名單,是拿基線當掩埋場 |

`CGC_MDL164 v0109`:`referenc(?!e?s?[/\])`,並 +⑰之二 正負控一條
(負控 = 排除清單 + rglob 的合成文字,**必須不命中**;正控 = `readers` / `referenced`,**必須命中**)。
