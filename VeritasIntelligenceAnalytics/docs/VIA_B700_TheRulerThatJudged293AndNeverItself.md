# 批700 — 它判了 293 站的生死,自己從來沒有一條檢

> 引擎:`CGC_MDL064_SelftestGrid` v0452 → **v0453**
> 任務 #62(格子平行工搶 DuckDB 寫鎖)。零網路 · 零寫庫 · 沒碰任何 `.ps1`。

## 題目本來是撞鎖

v0452 那一跑,6 站在平行段紅:

```
_duckdb.IOException: IO Error: Could not set lock on file
  ".../functional modules/VDF/output_hub/mega/vdf_tw_market.duckdb":
  Conflicting lock is held in /usr/bin/python3.11 (PID 19568).
```

六站全在同一個庫上撞,全部靠第二段序跑複判才轉綠。

## 照著查下去,撞出一件更重的

態→記號那張表是**三處字面 dict**,只寫了 `OK` / `FAIL` / `SKIP`:

```python
mark = {"OK": "OK  ", "FAIL": "FAIL", "SKIP": "SKIP"}[r["state"]]
```

而 `run_one` 明明生得出 `TIMEOUT`(2921 行),`main` 生得出 `NOT_RUN`(中斷)。
而且整支檔裡有一整段 批616 的程式碼,專門在總結裡**逐站點名逾時的站** ——
作者顯然預期得到 TIMEOUT 會發生。

**實跑逼它逾時一次**(合成一站 `sleep(20)`、逾時設 1s),量到兩面:

| 路徑 | 一站逾時的後果 |
|---|---|
| 加速器在位(`accel_map`) | `KeyError` 被工人吞掉 —— **那一站的行從頭到尾不印**,進度條與心跳跳過它。總結還是對的,可是跑的當下你看不到那一站 —— 而逾時的那一站,正是你最需要看到的一站(批423 立心跳就是為了這個場景) |
| 加速器缺席(`ThreadPoolExecutor` 退路) | **整跑當場炸 `KeyError: 'TIMEOUT'`** —— 294 站全丟 |

同一個缺陷,一條路上是沉默,另一條路上是致命。

## 三件一起修

### ① 一張表,永不丟例外

`MARKS` / `_mark()`:一份、蓋住引擎生得出的每一態、沒見過的態回 `?態` **大聲現形**。
不可以讓它安安靜靜消失,也不可以讓它殺掉整跑。

### ② `LOCKED` —— 庫被佔著不是引擎壞了

DuckDB 是單寫者。撞鎖時這一跑**量不到**,那不是紅燈。判成 `FAIL` 就是一盞判錯的紅燈,
而**判錯的紅燈會讓人去修一支沒壞的引擎**。

判準刻意寫**窄**:要同時有 DuckDB 那句鎖訊息**和**一個 `.duckdb` 檔名。
寬一點就變成一道把紅洗成非紅的後門 —— 那比假紅更糟,**假紅有人去查,假綠沒有**。

第二段序跑複判照舊,但**仍被佔就維持 `LOCKED`,絕不改判紅**,並逐站點名。
工作站上 VDF 管線在跑的時候,庫本來就會被機外行程佔著。

### ③ 撞過才建鎖 —— 不列手寫清單

同庫的站自此互相讓(照字母序取鎖,一致的次序不會成環,所以不會死結)。

**刻意不列手寫清單**:批699 才立的 LL363 說手寫清單會隨樹長大變假,而且變假不會紅。
量過:全樹 293 站裡**字面提到 `vdf_tw_market.duckdb` 的有 70 站**,而真正撞鎖的只有 6 站
—— 照「提到就排隊」列清單,等於用 70 站的序列化去換 6 站的重跑,那是壞交易。
撞過才建鎖:沒撞過零成本,撞過一次之後同庫互相讓。

誠實界線寫在臉上:只看得到引擎原始碼**字面寫出**的庫名,經模組鏈間接開的看不到。
所以這條路只**減少**撞鎖,不宣稱消滅它 —— 第二段序跑那張網子留著。

## LL362 的第一個樣本就是格子自己

批699 剛立 LL362:**一把尺自己要在它量的範圍裡**。

這支檔判了 293 站的生死,自己卻從來沒有一條檢。尺量不到自己的那個洞,
不會有任何一盞燈照出來 —— 因為照燈的那支也在洞外面。

所以本批 `+--selftest` 五檢,而且**格子自己開一站**:

| 檢 | 釘什麼 | 反面控制 |
|---|---|---|
| ① | 態→記號一張表,蓋住每一態,永不丟例外 | 餵一個沒見過的態,舊寫法當場 KeyError,新寫法要回得出看得見的記號 |
| ② | **實跑**逼一站真的逾時 | **兩條平行路都走**(加速器在位 / 缺席),都要印得出那一站、rc 都要是 2、都不准炸 |
| ③ | 鎖撞判準窄 | 真壞掉但提到 duckdb 的、鎖的是別種檔的,一律不得被當成鎖撞 |
| ④ | **實跑**分得出鎖撞與真壞 | 兩站**同樣 rc=1**,判定必須不同 |
| ⑤ | **量時鐘**證明排隊真的排到 | 同庫不重疊 **且** 異庫要重疊 —— 只證前者的話 `workers=1` 也會過 |

五檢一律實跑,不讀原始碼複述宣告(LL354/LL358)。

### 自審實錄:我的尺在量自己的時候,改變了被量的東西

② 第一版直接呼叫 `main()`。它跑得很好 —— 也**各寫了一份真的 `GRID_<ts>.json`
進 `VIA_Reports/selftest_runs/`**。

而下游(`VRN_ENG068` / `CGC_MDL131` / `CGC_MDL095` / `Invoke-VIA-FinishLine`)
一律取**最新的** `GRID_*.json` 當證據。等於我的自測**偽造了一份「全樹只有 1 站」的證據
給全系統讀**。

不是推論,是同一跑當場照出來的:

```
[FAIL] 測試結果總表六檢(批257)   ② grid 尾版存證真讀(站數>0)
[FAIL] 三軌測試矩陣自測(批267)   ② A軌=grid 尾版真值(站數>100 FAIL 數字在)
```

四次自測共寫了 **8 份**假證據進真夾。全部刪掉,並把「零足跡」變成 ② 的一條斷言:
合成跑的產出一律落在拋棄式暫存夾,跑完**驗真夾裡一份都沒多**(實測 210 → 210)。

**一把尺放進自己的範圍量自己,不可以在量的過程中改變被量的東西。**

## 新律

- **LL365** 一個態生得出來,就要有一張表接得住它。接不住的後果不是「少印一行」:
  在吞例外的工人裡是**那一站整個消失**,在不吞的路上是**整跑炸掉**。
  同一個缺陷在兩條路上一個沉默一個致命,而沉默那條更難發現。
- **LL366** 判錯的紅燈跟假綠一樣傷 —— 它會讓人去修一支沒壞的引擎。
  外部資源被佔住要有自己的態,不可以混進紅裡;而那個態的判準要寫得**窄**,
  寬的判準會從「別誤判紅」變成「把紅洗掉」。
- **LL368** 一把尺放進自己的範圍量自己(LL362),就要零足跡:量的過程不可以改變被量的東西。
  自測跑出來的產物與正跑長得一模一樣時,它會被下游當成真證據讀 ——
  那不是「多了一個檔」,是**偽造證據**。合成跑的產出一律改道,並用一條斷言驗「真夾一份都沒多」。
- **LL367** 要序列化就序列化**量到會撞的**,不是序列化**看起來會撞的**。
  70 站提到那個庫,6 站真的撞;照前者排隊是拿整個平行度換 6 站的重跑。
  撞過才建鎖:沒撞過零成本,而且不必維護一張會過期的清單。
