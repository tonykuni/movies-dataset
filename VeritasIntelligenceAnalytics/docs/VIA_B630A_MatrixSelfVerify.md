## 二 · 頁上的自我驗證

> 「實際產出看結果是否符合自我驗證」

`self_verify()` 從**同一份 rows 現場重數**,不是把 tally 再印一遍——
抄一遍只能證明「我抄對了」,證明不了那份 tally 本身是對的(LL112)。三條都要成立:

```
形狀  格子 567 = 81 份 × 7 欄
四態  逐格重數 vs 抬頭 tally
加總  四態相加 = 總格
```

負控 ㉚:把 tally 動手腳(GREEN 1→9),自我驗證**必須當場說「對不起來」**。
驗證器抓不到被動過手腳的數字,那它只是裝飾。

## 三 · 「準確率 100%」要拆成兩個數字

現況 GREEN 298 · YELLOW 8 · NODATA 180 · ABSENT 81。
若把準確率定義成 `GREEN ÷ 總格` = 52.6%,那**只要把缺料補上,這個數字就會自己上升**
—— 補料被偽裝成變準。所以拆開:

```
判對率 = GREEN ÷ (GREEN + YELLOW) = 298/306 = 97.4%    ← 只算判得動的格
可判率 = (GREEN + YELLOW) ÷ 總格  = 306/567 = 54.0%
```

**要 100% 準確,兩個數字都得是 100%。**
判對率講的是「量錯沒有」(邏輯的帳),可判率講的是「量得到沒有」(料的帳)。
兩者負責人不同,混成一個數字就誰也不負責(LL225)。

目前那 8 格 YELLOW 是判對率的全部缺口:評等 4 · 目標價 4。
那 261 格 NODATA/ABSENT 是可判率的缺口,其中 **上漲空間 81 格**全部卡在 VDF 價格覆蓋
(上市股一支都不在庫裡,見批630 量測)。
