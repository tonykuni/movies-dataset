## 做了什麼

`CGC_MDL160` v0106 `surface` 車道(29 檢):

### ① L100 邊界檢 —— 宣告面不得打 hub

```
[L100 邊界] 宣告面(VIA_HTML_UI/ui + VIA_Reports latest)驗 57 張 · 越界 0
```

### ② 退路項 —— **降為 ADVISORY,不判燈**

靜態掃描**證不出**「每個 fetch 都有退路」:

```js
VIA_b64(f).then(b64 => fetch('/intake', …)).then(…)   // fetch 在回呼裡,守衛在外層鏈
function postJson(p,b){ return fetch(B+p, …).then(…) } // promise 被 return 出去,守衛在呼叫端
```

兩種都不在任何一個以 fetch 為起點的掃描窗裡。硬判就是一面假紅牆(LL272)。

本閘 v0104 的紀律寫得很清楚:**不承諾自己不能證明的結果 —— 那跟假綠是同一件事。**
所以只**攤開** 5 張供人看,不判燈。

## 這把尺我改了三次

| 版 | 錯在哪 | 命中 |
|--:|---|--:|
| 1 | 對**整頁**比對 | `<code>fetch()</code>` 說明文字被算成 fetch(TreeAtlas 6 個) |
| 2 | `try {` **帶空格** | 壓縮碼 `try{` → MasterControl / VRNControlTower 三件誤判 |
| 3 | 越界條件由分類自己推導 | **一盞永遠不會亮的燈** |
| 4 | 收乾淨 | 5 張 ADVISORY · 越界 0 |

第 ③ 個值得單獨講:我寫的條件是「分類成 VIEW **而且**打了 hub 端點」——
而分類函式本身就是看端點決定的,**只要打了 hub 端點它就不會回 VIEW**。

> 那個條件邏輯上永遠不成立。
> **它會一直印「越界 0」,讓人以為邊界有人守。**

修法:**宣告與實測要來自兩個獨立的來源** —— 宣告看「它住在哪」,實測看「它打什麼端點」。→ **LL282**

> 律:寫完一個檢,先問它**有沒有可能為假**;
> 答不出「什麼情況下它會紅」,就是還沒寫完。
