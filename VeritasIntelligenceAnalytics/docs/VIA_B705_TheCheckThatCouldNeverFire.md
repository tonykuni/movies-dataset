對批701–704(我自己這四批)做對抗式自審。**七條,每一條都先用實測驗證過才算數。**

## 一、最重的一條:我自己寫的假綠

批703 的檢 ㉗d 寫著「不准吃到已經過閘的檔」:

```python
_overwide = [f for f, _w in GATE_SCAN_EXCLUDE
             if any(f in str(VIA / r["path"]) for r in gb if r["state"] == "GATED")]
```

`gb` 是**套用排除之後**的結果。被排除吃掉的檔,根本不會出現在 `gb` 裡 ——
所以沒有任何一條子字串比對得中。**它永遠回空,一次都不會叫。**

實測(不是推論):

| | |
|---|---|
| 現況 GATED | `ENG086` · `vrn_finlex` · `vrn_report_digest` · **`SUP_MDL015`** · `SUP_MDL749` |
| 塞一條吃掉 `SUP_MDL015` 的排除後 | `ENG086` · `vrn_finlex` · `vrn_report_digest` · `SUP_MDL749` — **少了一支** |
| 該檢的回報 | **「過寬 無」** |

一條會過的檢等於沒有檢(LL89)。這是**我自己在批703 種下的假綠**,
而且它就種在一批「專門在修別人假綠」的工作裡。

修:拿**沒套治理排除**的候選集來比。一條排除吃掉的檔裡只要有一支「讀券商冊而且過了閘」,
那條排除就是過寬。負控:塞一條吃掉已過閘檔的排除,必須當場叫並點名。

## 二、修好之後,它立刻照出第二件事

新尺一裝上就報紅,而且報得對 —— 它點名了 `CGC_MDL177_ChinaBrokerPurge` 與
`VIA_FinancialInstitution_Overlay`。但那兩條排除**是我故意寫的**:清除器讀名單是為了刪,
疊加層本身就是那扇門。它們當然帶著閘的字樣,排掉它們正是目的。

所以**尺沒錯,是表的結構錯了**:一張表裡混著兩種性質完全不同的排除。

| 表 | 性質 | 過寬檢管不管 |
|---|---|---|
| `GATE_HARD_FLOOR`(5) | 「它根本不是本倉原始碼」(`__pycache__` / `.venv` / `site-packages` …) | 不管 |
| `GATE_ROLE_EXCLUDE`(3) | **角色**排除:它是尺、是門、是正本 | **不管**(排掉帶閘字樣的東西正是目的) |
| `GATE_SCAN_EXCLUDE`(12) | **範圍**排除:它不是活樹上的解析面 | **管**(吃到解析面就是判寬) |

拆完:過寬 **無** · 死條文 **無** · 負控咬住 · **35 檢 OK 35**。

## 三、`_gate_candidates([])` 會把 `.venv` 整包吸進來

過寬檢的比較基準是「沒套治理排除的候選集」。批703 的寫法 `_gate_candidates([])`
是**零排除全樹走** —— 容器裡只是慢,工作站上會把 `.venv` / `site-packages` 一起數進去。
硬底線分出來之後,比較基準才是安全的(實測:2,337 支 · 0.2s)。

**這一條我第一次還修錯了**:`out.replace(frag, '', 1)` 砍到的是剛插進去的
`GATE_HARD_FLOOR` 那份,不是 `GATE_SCAN_EXCLUDE` 那份,於是三條硬底線從 FLOOR 消失、
留在 SCOPE 裡 —— **finding ③ 其實沒修到**。自審自己又抓一次,才改對。

## 四、`dangling()` 只掃了十八分之十

批702 的 `dangling()` 只跑 `PY_TARGETS`。**引擎升版件(3)與五本 JSON 一支都沒掃過。**
檢 ㊳ 於是只看得見十支就地改的 .py,其餘 8 個落點的懸空指標它一律看不見 ——
而看不見的東西當然「沒有未點名的」。

補齊三條路之後,活樹上引擎與 JSON 各 **0** 個懸空。
但 **「0」有兩種:真的沒有,和根本沒掃**,而 v0101 是後者,報得一樣乾淨。
所以三條路各配一個**合成負控**(`{"ZZHK": "GF"}` 必須被抓、`{"YT": "YUANTA"}` 不准被誤抓),
寫進自測,不留在臨時探針裡。

## 九、新律

**LL380 檢要拿「沒套這條規則」的結果來比,不能拿套完的結果比自己。**
一條「排除不准吃到 X」的檢,如果拿**套用排除之後**的集合去找 X,永遠找不到 ——
被吃掉的東西根本不在那個集合裡。判準的比較基準錯了,檢就不是寬鬆,是**恆真**。
凡是「某規則不准誤傷 Y」這一類的檢,基準集合必須是**關掉那條規則時**的結果。

**LL381 一張排除表只能放一種性質的排除。**
「範圍排除」(它不是活樹上的東西)與「角色排除」(它是尺/門/正本)判準相反:
前者吃到目標物就是判寬,後者吃到目標物正是目的。混在一張表,
任何一條想管住它們的檢都只能二選一 —— 要嘛放過該抓的,要嘛罵錯該放的。

**LL382 附帶的欄位也要有人看。**
檢裡順手多印的一欄,如果沒有任何一條斷言在看它,它壞掉的時候檢還是綠的。
批705 實例:可跑性分類因為少一行 `import ast` 而 **100% 壞掉**,而該檢照樣通過。
多印一欄就要多一條負控,否則那一欄只是裝飾。
