# 批633 · 整欄 ABSENT 不是缺料,是欄名寫錯了

工作站 105 份實跑帶回三件。

## ① 上漲空間 105 格全 ABSENT —— 我先前讀錯了

我在批630B 跟你說那是「VDF 價格庫沒有上市股的價」。**不是。**

`ABSENT` 的定義就是**庫裡沒有這一欄**。而正典表 `vrn_report_basic` 裡有:

```
upside_report DOUBLE · upside_calc DOUBLE · upside_db DOUBLE · upside_state VARCHAR
```

**沒有一欄叫 `upside`**,而 ENG083 的欄位鍵就寫 `upside`。

整欄 ABSENT 比一格紅更危險:它長得像「引擎版本不合」這種**誠實態**,
不像「我打錯字」,所以連著好幾批都沒人起疑(LL236)。

### 為什麼能活這麼久:夾具自己造了一個 schema

ENG083 的自測夾具自己 `CREATE TABLE` 了一份表,裡面寫 `upside DOUBLE`、`close_price DOUBLE`
——**兩個都不是正典表的欄名**。夾具與程式碼彼此自洽,自測一路全綠,量的卻是一個不存在的庫。

附帶傷害:`_v_tp` 裡「先讀 `close_price`,退到 `price`」的**真路從來沒被走過**,
夾具用假欄名把它擋住了。L83 說「只有一半的路被走過就不算跑過」——
這是它在夾具上的樣子:**夾具跟正典不同源,跑過的那一半是假的**(LL237)。

## ② 第五盞燈:N/A(不適用)

| | 數字 |
|---|---|
| 股票代號 NODATA | **48** 格 |
| ENG073 分出來的非個股報告 | **48** 份 |

完全對上。產業報告、大盤晨報本來就沒有個股代號——那 48 格是**永遠補不起來的洞**,
不是還沒做完的工。全部算進缺料,可判率就永遠壓著,而看的人會去補一個補不了的東西(LL238)。

三條紀律:

1. **只認冊**(`VRN_MatrixApplicability_SSOT_v0100.json`),引擎不自己判。
   冊裡現在**只有一條**,而且是從 ENG073 自己的分類律推出來的
   (「有代號一律先算個股」⇒ 非個股 = 檔名裡沒有可驗證的代號)——不是我的意見。
   其餘兩條寫在 `pending_operator` 等你裁定。
2. **冊缺席 = 全部當適用**,不假造 N/A。給多了 N/A 就是把真的缺料藏起來,跟假綠同一種傷。
3. **兩個可判率都印**(全格 / 扣掉不適用)。留著 N/A,100% 按定義做不到;
   悄悄拿掉,比率又憑空好看。只印好看的那一個,就是 LL228 的反面版本。

### 我第一版踩的坑:「不知道」當成了「不適用」

規則寫成「`report_kind` 不在 `[個股]` 裡就不適用」——**空字串也不在**,
於是舊庫、分類器留白的那些列整欄被判成不適用。
那正好是我自己在同一本冊上寫的第 2 條紀律。

**不知道型別就維持原判**,寧可留一格誠實的 NODATA。
抓到它的是批630 以前就寫好的舊夾具——**舊檢是新功能的防線**;
新功能讓舊檢變紅的時候,先假設是新功能錯了(LL239)。
