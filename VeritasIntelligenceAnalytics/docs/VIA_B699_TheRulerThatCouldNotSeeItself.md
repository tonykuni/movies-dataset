## 題目

`_tail_files()` —— 中央控管台用來決定「哪些檔算受治理元件」的那把尺 ——
十幾批以來一直是**九條手寫的 `(夾, glob)`**。

樹長大之後,整批治理中的尾版模組落在那九條之外。帶排除清單量出來是 **92 支**。

最難看的一支:

| 漏掉的 | 它是幹嘛的 |
|---|---|
| `SUP_MDL751_VIATailPick` | **決定「哪一版是尾版」的那把尺** —— 全樹經 `[VIA:TAILPICK-BRIDGE:v0100]` 綁它 |
| `SUP_MDL737_SuperAccelModule` | 加速器本體 —— 全樹 842 支經 `[VIA:ACCEL-BRIDGE]` 綁它 |
| `SUP_MDL752/753/754` | 共用 JSON I/O · 共用工具 · 收容基線 |
| `supportive modules/ssot` 16 支 | SSOT 模組 |
| `supportive modules/audit_tools` 6 支 | 稽核工具 |

換句話說:**中央控管台看不見那把決定尾版的尺,也看不見那支所有人都在用的加速器。**

## 後果不是燈變紅,是冊上根本沒有它們

```

```

不是「登記過後來退役」,是**從來沒被登記過**。`registry-sync` 一跑,
新 **1,966** 個元件 —— 1,966 個活著的元件從來不在冊上。

而這件事**漏掉不會紅**,所以它躺了十幾批。這正是批692 以來同一族的病:
**敘述與斷言對不上,而沒有任何一盞燈會照出它**。

## 修法:不是把清單寫長一點

手寫清單的毛病不是「寫漏一行」,是**它會隨著樹長大愈來愈假**。再補九條,
下一個新夾一樣進不來,而且一樣不會紅。

所以改成 **「全樹 − 具名排除」**(L77 掃描根一律帶排除清單律):

- 新開的治理夾**自動進來**,不必有人記得回來改清單;
- 要排除就**得寫得出因由** —— 寫不出因由的排除,等於在掃描面上挖一個沒人知道的洞,
  而洞裡的東西在中央控管台上等於不存在(LL359)。

九式沒有刪掉,改當**歷史下限(floor)**:㉛ 檢拿它守只增不減。

## 順手修掉的兩把尺

舊寫法用 glob `*_v????.py` **比**、用 `_v\d{4}\.py$` **去版號** —— 兩條尺不同。
於是 `..._v139L.py` 收得進來卻去不掉版號,家族名裡帶著 `.py`。
現在比與去同一條尺;版號異形由 `scan_face()["oddver"]` 誠實列出來(3 支),不是默默丟掉。

## 兩條新檢,都帶反面控制

| 檢 | 釘什麼 | 反面控制(讓資料**跨過**那條界線,LL358) |
|---|---|---|
| ㉛ | 全樹掃的結果必須覆蓋九式下限的每一支 —— **只增不減** | 注入一條吃掉整個 `registry` 夾的排除,下限檢必須當場破,而且**點得出名字**(實測照出 138 支) |
| ㉜ | 每條排除要有因由;**不准吃到下限裡的檔**;逐條印出吃掉幾支 | 塞一條因由留空的排除,必須當場被點名 |

㉜ 為什麼要逐條印數字:排除是**子字串**比對。一條寫得太寬的排除(例如只寫 `test`)
會安安靜靜吃掉一整個治理夾。逐條印出吃掉幾支,**過寬會以「數字不合理」現形,而不是以沉默現形**。

吃 0 支的是**這棵樹上**的死條文(容器沒有 `.venv`/`envs`/`node_modules`,工作站有),照實報,不報紅。

另外兩條標成**預防條文**,今天也吃 0 支,但留著的理由跟死條文不同 ——
掃描面改成「全樹 −」之後唯一新增的風險,就是有人把第三方碼放進來並帶上 `_vNNNN`,
它會**自動變成 VIA 元件**:

| 預防條文 | 背後的律 |
|---|---|
| `TALib` | **L50 第一條:TA-Lib 禁用,QuantGuard 是唯一正主** —— 第三方指標庫不得因為帶了版號就變成受治理元件 |
| `vendor` | 第三方 vendored 碼不是本系統元件 |

`預防:` 是標記不是路徑片段,比對前先拆掉 —— 不然它永遠吃不到東西,
就成了一條「看起來在擋、其實擋不到」的假條文(LL354 同一族)。
`scan_face()` 分開報 `prevent`(今天吃 0)與 `alive_prevent`(真的擋到東西),
擋到東西的那天要看得見。

量過:改版後的掃描面 **零支** `vendor` / `TALib` / `intake` / `_runs` / `output_hub` / `deck_intake` / `.git` 的檔進入受治理集合。
