## 一、先回答任務 #78:「單靠 `@` 就能完成 80% 建檔」是真的嗎

操作員 2026-09-23 附註的宣稱,批713 記在 `claim_check` 不當事實收。現在量得出來了:

| 分母 | 值 |
|---|---|
| **每個 `@` 錨點** | GREEN 72 / 92 = **78.3%**(姓名與 `@` 前對得上) |
| **每份研報** | 有電郵的 41 / 81 = **50.6%** |

**兩個分母的答案完全不一樣。**
在有電郵的地方,`@` 確實接近 80% —— 這句話是對的。
但**一半的研報第一頁根本沒有電郵**,`@` 這道錨點碰不到它們。

> 所以誠實的講法是:「**單靠 `@`,能把有電郵的那一半做到八成**」。
> 把 78.3% 講成「八成的作者建檔完成了」,就是拿錯的分母報對的數字(LL402 家族)。

四態全貌:GREEN 72 · UNVERIFIABLE 12 · YELLOW 4 · NODATA 4。

## 二、洞一:拒絕閘有一道**網域側門**

批678 立了拒絕清單 20 條(陸券),`廣發` / `GF` / `GF Securities` 三個別名都在上面。
但閘比對的是**別名字面**。語料裡出現的是:

```
…@gfgroup.com.hk
```

網域字根 `gfgroup` —— 三個別名**一條都對不上**。它就這樣從側門進來了 **2 次**。

> L20「網路只認 AegisNexus」管的是**連線**。
> 這一條管的是**資料來源身分** —— 同一份研報,從網域這一側進來的時候沒有人看。

補 `deny_domains` 10 條(廣發/中信/國泰君安/中金/海通的研究部常見網域),三態分清楚:

| 態 | 意思 |
|---|---|
| `DENIED` | **有這條而且不收** |
| `RESOLVED` | 冊上有,裁定得出來 |
| `UNKNOWN` | 冊上沒有 —— **不猜** |

「查無」跟「拒絕」是兩件事,混成一個空字串,下游分不出來這是沒查到還是被擋掉。

**負控比正控更重要**:`ctbcsis.com` 是**中國信託(台)**,
而 `中信證券`(CITIC,陸)在拒絕清單上 —— 兩家名字像,是兩回事。
批678 的 `deny_leak` 早就記過這個同名陷阱,⑮ 再釘一次:**擋錯人跟放錯人一樣傷**。

### 然後這道拒絕清單,把它要拒絕的東西救回來了

第一版我把被拒券商的**名字寫成 map 的值**:

```
"gfgroup.com.hk": "GF Securities"
```

全格子跑下去,批679 的**陸券清除實跑驗收**當場紅。它掃的是全樹尾版,
判準是「字串字面量裡出現陸券正典名」= **活的解析資料**;在註解裡才算 `[註解]`。
我那張表不管標題叫「拒絕」還是「映射」,在掃描器眼裡就是一張**活的陸券解析表**。

而且更糟的在後面。樹上本來有兩條**懸空指標**:

```
VRN_Integrated_ReportDatabase_Engine.py   "GFHK" → "GF"
VIA_VRN_FirstPageEngine.py                "GFHK" → "GF"
```

`GF` 早就被清掉了,所以這兩條是指著空氣的死指標 —— 批702 起明訂**不算紅**。
我把 `GF Securities` 寫回去的那一刻,**它們指到的東西又存在了**。

> **我的拒絕清單,把它要拒絕的那個東西救回了活的。**

改法:值一律寫 `DENIED`(那是**態**,不是名字);名字留在批678 那一本留痕台帳,
本冊、本引擎、連格子的站名都**不寫**。三個檔一起洗乾淨之後:

```

```

## 三、洞二:`@` 前**不一定是姓名**

華南投顧四份研報的分析師信箱長這樣:

```
電子信箱450@entrust.com.tw
電子信箱10863@entrust.com.tw
電子信箱9899@entrust.com.tw
```

`450` 是**員工編號**。這種 `@` 前**互證不了** —— 但批713 的程式會判成 `YELLOW`(具名衝突)。

> **驗不了,不是對不上。** 判成衝突就是憑空造一個衝突出來。

補 `at_left_kind` 三別:`NAME` / `STAFF_ID`(全數字)/ `ROLE`(research、ir、service…)。
後兩種一律 `UNVERIFIABLE`,**永不 YELLOW**。
券商那一欄照樣由網域裁定(`entrust.com.tw` → HUANAN),不受影響。

## 四、洞三:中文姓名咬到內文 —— 兩道鎖,一道不猜詞表

批713 的機構詞擋板擋不住這兩類:

| 咬到的 | 是什麼 |
|---|---|
| `據設備領` `導製造商` `戶多元且` | **長句子裡切出來的四字片段** |
| `電子信箱`(4 次)`資料來源`(3)`主要財務`(2) | 版面標籤 |

第一類**不必猜詞表**:要求候選是**獨立中文串**(左右不接中文),整批消失。
第二類是獨立串,才用量到的詞補擋板 —— **逐條量到才加,不預先想**。

剩下的是 `設計` `紡織` `揭露` `尋求` `群展` 這種獨立兩字詞。
再補詞表就是打地鼠,改用一條有依據的線:**台灣分析師姓名的首字是姓**。

> **只分級,不丟棄。** 首字是常見姓 → `name_cn`;不是 → `name_cn_weak`,原文留著。
> 罕見姓的分析師會落在 weak —— 那是**驗不了不是判錯**;丟掉才是判錯。

補完之後 `name_cn` 剩下的全是真名:
林子期 · 郭經緯 · 李政穎 · 黃勵誠 · 呂旻旂 · 鄭宇宏 · 潘俊宏 · 黎光岱 · 許願 · 陳逸民。

## 七、這一批的律

**LL408 拒絕清單比對的是字面,那就會有一道字面碰不到的側門。**
別名擋得住 `廣發`,擋不住 `gfgroup.com.hk`。
**每開一個新的識別面(網域、代碼、檔名),拒絕清單就要跟著長一面**,
不然那個面就是敞開的。

**LL409 「查無」和「拒絕」不可以共用一個空值。**
兩個都回空字串,下游永遠分不出這是沒查到還是被擋掉 ——
一個該去補冊,一個該去查為什麼有人送陸券進來。

**LL410 擋不掉的東西改用分級,不要一直補詞表。**
補到第三輪還在補,就表示用錯了維度。
`設計` 擋不掉不是因為詞表不夠長,是因為**該看的是首字是不是姓**。

**LL411 拒絕清單不可以把名字抄進實作。**
抄進去,那張表自己就變成**活的解析面**;更糟的是,被清掉的正典鍵會因為你寫了它而復活 ——
樹上原本指著空氣的死指標,當場變回真指標。
**擋一個東西不需要在擋它的地方寫它的名字。** 寫 `DENIED` 就夠了,名字留在台帳那一本。
這跟 LL384(檢自己不可以含它禁的字面)是同一條律的下一層:
**LL384 管的是誤判自己,LL411 管的是把清掉的東西寫回來。**
