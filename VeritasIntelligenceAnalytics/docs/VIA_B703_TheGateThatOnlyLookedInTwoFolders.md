## 一、先更正題目:不是 7 支,是 28 支

批680 的收尾寫著「還有 7 支沒過閘」,批680b 寫著「還有 7 支沒接閘(文字尺 3/10 沒變)」。
那個 7 是**手數的**,而且是照著 `gate_bypass()` 印出來的表數的。

`gate_bypass()` v0100 長這樣:

```python
roots = [VIA / "functional modules" / "VRN", VIA / "supportive modules" / "70_VRN_Rules"]
for q in root.glob("*.py"):          # ← 不遞迴
    ...
    stem = re.sub(r"_v\d{3,4}$", "", q.stem)
    if stem == q.stem:               # ← 無版號檔整個跳過
```

**兩個手寫根、不遞迴、跳過無版號檔。** 同一把尺(`_reads_broker_book` / `_is_gated` 一個字都沒改)
放到全樹去量:

| 讀券商冊的活尾版 | 10 支 | **37 支** |

*(第一版量出 41/8/28;把尺自己和另外三支「門與正本」排掉之後才是這個數 —— 見第四節。)*

少看見的那些不是被判成安全,是**根本沒被走到**。其中 4 支就是批680 自己點名的那七支:


## 二、為什麼舊檢照樣綠

檢 ㉗ 當時寫的是:

```python
chk("㉗ 沒過閘的活支逐支指名(尺量的是**檔案內容**,不是印象;L93)",
```

## 三、做了什麼

### CGC_MDL176 v0100 → v0101:掃描面換成「全樹 − 具名排除」

批699 對 VCGC 的掃描面做過同一件事,這裡照同一式:

* `GATE_SCAN_EXCLUDE` **16 條**,每一條寫得出因由(`__pycache__`、`RetiredEngines`、
  `references/`、`SCOPE_COPY`、`_superseded`、`new modules engines`、
  `VIA_Standalone_Package_`、`/tests/` …)。
* 回傳從兩態變**三態**:

  | 態 | 意思 |
  |---|---|
  | `GATED` | 檔案裡看得到拒絕閘的字樣 |
  | `EXEMPT` | 讀了冊但不必走閘 —— **逐支具名且寫得出為什麼** |
  | `PENDING` | 讀了冊、沒有閘、也沒有具名豁免 —— **這一欄就是還欠的帳** |

  豁免名單刻意只有兩個名字(`VIA_SSOT_Unified.py` / `VETF_VIA_SSOT_Unified.py`,
  共 5 個落點):它們把各本冊原樣端上來給別人判,自己不做券商名解析,
  在聚合層加閘會讓判準有兩個出處(L30)。**講不出理由的一律留在 PENDING** ——
  數字難看可以,數字消失不可以。
* 三條新檢,每條帶反面控制:

  | 檢 | 量什麼 | 反面控制 |
  |---|---|---|
  | ㉗c | 換掃描面只增不減:v0100 兩根看得到的每一支都還要看得到 | 注入一條吃掉整個 `70_VRN_Rules` 的排除 → 下限檢必須當場破**且點得出是哪幾支** |
  | ㉗d | 排除逐條具名 + 逐條印吃掉幾支 + 不准吃到已過閘的檔 | 因由留空要被抓;吃 0 支的死條文照實報不報紅 |
  | ㉗e | 三態逐支落地:豁免要有 why,還欠的要逐支指名 | — |

### vrn_report_digest v0116 → v0117:把閘接到**兩條**車道上

`harvest_meta()` 解析券商名有兩條路,v0116 **兩條都沒閘**:

```python
for broker in broker_dict:                    # 車道一:正文比對
    if broker and broker in hay:
        meta["broker"] = broker
        break
...
if hit:                                       # 車道二:檔名縮寫對映
    meta["broker"] = hit
```

v0117 兩條都過同一扇門。而且車道一用 `continue` 不是 `break` ——
**被拒的那一家不能把後面合法的那一家連坐擋掉**。

實測(探針從疊加層 `deny_keys` 當場取,名單一個字都不抄進本檔):

|---|---|---|

| 檔名 `ZZQ1815.pdf` | `'摩根'` | **`None`** |

### 修法用正典寫法,不用字串比對

第一版我把自排除寫成 `GATE_SCAN_EXCLUDE` 裡的一條子字串。
MDL164 的 ⑰ **看不到**那種寫法 —— 它認的是 `_SELF_FAMILY` 或
`stem.rsplit("_v", 1)[0] ==` 這一類**家族級**的排除。而它認的那一種也確實比較強:

```python
_SELF_FAMILY = re.sub(r"_v\d{1,4}$", "", Path(__file__).stem)
...
if stem.rsplit("_v", 1)[0] == _SELF_FAMILY or stem == _SELF_FAMILY:
    continue
```

用家族名不用 `__file__`:只排掉 `__file__` 的話,一開 v0102 **舊版就變成
「另一支讀了券商冊的活支」**,自己又回到分母裡(批578 就是這麼中的)。

檢 ㉗f 把這條釘住,帶反面控制:把自排除拿掉,尺必須當場自己冒出來 ——
證明那條排除真的在擋,不是裝飾。

修後 `CGC_MDL164 ⑰`:`SAFE 8 → 9 · 基線外 1 → 0` · **24 檢 OK 24**。

這是 LL133 這一族第四次(批695 / 697 / 699 之後)。棘輪每一次都當場咬住,
而且每一次都是**我自己**寫的新判定器 —— 寫尺的人最容易忘記自己也在被量的那棵樹上。

## 八、新法

**LL375 掃描器的檢要驗「掃到哪裡」,不是只驗「回傳長得對不對」。**
一條只驗回傳形狀的檢,對「掃描根寫死兩個夾子」完全無感 —— 每一條輸出都對,
只是少了一大半。掃描器的檢至少要有一條**下限檢**(換尺之後舊尺看得到的都還要看得到)
外加一條**反面控制**(注入一條過寬的排除,下限必須當場破且點得出名字)。

**LL377 寫尺的人也站在被量的那棵樹上。**
新寫一支「回答誰引用 / 誰覆蓋 / 誰過閘」的判定器,它的原始碼裡必然帶著它自己的判準常數
和自己的名字 —— 不排掉自己家族,它就會替自己的分子加一。排除要用**家族級**寫法
(`_SELF_FAMILY` / `stem.rsplit("_v",1)[0] ==`),不能只排 `__file__`:
只排 `__file__`,開了新版號之後舊版又回到分母裡。這一族第四次了。

**LL376 覆蓋率的分母要跟著掃描面一起被檢。**
「3/10」「6/7」這種數字,分母是掃描面決定的。分母錯了,比率再漂亮都沒有意義,
而且它會讓人以為只剩一點點。報覆蓋率就要同時報**掃描面是什麼、排除了什麼、各吃掉幾支**。
