## 三、三支真自測,照真 import 邊排序

### `VIA_MambaBridge_v0101`(15 條邊)· 六檢

量到兩件,**兩件都釘住現況、不擅自改**:

**① 抽取式很窄。** `numpy-1.26.0` 抓得到,`pandas 2.1`(空格分隔)**抓不到** ——
而 mamba/conda 的訊息兩種寫法都有。檢 ② 把現況釘住,**不假裝它很寬**:
哪天有人放寬,這條會亮,那時才知道行為變了。

**② fail-open:報告缺 `IsConflictFree` 鍵時,那一筆衝突被靜靜丟掉。**

```
乾淨環境           → 0 筆   (對:不該每個環境都生一筆假衝突)
有衝突             → 1 筆   (對)
缺 IsConflictFree  → 0 筆   ← **衝突消失了,而不是變紅**
```

上游改欄位名或報告殘缺時,**環境衝突會無聲消失**。
這跟任務 #67「同意閘 fail-open」是同一族的病。
**但改判準會動到環境治理的紅綠,屬操作員裁定** —— 本批只把它釘住、寫進檢的敘述裡。

其餘四檢:乾淨環境不進清單 · `ConvertTo-Json` 單元素物件也要收 ·
去重鍵只看三欄(**負控**:detail 不同不准被去重掉)· 壞 JSON 退預設(**正控**:好的要真的讀出來)。

### `VIA_DefTestAudit_v0102`(6 條邊)· 四檢

**現況裁定:沒命中 `def_test_` 時回 `None`,而簽章寫的是 `-> dict`。**
呼叫端一律要先擋 None。釘住,不改(改了會動到所有呼叫端)。

另外三檢都帶對照:模組層 `COLLECTABLE_AFTER_RENAME` vs 巢狀 `NESTED_STILL_UNCOLLECTABLE`
**互為負控**(全判同一態的分類器也會讓「有分類」看起來成立);
撞名要**跳過不硬改**(硬改會造出兩個同名函式,後面把前面蓋掉,比不改更糟),
**正控**=不撞名時要真的改得動、連內文引用一起改;語法壞檔誠實報 `parse_ok=False`。

### `via_synonym_engine_v0101`(5 條邊)· 四檢 —— 本批最重要的一條分態

實測種子檔:**canonicals 41 條 · synonyms `0` 條。**

```
resolve("任何詞") → None
```

一道只檢「resolve 回 None」的檢,會把**兩件完全不同的事判成同一種**:

| | 現象 | 該怎麼辦 |
|---|---|---|
| 引擎壞了 | resolve 永遠 None | 修碼 |
| **冊上沒有料** | resolve 永遠 None | **補冊,碼一個字都不用動** |

**把缺料說成缺陷,會讓人去修一支沒壞的引擎。**
所以檢 ③ 合成一條同義字丟進去再查一次(**正控**:證明引擎是活的),
檢 ④ 才把「冊上 0 條」當**誠實態**照實報 —— 冊被補料的那天它會亮。

## 六、新律

**LL399 字面/子字串判準會被「長得像」的東西騙,而且是連續慣犯。**
一週三次:`.json` 檔名字面被當成「有引擎在讀」(批709)· token 尺用字元數(批708)·
`from pathlib import Path` 的 guard 被 `… as _sa_Path` 騙過(本批)。
**凡是用字面去代表「某個行為/某個性質」的判準,都要先問:什麼東西長得像但不是?**
能用 AST 就別用字串;非用字串不可,就補一條負控餵它一個「長得像但不是」的樣本。

**LL400 一道檢要分得開「壞了」和「沒有料」。**
兩者在輸出上長得一模一樣(都回 None / 都是空),但處置**完全相反**:
一個要修碼、一個要補冊。分不開就會有人去修一支沒壞的引擎。
分法:**加一條正控** —— 合成一份料餵進去,看它活不活。活的就是缺料,不是缺陷。
