## 三件是制度,不是版面

### ① 燈號管理收成兩本冊
`LAMPS`(四盞燈:顏色 / 中文 / 意思)與 `VERDICTS`(五個裁決:掛哪盞燈、進不進分母)
是全樹唯一出處。頁上的 CSS 色、圖例、燈條、篩選器**全部從這兩本長出來**,
頁裡**不另寫一份 `state → 色碼`**。

> 為什麼要這樣釘:批630B 燒過一次——退路 `_load_rating_canon()` 悄悄換了一把尺,
> 拿人話詞表(`"NOT RATED"`)量正典鍵(`NOT_RATED`),四份抽對的被判成黃燈,
> **而且沒有人知道**(LL209)。尺散在各處,就一定會長出第二把。

自測 ㊳ 掃 `to_html` 原始碼:出現第二份 `"GREEN": "#…"` 就 FAIL。

### ② `in_denom` 是真的被讀的那一欄
判對率的分母資格寫在裁決冊,但只要 `self_verify()` 裡另外手抄一份 `PASS+FAIL`,
冊就變成**裝飾**:冊改了數字不動,而讀冊的人以為改得動。

v0109 的分母是 `sum(c for k, c in vd.items() if k in denom_verdicts())`,
自測 ㊵ **把冊上的 `in_denom` 翻一個**,分母不跟著 +1 就 FAIL(LL234)。

### ③ 舉證自動調節,而且把收斂寫進舉證本身
格數 ≤ 1200 給全量逐格;超過就只列非 GREEN 的格,
並在 `depth` 裡寫清楚:現在是 full 還是 focus、為什麼、列了幾格、省了幾格,
且 `n_listed + n_omitted == n_cells` 有檢在釘(㊲)。

> 理由不是省空間:**貼給 AI 的那一份會先被截斷,而截掉的是尾巴,
> 尾巴往往正是壞掉的那幾格。**
> **悄悄少給比給少了更糟**——給少了對方知道要再問,悄悄少給對方以為他拿到全部了(LL235)。

## 這一批我自己的檢先假綠了一次

㊴ 要釘「每一個產得出來的裁決都在裁決冊裡」。第一版寫:

```python
re.findall(r'verdict = "([A-Z_]+)"', body)      # → {'PASS'}
```

而程式裡是:

```python
verdict = "PASS" if ok is True else ("FAIL" if ok is False else "UNVERIFIABLE")
```

**一行三個答案,正規式只看得到第一個。**檢是綠的,而它只掃到 `PASS`
——一個號稱在防假綠的檢,自己假綠(LL232)。

改走 AST 之後又抓到第二件:`matrix()` 裡 `state` 這個鍵有**兩個命名空間**——

| 層 | 值 | 誰在管 |
|---|---|---|
| 引擎層 `{"state": …}` | `OK` / `NODATA` / `ABSENT` / `FAIL` | 接 rc,㉒ 在管 |
| 格子層 `{"state": st}` | `GREEN` / `YELLOW` / `NODATA` / `ABSENT` | 燈號冊 |

兩邊只有 `NODATA` / `ABSENT` 剛好同名,所以混在一起錯得**很安靜**:
拿 `OK` / `FAIL` 去問燈號冊,問出「冊上沒有」——不是冊漏了,是我問錯冊(LL233)。
