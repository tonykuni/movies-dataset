# 批666 · 一盞綠燈配一本舊冊

## 你貼回來的

```
PS> via-vrnbook
=== VRN 邏輯架構索引冊 · 守門 ===
  指標 35 · 在位且為尾版 35 · **過期 0** · 不在 0
  [計] GREEN
```

容器這邊同一句指令:**指標 50**,而且多一行 `[已裁·留痕齊]`。

**兩邊差 15。兩盞燈都是綠的。**

---

## 先認我自己的錯:那堆 ParserError 是我害的

你把整段量測結果貼進 PowerShell,跑出一串「無法將 'finlex' 字詞辨識為 Cmdlet」。

那不是你貼錯 —— 是我把**量到的數字**和**可以貼的指令**放進了同一種外觀的框:

````
```powershell
via-finlex --rulings     ← 這是指令
```

```
finlex 三十檢  OK 30    ← 這是結果,但長得一模一樣
```
````

在終端機前面的人,看到框就會貼。

→ **LL313:凡是給操作員看的輸出,「可以貼的」和「量到的」不准長成同一個樣子。
指令框裡只放指令,一行都不多。**

從這一批起我照這條做。

---

## 那個 35 是怎麼回事

根因量到了:

```
Updating adc80136..cc0bd4ad     ← 你的樹停在 批660,中間隔了 5 批
```

拉完就對上了。**但真正的問題不是你沒拉,是守門沒看出來。**

守門問的是:「冊上這 35 個指標,每一個都指得到樹上的尾版嗎?」
答案是「都指得到」,所以它誠實地回了綠。

**它誠實地回答了一個沒有人在問的問題。**

沒人問「這 35 個指標指得準嗎」,大家問的是「這本冊是現在的嗎」。

---

## 冊不知道自己是誰建的

打開冊看:

```json
"version": "v0101",   "batch": "批641",   "ts": "2026-09-20"
```

**那是寫死的字面。** 引擎已經走到 v0103,冊還說自己是 v0101。

所以那個 35 沒辦法自己說出它是舊的 —— 它連自己是誰建的都不知道。

→ **LL314:一本記不住「我是誰建的」的冊,它上面每一個數字都沒有年齡。
綠燈配舊冊,是一盞查不出問題的綠燈(LL304 的第二個渡口)。**

---

## 兩修

### ① 身分欄不再寫死

```python
_ME     = Path(__file__).stem          # via_vrn_logic_book_v0104
_ME_VER = "v" + _ME.rsplit("_v", 1)[-1]

"version":   _ME_VER,
"built_by":  _ME,
"built_at":  datetime.now().strftime("%Y-%m-%d %H:%M"),
"from_batch": "批641",    ← 原始出身留著,只增不減
```

### ② 守門第一行先講身分,再加一盞 [冊版不同步]

```
=== VRN 邏輯架構索引冊 · 守門 ===
  引擎 via_vrn_logic_book_v0104 · 冊由 via_vrn_logic_book_v0104 建於 2026-09-20 18:29 · ...
  指標 50 · 在位且為尾版 50 · 過期 0 · 不在 0
```

同一句話在你機器上要是再出現 35,第一行就會當場說「冊由 v0101 建」。

**兩個方向都報**:

| 方向 | 意思 | 修法 |
|---|---|---|
| 冊比引擎舊 | 沒重建 | `via-vrnbook build` |
| **冊比引擎新** | **你的樹落後了** | `git pull` 再 `via-reload` |

只認一個方向的話,另一個方向會安靜地給出一盞綠燈 —— 而那正是這一批要修的東西。

判紅,不是提醒。
