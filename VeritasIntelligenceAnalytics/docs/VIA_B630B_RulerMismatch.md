## 一 · 評等那 4 格:抽對了,是尺量錯

其中一份的檔名就寫著「**瑞基(4171,NR_未評等)**」—— 抽出 `NOT_RATED` 完全正確。

`VRN_ENG083._load_rating_canon()` 依序找三把尺:

```python
for fn in ("rating_keys", "rating_canon", "rating_words"):
```

而樞紐 `SUP_MDL749` **只有最後那一個**。於是它退到**人話詞表**去量**正典鍵**:

```
判定器 rating_words()  66 詞   Buy · 買進 · Outperform · "Not Rated" · "Strong Buy" · NR …
產生器 broker_ratings   6 鍵   BUY · HOLD · SELL · STRONG_BUY · STRONG_SELL · NOT_RATED
                               ↑ 差一個底線
```

`BUY` / `HOLD` 剛好兩邊長一樣才矇對;`NOT_RATED` / `STRONG_BUY` 就判錯。

> **退路悄悄換了一把尺,而且沒人知道。**(LL209 同族:graceful 把錯誤蓋住)

修法:樞紐 v0108 補 `rating_keys()`(6 鍵,**從機構冊讀,不手抄**)。
`_load_rating_canon` 本來就先找它 —— 所以 **ENG083 一個字都不必改就接上了**。

順帶兩條規矩:
- 有 fallback 鏈的判定器,要**把真的用了哪一把尺講出來**。
  驗法句改成 `落在正典評等鍵(樞紐 {RATING_SRC})`,**現場填**。
  寫死名字的話,尺換了句子不會跟著換 —— 那就是冊上寫錯尺的名字。
- 抽取詞表與驗證鍵表**各自具名、不可互代**。補鍵不是往詞表裡加詞。

**結果:評等 42 → 46 綠,YELLOW 清零。**

---

## 二 · 目標價那 4 格:不是判錯,是沒有可對照的

`_v_tp` 要拿目標價比現價。沒有現價 → 回 `None` → YELLOW。
而那 4 支的價格**不在 VDF 庫裡**(上市股一支都沒有,見批630 量測)。

LL225 已經把準確率拆成判對率與可判率,但判對率的分母當時還是 `GREEN+YELLOW`,
而 YELLOW 裡混著兩種東西:

| | 意思 | 該算誰的帳 |
|---|---|---|
| **驗不過** | 尺說不對,真的判錯 | 邏輯 |
| **驗不了** | 有值,但沒有可對照的 | 料 |

把「驗不了」算進判對率,等於**把 VDF 的帳記到 VRN 頭上**,
而且補了料那個比率會自己上升 —— 看起來像「邏輯變準了」。

v0108 給每一格多記一個 `verdict`(`PASS` / `FAIL` / `UNVERIFIABLE` / `NO_VALUE` / `NO_COLUMN`);
四態 `state` **原樣不動**給下游(只增不減),判對率改用 verdict 算。

## 三 · 結果

```

[判對率] 100.0% = PASS ÷(PASS+FAIL) = 302/302 · 另有 **4 格驗不了**(有值但沒有可對照的),
         它們在四態裡是 YELLOW,但不進判對率的分母 —— 那是缺料不是判錯
[可判率] 53.3% = 302/567 —— 要 100% 準確,這兩個數字都得是 100%
```

**判對率 100%,FAIL 0 格。**
那 4 格驗不了**照樣寫在畫面上**,四態統計裡也還是 YELLOW ——
**判對率變好不是因為我把它藏起來,是因為它本來就不該在分母裡。**

可判率 53.3% 是接下來的全部工作,而它大半是 VDF 的帳:
上漲空間 81 格 + 目標價 47 格 NODATA + 4 格驗不了,全部指向同一件事 ——
**價格庫裡沒有上市股**。
