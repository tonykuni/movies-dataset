## 四、那支真紅:兩個缺陷,而且都不是我以為的那個

`CGC_MDL119_SystemAPI` 自測 `九檢 OK 8 · FAIL 2`。我原本以為兩條都是「容器缺料」。
量下去,**兩條都不是**:

### ① `str(None)` 把 falsy 變成 truthy

```python
d["latest_ym"] = str(ym)      # ym 是 None 時 → 字串 "None"
```

庫缺席時 `ym` 是 `None`,`str(None)` 生出字串 `"None"` —— 它是 **truthy**。
下游任何一句 `if latest_ym:` 都會看到「有資料」。**缺料偽裝成有料。**
修:`str(ym) if ym is not None else None`。

### ② 寫死的「今日四包」

```python
chk("②c 首頁附上船件冊(MDL122;今日四包 INTEGRATED)",
    ... and h["totals"].get("intake_today") == 4)
```

今天量到 **16 包**。那不是壞掉,是**寫死的數字過期了**(LL372 同一族)。
修:不釘數量 —— 件冊讀得到、今天的每一包都 `INTEGRATED`、今天零包就是 NODATA。

### 為什麼這支一直沒人管

因為 v0103 把「這台機器上沒有那份料」判成 **FAIL**,於是它在容器裡**永遠 rc=1**。
掛上格子就是一盞每跑必紅的假紅燈(LL366),所以它一直待在格子外面 ——
**連真的壞掉都不會有人知道**。這是一個閉環:不誠實的態 → 上不了站 → 沒人看 → 缺陷留著。

v0104 三態化(`chk3`,缺料先判):**11 檢 OK 10 · FAIL 0 · NODATA 1 · rc=2**,用 `nodata_ok` 掛上站。

## 七、沒做的,以及為什麼(L87)

* **87 支 PENDING 沒補站。** 其中 58 支有 `__main__` 但沒有自測 —— 要先**寫檢**才談得上上站,
  而替別人的引擎寫檢要先讀懂它在保證什麼,一批寫 58 支只會寫出 58 條會過的檢
  (會過的檢等於沒有檢,LL89)。逐支留在 `PENDING` 欄,數字印在自測上,**不會再消失**。
* **`CGC_MDL154_VIAFunctionalAcceptance` 沒掛。** 它 rc=1 但輸出是一份 HTML 路徑,
  rc 到底是「壞掉」還是「現況分類」沒查清楚 —— 沒查清楚就掛,等於賭一盞燈的顏色。
* **那 3 支偵測誤判沒補尺。** 判準該從 `"--selftest" in text` 收緊成 AST 層級
  (真的有這個 argparse 動詞)。這一批先把**數字**說對,收緊判準是下一批的事。

## 八、新律

**LL378 綠的分母要跟綠一起報。**
「OK 290 · FAIL 0」是一句沒有分母的話。290 是**站數**,不是**受治理的東西**;
站面蓋不到的,永遠不會紅。報全綠就要同時報**站覆蓋率**,
否則「全部成功」講的只是看得到的那一部分。

**LL379 不誠實的態會讓一支引擎永遠沒人看。**
把「缺料」判成「壞掉」的引擎,在缺料的機器上永遠紅;永遠紅的站沒人敢掛;
沒掛的站沒人看;沒人看的引擎壞了也不會有人知道。
這是一個閉環,而它的入口只是**一個態判錯**。
三態化不是報表好看,是**讓這支引擎有資格被看見**。
