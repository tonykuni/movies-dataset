# 批660 · 兩把尺,而我只看自己那把

## 你貼的截圖

```

  #274 workflow run failed for main branch
  #273 #272 #271 #270 … failed for claude/via-envmanager-governance-7cls8h
```

**#267–#274 連續八跑全紅,連 main 都紅。** 而我這八批,每一批收尾都寫著：

> 全格子 v04xx:OK 260 · FAIL 0 · SKIP 2 · TIMEOUT 0

**兩句話都沒說謊。**

## 根因(容器完整重現,同一個字)

```
FAIL: test_11_committed_page_matches_generator
  committed: <b>102</b><span>現役引擎族</span>
  generator: <b>105</b><span>現役引擎族</span>
  : tracked MasterControl 與正主管理器輸出不同步
```

我每批新增引擎,總控頁上的數字跟著變(`102→105` 現役引擎族、`133→137` 中央治理模組),
**而 `CGC_MDL167_RegenRevert` 每批都把那張頁當「再生產物」還原回去。**

兩條律打架,打了八批:

| | 說法 |
|---|---|
| **LL49** | 再生頁是產物,容器空庫會生假內容 → 還原 |
| **test_11** | tracked 的那張頁必須等於管理器當場的輸出 |

## 裁決:再生物要再分兩種

**純產物可還原;有測試釘著的契約產物必須入倉。**

那張頁上的數字是從**引擎樹**數出來的 ——

```python
active_engines = sum(1 for row in engine_rows if not row["state"].startswith("已退役"))
```

不是從庫來的。容器與 CI 會得到**同一個數**,LL49 的空庫顧慮在它身上根本不成立。

→ `VIA_RegenArtifacts_SSOT` 的 `keep_even_if_matched` +1 條（**改冊,不改碼**）。
再跑:`再生物 0 · 刻意入倉 2 · 不明 0`。

## 但更該修的是:為什麼要等 CI 紅八批

```
$ grep -c "tests/" 格子
0
```

**CI 跑的 19 個契約測試,我那 262 站格子一站都沒跑過。**

於是「全格子綠」與「CI 全紅」可以同時成立,而且各自都是誠實的量測 —— 因為它們量的**不是同一棵樹上的同一件事**。

→ Grid v0416 加「總控頁契約十九測」站,**用 CI 那支檔本身**,不是我另寫一份（抄第二份就又是兩把尺,L30）。站數 262 → 263。

正反都驗過:

```
現況              rc=0
把頁改回 102      rc=1     ← 咬得住
還原              rc=0
```

## 順手踩到的第二個坑:我的感想被當成資料讀走

加完站第一次跑,契約測試**又紅**,而且紅在一個我沒預期的地方:

```
tracked  : 中央治理功能模組（正式名稱待治理 · 候核序號 m033）
generator: —**兩把尺,我只看自己那把** 治理模組（候核序號 m033）
```

我在 Grid v0416 的版史第一行寫了「…而我每批都說『全格子綠』——**兩把尺,我只看自己那把**」，
**`VIA_SYSTEM_MANAGER` 的抽名器把它抽成了模組名稱。**

版史註解不是隨筆,它同時是管理器的**輸入**。第一行照既有格式寫,破折號與粗體留到第二行以後。→ **LL302**

> 一個檔可以同時是程式、是文件、是資料;改它之前先問這三種身分各有誰在讀。
