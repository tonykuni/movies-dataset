# 批662 · 「待裁定」如果沒人去讀,它就只是一個看起來很負責的垃圾桶

## 先收你的裁定

> 那只是樣本不用盼失效

批661 加的年齡欄留著,但**講法改了** —— 它是**描述性年齡帶,不參與判燈**,不是有效期。ENG073 / ENG083 兩邊的字都改過,那個「待操作員裁定失效門檻」的懸念收掉。

留著它的唯一理由:**一個百分比要能被讀對,常常需要第二個數字陪著**(LL304)。

## 然後去找「邏輯沒整理完」的具體長相

找到了。VRN 邏輯架構索引冊裡:

```
off_book_pending = 15 支
  每一支都寫著「樹上活著但未列入六層;是否上架構冊=架構裁定,待操作員」
```

那句話當時是對的(LL90:不代操作員裁定)。**但它讓 15 支引擎在冊外躺了 21 批。**

去量才發現:

```
11 支有格子站在跑   （有自測、被驗收、每批都綠）
 4 支沒有
```

它們**不是死件,是在跑但沒被編進架構**。「待裁定」把「我不知道」和「我沒去查」混在同一個桶裡了。

## 歸位的憑據不用我的直覺

用**系統自己對每支的定義** —— 優先格子站名(那是系統驗收它時的那一句),沒站的用 docstring 首句,**兩種都寫明是哪一種**:

| 層 | 支 | 例 |
|---|--:|---|
| L1 擷取 | 5 | `VRN_ENG052` ← 格子站名「docx 引擎(doc)」 |
| L2 結構與知識 | 5 | `VRN_ENG071` ← 格子站名「鉅亨 FactSet 共識九檢(批199)」 |
| L3 驗證 | 1 | `VRN_ENG049` ← 格子站名「reconcile 對帳」 |
| L4 產出 | 2 | `VRN_ENG065` ← 格子站名「郵件情報管線八檢(批143)」 |
| L5 儲存 | 2 | `VRN_ENG050` ← 格子站名「store 落庫(dry)」 |

每一筆帶 `evidence`。**你要推翻任何一支,看那一行就夠。**
