**技術面六處齊,治理面零。跑得起來,但沒人管。**

另外兩處查完是**不適用**,不是缺口:

- **EngineBus 任務盤 0 處** —— 治理型引擎(`accel` / `uiunify` / `govaudit`)**一個都不在任務盤上**。
  任務盤掛的是 VDF/VRN/VAP 的資料工。這是分工,不是缺口。
- **MDL139 輸入主控台 0 處** —— 操作員令「先不碰 HTML」,本批不動。

所以「導入了嗎」的誠實答案是:**沒有完整導入**。
中央盤點制度健全度的時候,它根本不在被盤點的名單上 —— 這就是 **L73 功能身分律**的由來:
**一個東西能跑,不等於它被導入;導入的判準是它在治理藍圖上點得到名。**

第二件事:**零件編號不是一個功能。**
它在樹上只有技術代號「PEIS 能力引擎掛線口」——沒有名字、沒有一句話、沒有承諾、沒有保證清單。

## 二、名字

# VIA Essentia
## 能力精粹核

> **把一棵長歪的樹,收斂成一本讀得完的書。**
> *Distill a sprawling codebase into capabilities you can actually read.*

取 **Essentia**(拉丁語:本質),對齊既有命名家族 —— Veritas · Celeritas · Aegis · Nexus。

**它在賣什麼:**AI 讀原始碼是按 token 計價的。一棵 2507 檔 / 47999 函式的樹,全文是百萬 token 級;
精粹成 9134 張能力卡之後是千位數級。**省的不是錢,是讀得完與讀不完的差別。**

| | 數字 |
|---|---|
| 活樹(cgc sup vdf vrn) | 2507 檔 / 47999 函式 → **9134 能力** · 折疊 31217 · 近似 49978 · **省 99.97%** |
| VRN 單族 | 12568 函式 → 2282 能力 · **塌縮 81.8%** · 散在 525 檔 |
| 墓園(批586) | 261 檔 / 3283 函式 → 1595 能力 · 折疊 922 · **省 99.42%** |

**六個動詞:**`status` · `scan` · `cards` · `run` · `report` · `deadcheck`

**七條保證:**正本零觸碰(比 bytes 不看旗標)· 零網路 · 零安裝 · 不代設同意閘 ·
不提供 `--apply` · 死樹活樹不同掃(L72)· 尺不量自己(LL133)。

**啟動條件:**零重複 → **不啟動整合**(誠實 NODATA,不是紅燈)。沒有重複就沒有東西可收斂。

## 四、順手修掉一個會永遠亮的假黃燈

承載件清單第一版我把收容正本 `references/intake/PEIS_UnifiedEngine_b*` 列進去,
`via-govaudit audit` 當場報 **PARTIAL:承載件 3 件有 1 件不在**。

根因:`references/intake` **在這個閘自己的 SKIP 裡**(正本零觸碰)。
列了它,就等於要求稽核去看一個它按律看不到的地方 —— **永遠少一件,永遠 PARTIAL**。

**判錯的黃燈跟判錯的紅燈一樣傷。**改列自測格(那才證明「活樹上真的有人在做」),GREEN。
收容正本在不在,本來就由 MDL161 檢①②③ 逐檔 sha256 驗,不需要這個閘再驗一次。
→ 寫進 L73 附帶條。
