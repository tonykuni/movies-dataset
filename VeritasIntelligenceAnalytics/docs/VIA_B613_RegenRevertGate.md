## 做成引擎,重點不是自動化,是分類

`CGC_MDL167_RegenRevert_v0100.py` 把髒的追蹤檔分三類:

| 類 | 判準 | 動作 |
|---|---|---|
| **再生物** | 冊上有樣式,**且附理由**(L87) | `--apply` 才還原 |
| **刻意入倉** | 白名單(台帳 / 法課 / 元件冊) | 永遠不動 |
| **不明** | 對不上任何樣式 | **一律不還原**,rc=1 逼人看 |

第三類才是關鍵。**引擎寫到原始碼、和你自己改的,在 `git diff` 裡長得一模一樣** ——
只有你分得出來。所以它不猜,它擋住。

**能自動的部分自動,不能自動的部分要擋住,不是猜。**

## 鐵則(十四檢逐條釘住)

- 預設**一個字都不改**;`--apply` 是你的手
- 未追蹤檔一根不碰
- 還原前整包複製到 `VIA_Reports/regen_revert/<ts>/`(第二條退路)
- 零 force · 零刪除 · 零 commit · 零 push
- 冪等:再跑一次,再生物已乾淨,不明的還在

冊:`VIA_RegenArtifacts_SSOT_v0100.json`,10 條樣式逐條附理由,例如

```
^VeritasIntelligenceAnalytics/VIA_Reports/   跑次報告夾:每一跑都重寫,內容綁當下的庫與時間
/registry/VIA_IndustryUnifiedMap            產業對照冊自 tw_listings_industry 再生;庫不同數字就不同
```

## 怎麼用

```powershell
via-regen            # 唯讀:攤開分類,零動作
via-regen --apply    # 只還原再生物,動之前先整包備份
```

跑完 `via-allinone` 之後打一次 `via-regen`,看一眼,再決定要不要 `--apply`。
