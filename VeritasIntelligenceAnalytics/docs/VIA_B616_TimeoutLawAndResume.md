## 一、逾時被算成紅燈(L91)

你那一跑 252 站 4,394s 還沒完,畫面上一整排紅。數一數:

```
中央治理台 600s · 介面合約 600s · 引擎調度匯流排 600s · 族群回測 600s
族群分類×價格指數 900s · 產品資格閘 900s · 轉檔器 DPI 600s · 首頁文字擷取 180s …
```

**十站是純逾時。** 而格子的程式碼是這樣寫的:

```python
except subprocess.TimeoutExpired:
    return {"state": "FAIL", "rc": "TIMEOUT", "note": "逾時"}
```

我自己在批611 的站名上寫「**被砍的站等於沒跑過,不是紅**」,格子本身卻還在把它算成紅。

> 逾時的站**沒有結論**:它可能是綠的、也可能是紅的,我們不知道。
> 算成紅就是**編造一個我們沒量到的結論**,而且會把真紅淹在一整排假紅裡。

v0371:

- `TIMEOUT` 獨立成態,不進 OK 也不進 FAIL,而且**逐站點名**
- 整跑 rc:有真紅 → 1;**只有逾時 → 2**(沒量完,誠實 NODATA,不冒充全綠)

合成驗證(兩條路都走):

```
逾時站 state = TIMEOUT | rc = TIMEOUT
真紅站 state = FAIL    | rc = 1
_tally → OK 0 · FAIL 1 · SKIP 0 · TIMEOUT 1   ← 逾時不再被算進 FAIL
```

## 二、逾時秒數是照容器調的

容器 31s 的站,你那邊要 164s。**同一個數字在兩台機器上是兩種意思。**

v0371 開跑先校準:固定工作量(純迴圈 300k + 一次子行程啟動)取三次中位數,
對容器基準 `0.024s` 算係數,夾在 `[1.0, 8.0]`。

- **永不縮短**宣告的逾時(只增不減)
- 不讓離群值把上限炸掉
- `VIA_GRID_TIME_FACTOR` 讓你直接指定 —— **你的手優先於我的量測**

容器實測 **×1.00 = 零回歸**。你那邊估計會落在 ×3–6:

```
×6 → 300s 站 1800s · 900s 站 5400s
```

## 三、「卡住」:重跑已經綠的步驟不是測試,是罰站

第 13 步跑了 4,394s,而前面 12 步全綠 —— 要看第 13 步的結果,卻得把前面 12 步再跑一次。

AllInOne v0108:

```powershell
via-allinone -From 13        # 從第 13 步開始
via-allinone -Resume         # 讀上一跑 run.json,GREEN 的略過
```

`-Resume` **只沿用 GREEN**:RED / NODATA / ABSENT / 逾時一律重跑 ——
沿用紅燈等於把紅燈藏起來。

略過的步驟**留一列 `SKIPPED`**,不是消失:表上少一行,看的人會以為它跑過了。

## 四、我這一批自己造的三個缺陷

**(a) 版號寫死。** v0108 的抬頭還印 `v0107` —— 跟「本視窗點的是舊冊」同族:
你畫面上看到的版本不是你實際在跑的版本。改成從檔名 regex 解。

**(b) 工具讀自己的輸出當輸入(LL179)。**
`-Resume` 掃存證夾取最新一份 —— 可是**本跑的夾在那之前就建好了**,
於是它挑到自己那個空夾,回報「上一跑沒有 run.json」。
跟 LL133(判定器不自判)同一條,形狀不同。
**凡是「取最新一份」的地方,先問一句「這裡面有沒有我自己」。**

**(c) 假設欄位名等於沒讀過那個檔(LL180)。**
我寫 `$prevRun.rows`,而 run.json 的鍵是 `steps`。
PowerShell 讀不存在的屬性回 `$null`,`foreach ($r in $null)` 跑零圈,**一個字都不抱怨**。
是印出 `GREEN 0 步` 而上一跑明明 `GREEN 1` 才發現的。
**「讀到零筆」要當成可疑訊號去查,不要當成「本來就沒有」。**
