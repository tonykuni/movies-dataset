## 二、jieba 那一盞:整串沒切 ≠ 切錯詞

容器跑**同一檢、同一句話**:

```
⑦ 分詞(jieba 道) (['台積電', '第三季', '毛利率', '創高'])   ← 綠
```

工作站切出來的是 `['台積電第三季毛利率創高']` —— **整串原樣回傳**。

那不是「分詞判斷錯」,是 **jieba 的字典根本沒載進來**(載入失敗時它退化成原樣回傳)。
兩種紅長得一模一樣,**修法完全不同**:

| 症狀 | 意思 | 怎麼修 |
|---|---|---|
| 整串原樣回傳 | 字典沒載 | 刪 `%TEMP%\jieba.cache` 讓它重建;刪不掉就是權限 |
| 切開了但切錯 | 詞庫或模式不對 | 調詞庫 / 換 backend |

所以這一檢改成**自己講原因**,而不是回一個紅字讓人去猜。
負控也驗了:`['台積','電第三季毛利率創高']`(切錯但有切)照樣紅,**但不會誤報成「字典沒載」**。

## 六、這一批的律

**LL428 `grep` 找到的檔,不等於尾版。**
這棵樹每支引擎五六個版本並存,`grep` 回的是第一個符合的。
改到非尾版有兩種後果,都很糟:
**修正進了沒人跑的檔**(以為修好了,其實沒有)、
**手跑的紅與格子的綠對不起來**(以為格子在說謊,其實兩邊量的不是同一個檔)。
**動任何一支之前,先 `ls …_v*.py | tail -1`。**

**LL429 「整串原樣回傳」和「切錯」是兩種紅。**
一個是工具沒載起來,一個是判斷錯了 —— 症狀一樣、修法完全不同。
檢要分得開,不然操作員拿著紅燈去調詞庫,而問題在快取。
