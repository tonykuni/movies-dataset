## 五 · 還沒收的(Z194)

普查剩下的 3 支都是**關聯層**:SQL 直接從一張表寫到另一張表，不經過 Python 的一批列。正典 `upsert_rows` 吃的是 Python 的一批列。

| 引擎 | 寫法 | 啟動入口 |
|---|---|---|
| ENG065 DbImport | 從 parquet 寫進表時用 except 去重 | 沒有(休眠) |
| ENG079 LocalDbConsolidate | 鍵比對 NULL 也算相等 + 來源先自己去重 + 沒有鍵時用 except | Register v0242 |
| ENG081 UniverseAlign | 先在暫存表做 anti-join 再寫進去，同一批新列還要另外落 parquet 增量 | Register v0242 |

硬套進正典的話，得先把資料搬進 pandas,而且「NULL 也算相等」「來源先去重」「把新寫進去的列回傳出來做增量落檔」這三種語意正典都還沒有。
照 Z191 的約定:語意不同，就先在正典另立一支關聯層的寫入，再逐支量語意、跑真庫副本零差異，然後才遷。沒遷之前普查名單照列，不算已收。

普查只看 SQL 本身。像 ENG078 v0109 那種在 Python 端先用集合去重、再一列一列插的寫法，它看不到。那一族這次是靠搜函式名抓到的，Z194 也記了這個盲點。
