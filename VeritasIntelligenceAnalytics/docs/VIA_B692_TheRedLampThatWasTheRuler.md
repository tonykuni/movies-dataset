# 批692 · 兩盞紅燈,兩支尺 —— 一棵樹不會有兩個真相

操作員把工作站的 `via-vrnrun` 貼回來,兩盞 RED:

```
SUP_MDL746_PDFPlumberPlusHub   RED  ⑦ 密度只當訊號不當判決
CGC_MDL141_ClosingGate         RED  ⑫ CLI --db/--zones 真的傳到 vrn_closeout
```

容器這邊**兩支都是綠的**。而「我這邊綠」從來不是答案 ——
批619 早就寫過:一棵樹不會有兩個真相,所以要先問**紅的是樹還是尺**。

逐條量完:**兩盞都是尺錯。** 而且兩支錯的方式不一樣,值得各記一條。

## 一 · ⑦:把「今天那棵樹的全庫長相」寫成了規格

工作站的細節句(操作員第二次貼,不截斷才看得到):

```
(THIN 1 件:Veritas Intelligence A=868字 · 全庫最低真文字首頁 112 字 > 界線 300)
```

⑦ 的斷言有三條,前兩條測的是它自己宣告的規格,第三條不是:

```python
all(c >= SPARSE_CHARS for _, c, _ in thin6)                  # THIN 件都還有真正文
and all(c < SPARSE_CHARS for _, c, _ in seen["SCANNED"])     # 判掃描的確實沒字
and (lo_real == 0 or lo_real > SPARSE_CHARS)                 # ← 全庫最低 DIGITAL 首頁字數 > 300
```

去讀分類器**實際**怎麼判:

```python
if   n < TRIAGE_MIN_CHARS:  state = "SCANNED"
elif dense_ok:              state = "DIGITAL"      # ← 密度夠就過,**在字數之前就短路**
elif n >= SPARSE_CHARS:     state = "THIN"
else:                       state = "SCANNED"
```

**分類器從來沒有保證過「DIGITAL 的首頁字數 > 300」。**
小版面 + 密度夠 + 首頁只有 112 字 —— 那是**合法的 DIGITAL**,不是缺陷。
第三條記的是寫檢那天那棵樹(容器 18 件)碰巧的樣子,不是規格。

> **LL332 又一次:會隨全庫改變的數字不可以當斷言。**
> 容器 18 件不會踩到,操作員 83 件一跑就紅 —— 而紅的那件是對的。

換成分類器**真的**保證的那一件,與全庫無關:

```python
and all(d >= P7["TRIAGE_MIN_CHAR_DENSITY"] for _, _, d in dig6)   # DIGITAL 的密度一律 >= 門檻
```

正控/負控(拿操作員的真數字合成,LL89):

| 情形 | 舊尺 | 新尺 | 要的 |
|---|---|---|---|
| 工作站那一組(DIGITAL 含 112 字件) | 紅 | **綠** | 紅→綠 |
| DIGITAL 密度破門檻(分類器真的壞了) | 紅 | **紅** | 照樣紅 |
| THIN 件字數不足 | 紅 | **紅** | 照樣紅 |
| SCANNED 件字卻很多(⑦ 本來要抓的假紅) | 紅 | **紅** | 照樣紅 |

**假紅拿掉,保護一條沒少。**

### 一之二 · 附帶修:一句在自己紅的時候還在說條件成立的話

```python
f" · 全庫最低真文字首頁 {lo_real} 字 > 界線 {SPARSE_CHARS})"
```

`>` 是寫死在字串裡的。所以失敗時它印的是「**112 字 > 界線 300**」——
讀的人會以為條件成立。細節句是用來指路的,不是用來湊版面的。

## 二 · ⑫:一條 POSIX 專用的斷言

工作站細節句:

```
(db=\tmp\_x_.duckdb zones=\tmp\_z_;無旗標時 kw=['do_print', 'report_dir', 'run'])
```

**「有傳到」四個字就寫在臉上** —— `db` 和 `zones` 都拿到了,無旗標時也沒有硬塞 None。
那為什麼紅?因為斷言是:

```python
str(_seen.get("db")) == "/tmp/_x_.duckdb"
```

`main()` 把 CLI 字串轉成 `Path`。於是:

```
Linux    str(Path("/tmp/_x_.duckdb")) == "/tmp/_x_.duckdb"     → 綠
Windows  str(Path("/tmp/_x_.duckdb")) == "\tmp\_x_.duckdb"     → 紅
```

跟**批619 的 CRLF** 是同一族:同一棵樹,兩個平台兩個答案,而**紅的是尺**。

改比 `as_posix()`,兩邊同一個答案;負控(值真的不對 / 是 None)照樣紅。

## 三 · 兩支的共同點,和不同點

| | ⑦ | ⑫ |
|---|---|---|
| 病 | 把**資料的長相**當規格 | 把**平台的長相**當規格 |
| 誰照出來的 | 操作員 83 件真檔(容器 18 件不夠) | 操作員 Windows(容器 Linux 不夠) |
| 共同點 | 都在**寫檢那天的那台機器上**恆綠 —— 所以寫的時候看不出來 | |

> **LL348:一盞只在你自己那台機器上綠的燈,跟一盞對的燈,看起來一模一樣。**
> (LL342 的孿生:LL342 講的是「東西不在所以恆綠」,
> 這一條講的是「東西剛好長這樣所以恆綠」。兩條都要靠**別台機器**才照得出來。)

> **LL349:紅燈的細節句不准把比較符號寫死。**
> 一句在自己紅的時候還在說「112 > 300」的話,會讓看的人往錯的方向找一輪。
