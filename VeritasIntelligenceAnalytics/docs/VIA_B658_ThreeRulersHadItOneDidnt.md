### 一半同等重要:豁免只擋「修」,不擋「掃」

## 順手抓到的第二個洞:哨兵抓到了,卻沒有下一步

乾跑的 `applied_by_class` 只有 `{"ACCEL": 22}`。**`VERB 8` 一件都沒進計畫,`skipped` 也是空的。**

追進去:VERB 修復器只認 `    args = parser.parse_args()` 一種寫法。
樹上最常見的 `main(argv=None)` + `X.parse_args(argv)` 落到 else 裡,
而那條 else **只在最內層 if 才 append 理由**,外層條件不成立就直接靜悄悄回去。

> 報表上永遠「有 8 件可修」,跑下去永遠「修了 0 件」。兩個數字各自都對,合起來是假的。→ **LL298**

補第二型 + 讓每條「不修」的路徑都講得出理由(L92)。形狀不在已知兩型 → 明講「請把這一型帶回引擎加形狀」,不在現場猜改。

## 第二回(同一輪,L93 先疑尺不疑樹)

`PINVER 24` 裡有幾件是判錯的紅燈?去量:尾版 glob 常常**寫成跨行**——

```python
CAND = (sorted(D.glob('CGC_MDL148_EngineBus_v*.py'))
        or [D / 'CGC_MDL148_EngineBus_v0100.py'])[-1]
```

那個 `_v0100` 是 glob 落空的**後備預設**,不是釘死版號。舊尺只看「同一行有沒有 glob」,跨行就看不到。
改看**同一個簡單陳述式**(Assign/Expr/Return…)裡有沒有 glob/newest;
**刻意不含 `def`/`if`/`for` 這種複合陳述式**——否則一個函式裡任何一處 glob 會讓整支函式免驗,那是把尺放寬,不是把尺修對。
自測 ㉓ 附反例:同一份夾具裡真的釘死那一行**仍然照報**。

`PINVER 24 → 22`。算它要 `ast.dump` 每個陳述式,全樹會多花 7s,所以**只在真有候選時才算一次**(13.5s → 13.7s)。
