## 二、新的是**規劃器**不是掃描器

掃描器樹上已經有(橋掃器、全景稽核、六域矩陣、格子)。缺的是把它們的結果

### 五件

**① 錯誤識別 —— 四類,不是一律叫「問題」**

| 類 | 意思 | 進修復波? |
|---|---|---|
| `REAL_GAP` | 真缺:該有的東西不在 | **是** |
| `RULER` | 尺的錯:判準把合法狀態判成缺 | 否(要改的是尺) |
| `NEED_DATA` | 缺料:料沒到位,不是壞掉 | 否(要補料) |
| `GATED` | 等閘:同意閘或操作員裁定 | 否(要人) |

> **把後三類混進「問題」裡,人會去修不該修的東西。**

**② 可同時 / 依序 —— 依「會不會碰到同一個檔」分波**

同一波內兩筆的**目標檔案集合必須不相交**。相交就排到後面的波 ——
兩個動作同時改同一個檔,誰後寫誰贏,而且沒人知道發生過。

分波是**保守**的:拿不準就排序列。並行做壞的代價比多跑一輪大。

**③ 九頭龍風險 —— 會長出第二顆頭的動作**

```
新建一支可能已有正主的件 · 把判準或名單複製到第二處 ·
第二扇門(L101 一個名字只能有一扇門) · 自備第二份判準
```

風險件**一律不進並行波**,要人看過才動。

**④ 不可傷害系統 —— 兩層**

```
禁動詞閘(出現即 BLOCK,不是警告):
  Stop-Process · Remove-Item · rm -rf · conda remove · pip uninstall ·
  push --force · --approve-remove · 改 .ps1
影響半徑:每筆標 blast(檔數)與 reversible(能不能一鍵還原)
```

而且**本支預設零動作** —— 它不執行任何修復,只印「誰先誰後、哪些可以一起」。
自測⑰ 從原始碼層咬:不准有 `unlink` / `rmtree` / `os.remove`,寫入只能落自己的報告夾。

**⑤ 一次一批 —— 輸出是波不是清單**

## 三、做這支的時候,我踩了三次同一個坑

### 第一次:自己寫了第二份排除清單

### 第二次:改成 AST 取靜態清單,還是漏 4 支

剩下 4 支住在 `VIA_CentralGovernanceFamily_b514/`。橋掃器的理由是:

```
雜湊冊凍結夾(VIA_CentralGovernanceFamily_b514/MANIFEST_b514.json)
```

**而「這個夾被雜湊冊凍結了」不在任何一張靜態表上** —— 它是 `_excluded()` 裡的一段分支。

→ **LL316:抄清單不算一個出處,抄到函式才算。
判準會長出靜態表看不到的分支,而那些分支通常正是「不該動」的那幾件。**

改成把橋掃器**整支載進來**、直接呼叫它的 `_excluded()`。5 → 4 → **0**。

### 第三次:負向測試連挑兩次「永遠成立」的例子

```
第一次:挑了一個不存在的檔       → 被判「未在冊(gitignored 產物)」
第二次:挑了本檔(還沒 commit)   → 一樣被判「未在冊」
```

兩次都不是判錯,是**我拿一個永遠成立的東西當負向例** —— 假綠的長相。
改用已入倉的檔。

## 四、順手修一句自相矛盾的話

批669 的存證新鮮度訊息印出來是:

```
**這份存證比現在的樹舊**(存證比 HEAD commit 早 0.0 天)
```

**斷言說它舊,括號裡說它不舊。** 根因是 gap 一律 round 到 1 位小數,同日全被壓成 0.0。

改成差距小就換單位(天 / 小時 / 分鐘),讓那個數字自己撐得住那句斷言。
自測改成咬 `"早 0.0" not in why`。
