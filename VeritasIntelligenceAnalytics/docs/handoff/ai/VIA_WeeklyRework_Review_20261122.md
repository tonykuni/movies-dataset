## 3. Fixes made in this batch (in #717; they take effect after merging)

1. **`.github/workflows/pr-guards.yml` + `.github/scripts/pr_guard.py`** (covers A and B; self-test 8/8)
   - Runs on every PR.
   - A program version (`.py` / `.ps1` / `.psm1`) inserted below the base's tail → **red**.
   - A book or document version inserted below the tail → **yellow** (reminder only).
   - The PR modifies or deletes a file that is success-locked (LF-normalized sha differs) → **red**. This enforces "to change it, issue a new version".
   - Tried on real branches: #690 gets 3 reds, #689 gets 1 red, #677 / #680 are green, and #717 gets 2 yellows (it holds book numbers that main skipped).
2. **`.github/scripts/codex_gate.py`** (covers A; self-test 8/8)
   - Puts a **"Codex 審查" (Codex review)** status on the PR's latest commit.
   - Green only when Codex reviewed exactly that commit, the review is completed, and there is no unresolved Codex thread.
   - Codex still running, or it reviewed an older commit → **yellow**, with the hint "comment `@codex review`".
   - An unresolved thread → **red**.
   - It reads only PR data and does not run any PR code.
   - It runs only once it is on the default branch, so it takes effect after this PR merges.
3. **This document** and the lessons ledger row LL-20261122-01.
