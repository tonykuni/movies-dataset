# 批631 · 同一棵樹,兩台機器,兩個答案 —— 先疑尺,而且「只比類別」就是一把會說謊的尺

## 操作員看到的
矩陣表格**中間被切斷**,插進去的是這兩行:

```
C:\...\SUP_MDL749_VRNFieldRuleHub_v0108.py:864: SyntaxWarning: invalid escape sequence '\d'
  (`00\d{3}` 五碼 → `00\d{2,4}` 四到六碼)。理由是量出來的:`0050` 四碼,
```

第二行不是我印的,是 **Python 把出問題的那一行原始碼也一起印出來**。
功能沒壞——壞的是畫面,而畫面是操作員唯一看得到的東西。

## 我第一次量錯了
容器掃全樹,**0 支**。差一點就回報「樹上沒有這種東西」。

根因不在樹,在我的尺:

| | py3.11(容器) | py3.12(工作站) |
|---|---|---|
| 不是 raw string 卻帶反斜線 | `DeprecationWarning`(**預設不印**) | `SyntaxWarning`(**印到終端**) |

我第一版**比的是類別**(`SyntaxWarning`),那在 3.11 上永遠是 0。
改成**只比訊息**(`"escape sequence" in str(msg)`)→ **6 支**。

> L93「跨機器判定不一致先疑尺不疑樹」這一次用在我自己身上。
> 更精確的教訓(LL229):**不要拿一個會隨版本改名的東西當判準。**

## 六支裡只有四支是活的
另外 2 支是**舊尾版尺算錯**的:MDL168 自己寫的尾版判準把「沒版號的 `X.py`」
當成**獨立一支**,於是 `X.py` 與 `X_v0102.py` 同時被算成活件。
實例:`VRN_ENG062_SummarizerV1.py` 旁邊就有 `_v0101` / `_v0102`。

**沒版號的那支是同族第 0 版,不是另一支引擎。**算成活件,掃出來的「債」裡
就混著早就退役的東西,修它是白工(LL230)。

## 閘第一跑抓到的是它自己
C 轉義道上線第一跑,全樹命中 **1 支——就是它自己**
(我把工作站那一行原始碼原封不動抄進函式說明,忘了把 docstring 設成 raw)。

這不是尷尬,是**這一道有效的證據**。一個掃不到自己的閘,
你無從知道它掃不到的還有什麼(LL231)。
反過來說:新閘第一跑就 0 命中的時候先別高興,
先確認它抓得到一個你**故意造的**壞件。
