## 六之二、我寫的檢自己壞掉了 —— 全格子當場抓到

`㊱ 同義字冊清完` 的第一版寫成:

```python

```

`_drop` 是「這一跑刪掉幾筆」。也就是說這一檢**要求冊裡還有陸券可刪**。

`--apply` 跑完之後冊已經乾淨,`_drop` 當然是 0 ——
**這一檢在它自己修好問題之後轉紅**。全格子第 215 站當場報 FAIL。

那不是尺,那是在量「樹現在髒不髒」,而且量出「乾淨」還判它錯。
檢要能**重複跑而結論不變**。改成兩段:

這一條值得記下來:**寫一個「修好之後自己就會紅」的檢,等於在系統裡埋一盞假紅燈**。

## 九、新法

**LL371 清除閘清完不等於清乾淨——要盯「又流進來」。**
一次性的清除做完就下站,只擋得住一次。清除閘的 `verify` 要**留在格子裡長跑**,
因為側枝收容、主線回帶、工作站塞件都會把清掉的東西再帶回活樹。
批679 收在 0,批702 量到 5,中間只隔了一次 `local/parallel-*` 收容。

**LL372 敘述裡不放會過期的斷言。**
站名、檢名這一類**不會紅**的文字,不准寫死一個會被下一批改掉的數字。
要嘛不寫數字,要嘛從資料自己算。第七次碰到同一族之後改的是**修法**不是**實例**:
把數字改對只能撐一批,把數字拿掉才是治。

**LL374 檢要冪等:修好之後還要綠。**
一條「只有在問題還在時才會綠」的檢,等於在系統裡埋一盞**假紅燈**——
問題修掉的那一刻它轉紅,下一個人會回頭去把修好的東西改壞。
要量尺就餵合成資料(髒的、乾淨的各一份),要量現況就只問「現在乾不乾淨」,
兩件事不准寫在同一個 `chk()` 裡。

**LL373 刪出來的懸空指標要逐條點名。**
清掉一個正典鍵之後,還指著它的每一處都要有名有理由。
若「補進名單」是操作員的裁定權,那就**維持點名待裁**——
既不擅自加名,也不讓它靜靜地懸在那裡。沒點名的懸空指標要讓檢紅。
