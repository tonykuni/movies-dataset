## 病根:進度走錯通道

v0108 用的是:

```powershell
Write-Progress -Activity "VIA ALL-IN-ONE" -Status "..."
```

`Write-Progress` 寫到 host 的**進度 UI 通道** —— 一旦輸出被導向、被管道接走、
或被複製成逐字稿,**它完全不存在**。

而你每次貼回來給我看的,正是那份逐字稿。所以第 13 步那 4,394 秒在你眼裡就是全黑。

更冤的是:格子從批423 起**每一站都在寫** `SELFTEST_PROGRESS.json` 心跳
(done / total / ok / fail / eta / heartbeat),**只是從來沒有人去讀它**。


- **TTY**:`\r` 就地重畫,每 1 秒
- **非 TTY**(你的逐字稿):每 30 秒印一行 —— 看得出還活著,又不洗版
- 內容:總進度條 + 百分比 · 步 N/15 · 本步已跑/逾時預算 · **內層 done/total + % + OK/FAIL + ETA**
- **不卡斷**:讀不到心跳就跳過,絕不阻塞主迴圈

## 三條自審(都是我這一批自己造的)

### (a) 總條停在 0% 而內層已經 57%

第一版總進度只算「跑完幾步」。於是畫面是:

```
[....................]   0%  步 1/15 ...  ·  內層 144/252(57%)
```

**讀起來仍然像沒動 —— 跟原本的問題一模一樣。**
改成把本步的內層比例併進總條;沒有心跳時用時間粗估,並**封頂 0.9**(不假裝快做完)。

### (b) 心跳「很新」不等於「是本步寫的」(LL179 第三次)

實測:上一跑剛結束的 `252/252` 心跳只有幾秒大,於是本步一開跑就顯示 **100%**。

判準改成**這一步開始之後才寫的**才算數 —— **時間新不代表出處對**。
這已經是同一族的第三次(LL133 判定器不自判 · LL179 讀自己的空輸出 · 這次讀上一跑的輸出)。

### (c) PowerShell 沒有 docstring(LL182)

我把 Python 習慣帶進 `.ps1`:

```powershell
function Get-InnerHeartbeat {
    """長步驟的內層進度..."""      # ← 這不是註解
```

PowerShell 裡那是一個**字串運算式**,值會被送進管線 ——
函式回傳變成 `[字串, 物件]` 兩個東西。

**AST 檢查一路綠燈**,因為它語法上完全合法。這類錯誤只有真的呼叫一次才看得見。

## 怎麼跑

