## 六、新律

**LL387 既有債可以背,新增的債不可以悄悄地背。**
一批量出來的缺陷,如果沒有能力或沒有權限當場修完,
**正確的動作不是把它藏進一個模糊的欄位,也不是硬修**,
而是把它**釘成基線**,並且讓**基線外的同類當場變紅**。
沒有基線,那一欄會越長越長,而且每一支新的都看起來像舊的。

**LL388 棘輪的基線必須是實跑量出來的,而且要有一條檢釘住這件事。**
手寫的基線會悄悄多出一行——多出來的那一行是一張**永遠用不到的免死金牌**,
因為它指向的家族根本不存在,沒有任何一次跑會碰到它,所以沒有任何一次跑會說它有問題。
檢 ㉔ 就是釘這件事:基線裡的每一支都要在主名單裡。

**LL389 用字面判缺陷會喊狼;缺陷要釘在量出來的行為上。**
「檔案裡提到 `C:\Users\...`」在受治理面上有 84 支,
「import 期真的去讀寫它」只有 22 支。差了 62 支。
**一把對 62 支喊狼的尺,跑三次就沒有人看它了**——那比沒有尺更糟(LL272 同族)。

**LL390 尺自己要先量得準。**
我量「字面帶倉外路徑」的第一版 regex 是 `[A-Za-z]:[\\/]`,
它把 `https://` 的 `s:/`、字串裡的 `e:\n` 全算進來,全樹喊出 1677 支。
**在用一把尺去判別人之前,先讓它量幾個你已經知道答案的東西。**

**LL391 只檢比值的檢,照不出「分子分母一起錯」的尺。**
`read` 的省下百分比在錯尺與對尺之下分別是 95.0% 與 94.9% —— **幾乎一樣**,
因為原檔與骨架卡的 CJK 佔比相近,偏誤同向抵消。
**尺的檢要釘絕對值**,而且要拿舊尺當負控:舊尺跑同一條斷言必須當場破。

**LL392 儀器要省的,是你真的在花的那一項。**
`read`/`slice` 省的是「讀原始碼」;而我這條迴圈量下去,大宗是「**讀跑測日誌**」
(一跑 ≈ 三萬 token)。**優化要對著量出來的花費走,不是對著直覺走。**
更重要的是:那份日誌我土法 `grep` **會讀錯**——省 token 是其次,**不被自己的尺誤導**才是主因。

**LL393 跨分支撞號:兩邊各自都是綠的,合起來是壞的。**
兩條分支同時開 `_v0460`、同時叫「批707」,各自自測綠、各自全格子綠。
**同名不同容的 `add/add` 衝突,不會出現在任何一條分支的自測裡**
——因為在每條分支上那個檔名都只有一份。
併法:**先併進 main 的保留號與檔名**,後到的改號,並把改動**搬到下一個尾版**(只增不減)。

**LL394 摘要不准把「既不綠也不紅」壓成綠或紅。**
`LOCKED`/`TIMEOUT` 壓成綠是假綠,壓成紅是假紅。摘要的誠實作法是**不下綠紅判**、
逐站點名要人去看。而這一態也要有負控:乾淨的那一份必須**仍然是綠**

## 八、自測攻:我拿它自己的尺去量它,量出兩個缺陷

操作員令是「**替你執行自測攻並優化他**」,所以不是拿來用就算,是要**打它**。

**攻①～③ 沒事**:語法壞檔誠實報 `SYNTAX`、找不到的檔誠實報 `ABSENT`、
`slice` 取方法取得到。它自己的自測 33 檢 OK 33。

**攻④ 打中了:那把 token 尺自己是錯的。**

```
CGC_MDL147_v0103   字元 35633 · CJK 5956(16%)
  舊尺(一律 4 字元/token)      8908
  CJK 感知(ascii/4 + cjk/1)   13375     ← 少報 33%
```

CJK 在主流 BPE 分詞器上約 **1 字元 1 token**,`// 4` 對中文差了四倍。
**為什麼這個缺陷活到現在**:`read` 印的是**省下的百分比**,
而原檔與骨架卡的 CJK 佔比相近(都 16%),**分子分母一起偏低,比值幾乎不動**
——95.0% vs 94.9%。**一條只檢比值的檢,永遠照不出這個缺陷。**
所以檢 ㉛ 釘的是**絕對值**:100 個中文字必須算 100 token、100 個英文字元算 25,
**負控**=舊尺拿來跑同一條斷言必須當場破。

**攻⑤ 打中了第二個:它省的是讀原始碼,而我這條迴圈真正的大宗是讀跑測日誌。**

全格子一跑 108 KB ≈ **三萬 token**。而且我土法 `grep '\[FAIL\]'` **會被帶錯** ——
批707 實錄:我 grep 到 **1 行 FAIL**,總表卻寫 **FAIL 0**,多花兩次工具呼叫
才查出那一站是**平行敗→序跑轉綠**。**省 token 是其次,不被自己的 grep 誤導才是主因。**

新動詞 `digest`(同一個正主,不開第二支;Zero-Hydra):

- 只認**行首第一個**中括號 —— 站列是「`[OK  ] 站名 · 秒 · 站自己的輸出`」,
  而站自己的輸出裡常常也有 `[FAIL] ③ …`。**嵌在後面的不是站的判決。**
- 同一站出現多列**以最後一列為準**;轉綠的**自成一態並且照列**
  ——不列=把紅洗掉,列成 FAIL=假紅,**兩個都不行**。
- `LOCKED`/`TIMEOUT` 既不綠也不紅 → **MIXED,本摘不下綠紅判**(rc5)。
- 沒有 `[計]` 總表行 = 截斷或還在跑 → **NODATA,不編一個總表出來**。

實測拿它讀批707 那份真日誌:

```
[摘] GREEN · 站列 325 · 真 FAIL 0 · 平行敗→序跑轉綠 1 · SKIP 5 · 其他態 0
  [轉綠(不算紅,但照列)] 測試結果總表六檢(批257) · 2 次;末列 OK
[token 帳] 日誌≈30634 · 摘要≈371 · 省 98.8%
```

**它一行就講出了我上一批花兩次工具呼叫才查出來的事。**

**自審留痕:我自己在新碼裡把剛修好的錯尺又犯了一次。**
`render_digest` 第一版我寫 `_tok(0, "x" * chars)` ——
用一串 **ASCII 的 x** 去代表一份**中文滿天飛**的日誌。已改成帶日誌自己的 CJK 佔比算。

**自審②:MIXED 那一態是打出來的,不是設計出來的。**
v0106 第一版我寫 `RED if fails else GREEN`,於是一份末列是 `LOCKED` 的日誌**被判 GREEN**。
那是假綠。檢 ㉞ 釘住它,**負控**=全是 OK/誠實 SKIP 的那一份必須**仍然是 GREEN**
(否則就是把閘調成「永遠不綠」,那跟永遠綠一樣沒有判斷力)。
