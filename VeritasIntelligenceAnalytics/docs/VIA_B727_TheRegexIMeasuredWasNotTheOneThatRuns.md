## 二、動手前先問一句:這條式子有人跑嗎

批725 剛用 LL428 教過我一次——grep 撈到的檔不是尾版,我改了一支沒人載的檔,還以為修好了。
所以這次在改之前,我先追了一遍**誰讀這條 `rating.cue_rx`**。

追下去是這樣:

- `SUP_MDL749_VRNFieldRuleHub`(樞紐)的 `rating_of()` → 轉交 `matchers()`
- `matchers()` → 惰性載入 `VRN_ENG086_FirstPageLogicBridge` 的**尾版**,拿它的函式本體
- `rating_of()` 實際呼叫的是 `rating_local_scale` / `rating_quoted` / `rating_from_title` / `safe_rating`

然後我去 ENG086 裡找這四支用的詞表:

```
208:_RATING_CUE = re.compile(
209:    r"(投資評等|評等|評級|建議|Rating|Recommendation|Rec\.)[^\n]{0,8}?[:：]?\s*"
210:    r"(強力買進|買進|…|Underweight|Reduce)", re.I)
```

**`re.I` 本來就在。** 而且 `Rating` 是子字串比對,`Stock Rating` / `12-month rating` 裡都含 `Rating`。

也就是說:批726 那次量測,量的是**冊上那一份抄本**,不是引擎真的在跑的那一份。
冊上那份沒有 `re.I`(旗標不在字串裡,編譯的人才決定),所以量出一排「沒中」——
而那排紅燈掛在一條沒人走的路上。

## 三、真的缺口在哪:目標價,而且不是大小寫

1. **標籤與數字之間的括號修飾語**把強線索整條打斷。舊式只容 `[:：]` 與空白;
   `Price Target (Dec-25):` 一來就對不上。
2. **幣別前綴只認 NT / NTD / TWD**。外資英文研報寫 `US$` `HK$` 是常態,全沒中。

還有一件更不好看的:`Price Target (Dec-25): NT$250` 那格,v0113–v0115 **看起來有中**,
但 `how` 是「收容件 NT$ 正則(弱)」——強線索斷掉後退到弱正則撈到的。
弱正則**不綁標籤**,它只是在全文找 `NT$` 後面的數字。所以同樣的版面換成沒有 `NT$` 的
`Target Price (12M): 250`,就整個沒中。**那一格的綠燈,是靠一條不看標籤的式子碰巧撈到的。**

三版同為 3/7,代表 PR #75 帶進來的 v0114 / v0115 從來沒碰過這條路。

## 六之四、批727b:Codex 在 PR #94 上抓到我放寬出來的洞(P1,複驗屬實)

只擋 `%` 是擋現象不是擋根因。

追下去根因有兩層,第二層是**本來就在、被我放寬才照出來的舊洞**:

1. 括號插進標籤與數字之間以後,幅度詞被推出「數字前後 26 字」那個視窗,守衛看不到。
2. 更糟的是 `_UPSIDE_RX` 的詞表是 `(潛在)?上漲空間|上檔空間|upside` ——
   而 **`Up/downside` 這個字裡根本沒有 `upside` 這個子字串**(`U-p-/-d-o-w-n-s-i-d-e`)。
   也就是說 downside 那一整類,**這道守衛從上線以來一次都沒攔過**。
   只是舊式子要求標籤後面緊接數字,幅度欄本來就進不來,洞一直沒被踩到。

修在守衛那一處,不另開第二道:
- 括號修飾語不准含 `%` / `％`(單位不是修飾語);
- `_UPSIDE_RX` 補 `下跌空間` / `up\s*/?\s*downside` / `downside`;
- `_is_upside_context` 除了數字周邊,**線索詞之前也看一次**(同一支函式呼叫兩次,不是兩套判準)。

## 七、教訓

**LL432:量之前,先確認量的是不是活路徑。**
冊上的式子和引擎跑的式子可能是逐字相同的雙胞胎,但旗標(`re.I`)不在字串裡、
讀冊的那支可能根本不是跑的那支。我在批726 量到一排紅燈,
紅燈是真的,只是掛在一條沒人走的路上——照它動手,就會往一個沒壞的地方補一顆新的頭。
追一次「誰讀這個值」的成本,遠低於種一顆第二顆頭的成本。

附帶兩條老教訓又各咬了一口:
- **LL421**(診斷印在沒人走的路上)換了個樣子:常數整塊重複,只改第一份等於沒改。
- **LL428**(動任何一支之前先看尾版)這次是**反過來**救了我:先追尾版,才發現冊與引擎是兩個東西。

**LL433:放寬一條式子的時候,要同時問「既有的守衛擋得住放寬後的新形狀嗎」。**
這次的答案是不但擋不住,而且那道守衛連它原本就該擋的 `downside` 都從來沒擋過——
**放寬不是製造了這個洞,是把一個一直都在的洞照了出來。**
自動審查報上來的東西要當 bug report 實測複驗:Codex 這條是對的,
但它給的修法(擋 `%`)只蓋住現象,不擋根因;採信結論、自己追根因,兩件事都要做。
