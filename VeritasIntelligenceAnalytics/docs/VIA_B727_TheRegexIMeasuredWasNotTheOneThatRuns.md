## 二、動手前先問一句:這條式子有人跑嗎

## 六之六、批727d:第三輪又兩條 —— 我一直在補視窗,那本身就是根因

第三輪(我主動請的)又回兩條 P1,而且**正好命中我自己列的那兩個方向**:

| 探針 | v0115 | 727c | 727d |
|---|---|---|---|
| `Price Target (12M): 25\n   %` | `None` | `25.0` | `None` |
| `Downside (%) to Price Target (12M): 38` | `None` | `38.0` | `None` |

第一式:`%` 被換行加縮排推到第 5 個字元,落在我那個固定 4 字元切片之外。
第二式:`(%)` 出現在**線索詞之前**(欄位標題 `Downside (%) to ...`),
而我的 `downside\s+(?:to|vs)` 要求 `downside` 後面緊接 `to`,中間插了 `(%)` 就不中。

三輪下來的形狀已經很清楚:**我一直在補「視窗」,而視窗本身就是根因。**
用固定寬度的字元切片去判「這個數字是價還是幅度」,永遠有下一個邊緣形狀。
所以這一輪改判準,不再補視窗——兩條**確定性**規則:

- **規則 A**:數字之後跳過任意版面空白就是 `%` → 這個數字本身是幅度。
  (`[ \t\r\n\u3000]*[%％]`,不再是「後面 4 個字元」。)
- **規則 B**:同一行的標籤區出現 `(%)` 這種**欄位單位標記** → 整欄是百分比欄。

規則 B 有個關鍵的收斂:**只認獨立的 `(%)`,不認行內的 `15%`**。
我原本想寫成「標籤區出現任何 `%` 就擋」,自己先拿反例測了一下:

```
Revenue +15%, Target Price: 250      ← 一行同時有幅度與價
Target Price: 250 (+15%)
目標價 250(上漲空間 15%)
```

三式都會被那個寫法誤殺。`(%)` 是**欄位單位**,`15%` 是**值**——判準要分得出這兩件事。
這三式已經以正控入自測。

結果:負控 **28/28**(含三輪全部 findings)· 正控 **18/18** ·
自測 67 → **75 檢 OK 75** · 64 份語料仍完全相同。

## 七、教訓

**LL432:量之前,先確認量的是不是活路徑。**
冊上的式子和引擎跑的式子可能是逐字相同的雙胞胎,但旗標(`re.I`)不在字串裡、
讀冊的那支可能根本不是跑的那支。我在批726 量到一排紅燈,
紅燈是真的,只是掛在一條沒人走的路上——照它動手,就會往一個沒壞的地方補一顆新的頭。
追一次「誰讀這個值」的成本,遠低於種一顆第二顆頭的成本。

附帶兩條老教訓又各咬了一口:
- **LL421**(診斷印在沒人走的路上)換了個樣子:常數整塊重複,只改第一份等於沒改。
- **LL428**(動任何一支之前先看尾版)這次是**反過來**救了我:先追尾版,才發現冊與引擎是兩個東西。

**LL433:放寬一條式子的時候,要同時問「既有的守衛擋得住放寬後的新形狀嗎」。**
這次的答案是不但擋不住,而且那道守衛連它原本就該擋的 `downside` 都從來沒擋過——
**放寬不是製造了這個洞,是把一個一直都在的洞照了出來。**
自動審查報上來的東西要當 bug report 實測複驗:Codex 這條是對的,
但它給的修法(擋 `%`)只蓋住現象,不擋根因;採信結論、自己追根因,兩件事都要做。

**LL434:自動審查值得主動再請一次,而且要問對問題。**
Codex 只在開 PR 時審,修補本身沒人看過——是我主動 `@codex review` 才叫出第二輪,
而第二輪抓到的 P1 比第一輪那條更深:它指出的 `seg[span:span+4]` 位移錯誤,
讓那道「數字後面帶 %」的守衛**從上線以來在短文裡一次都沒生效過**(v0115 也錯)。
兩輪合起來的形狀是一樣的:**我放寬的地方,旁邊的守衛本來就是壞的或不夠的**;
放寬把它們一個一個照出來。修守衛的時候也要記得反方向驗一次——
P2 就是我把守衛收得太緊,反過來誤殺了 v0115 本來抓得到的正當命中。

**LL435:同一個地方被連續指出三次,問題就不在那三個洞,而在判準的形狀。**
前兩輪我修的是「補一個詞」「補一個偏移」,第三輪還是被找到兩個新形狀——
那時候該停下來問的不是「還有哪個形狀沒補」,而是**「為什麼永遠補不完」**。

三輪所有 findings 一次全滅,而且我自己先用反例把規則 B 從「任何 %」收斂到「獨立 `(%)`」——
**加嚴的時候要同時拿「不該被擋的」去測**,否則就是下一輪的 P2。
