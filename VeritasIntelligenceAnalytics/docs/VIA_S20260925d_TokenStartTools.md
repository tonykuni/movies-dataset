## 啟動項

尾版 `CGC_MDL158_VIAPanoramaAuditRepair_v0106.py`。短令仍是 `via-panorama`，不寫死版號。

| 啟動 | 做什麼 | 不做什麼 |
| --- | --- | --- |
| `via-panorama read <檔或夾>` | 骨架卡：匯入、定義樹、行號、AST 五類 | 不把原檔貼進對話 |
| `via-panorama slice <檔> <定義名>` | 只回那一個定義，向下一層 | 不把整支讀完 |
| `via-panorama digest <跑測日誌>` | 只留判決行。同一站以最後一列為準 | 不 grep 整份日誌 |

AST 五類就在 `read` 裡，不另開五支：`DUPDEF` · `UNREACH` · `BAREEXC` · `SWALLOW` · `MUTDEF`。PowerShell 另兩類 `PSDUPFN` · `PSDOCSTR`，不算進這五類。

批708 實測：日誌 30634 token → `digest` 371 token。骨架卡對單檔約省 95%。尺要用 v0106 的 CJK 感知算法，不用 `字元數 // 4`。

## 互動回饋

工具回一張卡。AI 只回三件事：卡上的數、五類點名、下一步一個動詞。不把原文件貼回來。

| 動詞 | 工具回給 AI | AI 必須回 | 下一步只准 |
| --- | --- | --- | --- |
| read | 路徑、行數、說明、匯入、定義樹（行號、種類、簽章、首行）、問題標成報／修／免、token 帳 | 問題幾條；五類點名哪幾個定義；省了多少 | 要看內文 → `slice` 那個定義。沒問題 → 停。骨架卡比原檔大 → 這次不啟動 |
| slice | 行範圍、該段原文（含裝飾器）、同名幾個、原檔 token 與這一段 token | 同名多個要逐個說；這一段占原檔多少 | 還要別的定義 → 再 `slice` 一個名字。不整檔重讀 |
| digest | GREEN／RED／MIXED／NODATA、總表行、真 FAIL、轉綠、SKIP、其他態 | 先報狀態。真 FAIL 與轉綠分開。LOCKED、TIMEOUT 不下綠紅判 | 真 FAIL 才對那一站 `read`。摘要比日誌大 → 不啟動 |

沒有 `[計]` 總表行 = NODATA，不編一個結論。問題標免的不當成要修的。

## 這次實測

用倉上 v0106 的副本直接跑，不是預覽裡另寫的讀檔器。

自測 37 檢：OK 29 · FAIL 8。失敗的那 8 項是已修冊、CGC_MDL156、活樹不在這份副本旁邊。省 TOKEN 本體這幾項是過的：讀完不執行被讀的檔、slice 只回一個定義且同名兩個都列、CJK 尺、digest 轉綠照列、只認行首第一個括號、沒有總表就是 NODATA、LOCKED 不判綠。

再拿 13 行小樣與 5 行日誌跑三個動詞：

| 動詞 | 結果 |
| --- | --- |
| read | 抓到 SWALLOW、DUPDEF。原檔約 40 token，骨架卡約 101，省 −152.5% |
| slice drop | 同名兩段都列出來。整檔約 40，片段約 36 |
