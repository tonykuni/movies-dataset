## 一、三態冊,這一批拿到了它的實證

批720 立冊的時候,我把自己推出來的路徑標成 `CANDIDATE` 而不是直接寫成事實。
當時寫的理由是:

> 編一個看起來像樣的網址出來,探針會去打它、然後回報「失敗」——
> 而看的人第一個念頭會是「**交易所那邊壞了**」。

一天之後,帳結出來了:

| 我推的 | 結果 | |
|---|---|---|
| `MI_MARGN`(融資融券) | **VERIFIED** 1,297 列 | 推對了 |
| `TWTB4U`(當沖) | **VERIFIED** 1,233 列 | 推對了 |
| `FMTQIK`(市場成交) | **VERIFIED** 16 列 | 推對了 |
| `T86`(三大法人) | **DEAD** 0 列 | **推錯了** |

**四分之三準,四分之一錯。** 如果批720 我把這四條全寫成 `VERIFIED`,
那一條錯的會在冊上躺著,直到某天有人拿它去接管線、然後花半天查「為什麼交易所不給料」。

> **推錯不丟臉。推錯又寫成事實才丟臉。**

## 二、被打掉的那一道,不刪也不留在 CANDIDATE

`T86` 回的不是 JSON(`Expecting value: line 1 column 1` = 空的或 HTML)。
處置寫進冊,三件一起:

| 欄 | 內容 |
|---|---|
| `state` | `DEAD` —— 不是刪掉,也不是留在 CANDIDATE |
| `probe_error` | 回的到底是什麼(原文錯訊) |
| `evidence` | 誰在哪一天打掉的 |
| `path` | **原路徑原樣留著** |
| `next_candidates` | 補兩條:`BFI82U`(市場合計)· `T86` 帶 `?date=` 參數 |

原路徑留著是因為:刪掉之後,下一個人會把同一條路再推一次、再打一次、再敗一次。
**一條死路的價值,在於它被記成死路。**

`next_candidates` 是**負控**:DEAD 如果不補下一批候選,這道就永遠停在死路上 ——
看起來像「已處理」,其實是「放棄了但沒人講」。檢 ⑨ 釘住這一條。

探針下一跑會自動把那兩條 alt 打進去(`institutional#alt`)。

## 四、順手記一筆:那些警告不是引擎發的

實錄裡每一道探針前面都有一段:

```
urllib3 ... InsecureRequestWarning: Unverified HTTPS request is being made to host '127.0.0.1'
```

那是工作站的流量走**本機 127.0.0.1 代理**、而該代理的憑證沒被驗證。
不影響探針判讀,但值得記下來 —— 因為紅字很多的時候,
人會把**不是自己發的警告**算到自己頭上。

## 五、這一批的律

**LL426 推出來的路徑要標成「推的」,而且要有一個會去打它的東西。**
三態冊不是形式:`CANDIDATE` 是一張欠條,`probe` 是去把它兌現或撕掉的那隻手。
沒有探針的 CANDIDATE,和直接寫成事實沒有差別 —— 只是把謊話延後。

**LL427 死路要記成死路,而且要補下一條。**
刪掉 → 下一個人把同一條路再推一次。
留在 CANDIDATE → 它看起來還有希望。
記成 DEAD 但不補候選 → 看起來像處理完了,其實是放棄了沒人講。

## 七、批722 — 分開擷取後整合(操作員令)

操作員裁定:**「一擬建議執行 可分開擷取後整合」**。

`run` 動詞落地,兩段分得很開:

### 分開擷取 —— 一道敗不中止其他道

每一道各自回自己的態,互不牽連。負控用一個**會在融資券那道炸掉**的假網路工具餵進去:
那一道 FAIL,**其餘每一道照樣拿到料**。

> 整跑被一道拖死,「可分開擷取」這條令就沒落地 ——
> 所以那一檢餵的不是好料,是**一顆炸彈**。

### 再整合 —— 逐欄講明出處,四種分得開

| 出處 | 欄 |
|---|---|
| `EXCHANGE` 交易所直接給 | 開高低收 · 成交量 · 成交值 · 成交筆數 · 融資券 · 當沖 |
| `YAHOO` | adj 四價(+ `adj_method` 記明是 auto_adjust 還是比例法) |
| **`DERIVED` 算出來的** | 市值 = 收盤價 × 發行股數 |
| **`NOT_WIRED` 還沒接上** | 三大法人 |

紅線寫在程式裡,不只在文件裡:

> **`0` 是「今天沒人買賣」,`NOT_WIRED` 是「我還沒接上」。**
> 把後者寫成前者,下游會拿一整排真實的零去算比率。
