## 你的新令:目標價過了除權息要改 ADJ CLOSE

> 有目標價過了除權息都要改成 ADJ CLOSE,跟目前的 ADJ CLOSE 更新計算目標價

量過之後 —— **這條既有實作已經成立**,不用改邏輯:

| 步 | 實作 |
|---|---|
| 因子 | `adj_close / close` |
| 因子鏈 | `f = 報告日因子 ÷ 最新日因子` |
| 除權息事件日 | 由**因子變動**偵測(母倉無配息事件表) |
| 調整後目標價 | `tp_adj = tp × f` |
| 上漲空間 | `(tp_adj − adj_close) / adj_close` |
| 紅線 | **永不拿 close 頂替 adj_close** |

而且我量了 adj 基準夠不夠「目前」:

> **價表 892 檔,最新日因子全部 = 1**(最新日 2026-09-18)。
> 沒有一檔是混抓時點的。

所以這一批做的不是改邏輯,是**把它釘成 L99 + 加一道檢㉗**,免得以後被人改掉。

**但瓶頸不在口徑。** 46 份裡只有 5 份有價,所以只有 4 份走得到因子鏈 ——

## 第二個真缺陷:41 份的調整態是空字串

`price_context` 在「票不在價表」和「價表無 adj_close」兩個出口**直接 return,沒帶態**,
落庫就是 `''`。容器 46 份裡 **41 份**是這樣。

而 `''` 跟 `NONE`(有價、查過、確認期間無除權息)**意思完全相反**,在庫裡卻都篩不出來:
`WHERE adjust_method = 'NONE'` 抓不到,`WHERE adjust_method <> ''` 也抓不到。

補三個誠實態後實測:

> **態不夠用的時候,缺口不會報錯,它會安靜地借一個空值站著。** → **LL271**

理由:產業/晨報/研討會/海外這四型**確實會寫個股的目標價與評等**,常常一次好幾檔。
問題出在 `vrn_report_basic` 這三欄是**單值欄** —— 一份涵蓋五檔的產業報告塞不進一個 `target_price`。

**判 N/A 等於把「我們的欄位裝不下」說成「報告裡本來就沒有」。**
正確的補法是 per-stock 子表(一報告 N 檔),不是改判態 —— **欄位形狀的問題不用燈號解**。

方向一律選不藏缺料的那一邊。兩筆都標 `AI_DECIDED_批643_REVISABLE`,你隨時可以推翻。

## 順手修掉一個連兩批的假警報

批642、批643 兩次全格子,唯一的紅都是同一站:

```
[FAIL] VRN 索引冊守門 · 冊寫 …_v0107.py · 樹上尾版 …_v0108.py
```

根因在**次序**:LL191 定的是 `registry-sync → 全格子 → via-vrnbook build`,
而**索引冊是「樹的索引」,不是「格子的產物」**。
只要這一批動過任何引擎版號,冊在跑格子的當下就一定是舊的 —— 每次都得跑第二次格子(一次 250 秒),
而且第一次的紅是**可預期的假警報**。假警報跑久了,就沒有人看紅燈了。

次序改成:`registry-sync → **via-vrnbook build** → 全格子 → via-regen --apply → commit`。→ **LL272**
