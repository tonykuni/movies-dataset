## 一 · 一句話

v0103 有四個地方會把「還沒抓齊」當成「齊了」:
- 空列表、或認不出的回應;
- 一個端點成功就算整個市場成功;
- 資料只少了幾項;
- 期限當天抓的。

v0104 把這四個都改成「還缺、下次照抓」,而且只有全部抓齊才回 rc0。

## 二 · 四條逐條

| # | Codex 說的 | 實量 | v0104 怎麼改 |
|---|---|---|---|
| 1 | 空列表、或欄名變了一項都解不出的回應,被記成 OK、0 項 → 判齊,要等下一季才重抓 | 屬實 | 先量真的空業別長什麼樣:TPEX 8 個空業別端點都回一列,只有「出表日期」有值。v0104 分三種:只有佔位列 = 空業別 OK;空列表 = `EMPTY`;有值卻一項都解不出 = `UNPARSED`。後兩種不算抓成功、下次照抓;解析例外記 `ERROR`、也不算 |
| 2 | 一個端點成功、其餘逾時,整個市場標 OK、rc0 | 屬實 | 抓完用同一套判準(`mops_plan`)重算還缺什麼:全齊才 rc0;還缺 → rc2,有東西到位時標 PARTIAL,並印 `[仍缺]`。PARTIAL → rc2 與 VDF_ENG057 · ENG078 同慣例(v0103 的 PARTIAL rc0 是我定錯) |
| 3 | 那一批只少了幾項(不是全刪),認不出 | 屬實 | 台帳多記「寫入後表裡實存項數」`n_stored`,計畫拿現有項數比,少了就重抓。比的是實存、不是解析項數,所以別的端點先寫過的同鍵(實存 0 項)不會被當成少了 |
| 4 | 期限當天抓的被當成已齊,可是期限當天還能申報 | 屬實 | 「該齊的那一季」要等期限整天過完;期限當天或之前抓的都照抓(8/14 抓的:8/14 當天判齊,8/15 照抓) |

**同類再補兩條(不是 Codex 提的)**:
- **平常有資料的端點,偶爾只回佔位列**:例如一般業這種平常有資料的端點。規則是「上次 0 項、前一次卻有項目」→ 再抓一次確認,連兩次 0 項才算真的空了。業別真的清空時,確認一次就停,不會一直重抓。
- **升級相容**:寫這份文件時自己抓到的。v0103 已經併進 main,如果你已經在工作站用 v0103 跑過 `--mops`,台帳就沒有 `n_stored` 欄,而 v0104 的計畫第一步就讀這一欄,會直接崩。
  v0104 先看台帳有哪些欄,舊台帳把 `n_stored` 當空的讀;寫台帳時正典 `upsert_rows` 照型別補欄。
  實測:同一份真庫副本先用 v0103 跑,再用 v0104 跑 → TPEX 判齊、零請求,台帳補上 `n_stored`。
- **同一批裡同鍵重複**:改壞測試量到,正典 `upsert_rows` 照 v0110 語意不替來源去重。一批裡同鍵兩列會兩列都進表(實量:2 列 → 表裡 2 列);交易所回應要是有重複列,長表就會有重複鍵。v0104 寫入前同一批同鍵只留第一筆,台帳備註寫「同一批重複 N 項只留第一筆」。真資料量過:0 重複。
