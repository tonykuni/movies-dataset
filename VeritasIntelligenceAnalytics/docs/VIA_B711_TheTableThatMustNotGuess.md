## 二、中央治理引擎:釘的是**它的判斷力**,不是它跑得動

2093 行的字彙治理引擎,下游所有的同義字查表都靠它。七檢,每檢帶控:

| 檢 | 釘住什麼 | 控 |
|---|---|---|
| ① `norm` 地基 | 全形→半形 · 大小寫壓平 · `_`/`-`/連續空白收斂 | **負控**:兩個本來不同的詞,正規化後**不可以**變同一個 |
| ② `variants` | 拉丁詞衍生確定式變體 | **中文單詞只回它自己** |
| ③ 台股代號 | 4–5 碼(含 B/A/D 末碼)→ `.TW`/`.TWO`/`TT` 三式 | **負控**:`abc` 不是代號,必須回空 |
| ④ `match_score` | 同字 1.0 · 無關 0.0 | **成對檢**(只檢一邊,永遠回 1.0 或永遠回 0.0 都會過) |
| ⑤ 只增不減 | cid 冪等 · 同義字 append-only | **正控**:第一次必須回 True |
| ⑥ `synth_regex` | 寫回 `regex` 欄 · 每條**真的編得過** · 長者優先 | **負控**:全空要回空清單,不准硬造 |
| ⑦ `build_lookup` | 命中回 cid · **查無回 None** | — |

**②和⑦是這一批的重點,兩條都是「不准猜」:**

- `variants("台積電")` 只回 `{台積電}`。字彙表一旦開始猜,
  就會長出**沒有人裁定過的同義字**,而且沒人知道是誰加的。
- `build_lookup` 查無回 `None`,不回「最像的那一個」。
  **猜出來的對應,下游看不出來它是猜的** —— 那比查不到更危險。

這兩條不是「功能」,是**刻意保留的空白**。而刻意的空白最容易在下一次「優化」時被填掉,
所以要有一條檢站在那裡。

## 三、Mega 引擎:缺了正本卻亮綠燈,比沒有燈更糟

```python
def light(r):
    reds = len(r["py_errors"]); yellows = len(r["findings"]) + len(r["hydra"])
    missing = sum(1 for x in r["ssot"] if not x["present"])
    if reds or missing: return "RED"
    return "YELLOW" if yellows else "GREEN"
```

檢 ③ 釘住 **SSOT 缺件必須 RED**,並帶**負控**:全部乾淨的那一份必須真的是 GREEN
(只檢「缺件會紅」的話,一個永遠回 RED 的燈也會過)。
檢 ④ 釘住 `findings`/`hydra` 是 **YELLOW** —— 既不綠也不紅,壓成哪一邊都會讓人做錯事。

另外釘住一個容易被「順手修好」的現況:`zone_of` 的副檔名參數**不帶點**
(`"psm1"` 命中、`".psm1"` 不命中)。不改,但釘住 —— 哪天有人改成帶點,這條會亮。

## 五、新律

**LL401 刻意的空白要有一條檢站在那裡。**
「查無回 None 不猜」「中文單詞不衍生變體」這種**刻意保留的不作為**,
在碼上看起來就像「還沒做」—— 下一個人很容易順手把它「補完」。
補完的那一刻,系統開始產生沒有人裁定過的資料,而且**下游看不出來那是猜的**。
所以不作為也要有檢:它不是在測功能,是在**擋住一次善意的優化**。
