## 所以本批只做那一條接線

- **矩陣與頁殼改由 MDL173 供給**(`page_html` + `html_table`)—— 一份 CSS,不長第三份。MDL173 自己的 docstring 說得最清楚:「四支落頁引擎各帶一份 CSS…規格散在四處就不是規格」。

## 自審實錄:我在下一批就踩了上一批的律

第一版把站的態直接丟進 SPEC 的燈色,結果 **294 站只有 9 格上了色**。

根因是**兩套字彙**:

| 誰 | 說的話 |
|---|---|
| 格子 | `OK` / `FAIL` / `SKIP` / `UNTESTED` / `TIMEOUT` / `LOCKED` / `NOT_RUN` |
| `SPEC["states"]` | `GREEN` / `RED` / `NODATA` / `GATED` / `ABSENT` / `SKIP` / `YELLOW` / `NA` |

只有 `SKIP` 剛好同名,所以只有它有色。

**這正是批700 LL365 那一族**:一個態生得出來,就要有一張表接得住它。差別只在那次接不住是「整跑炸掉」或「整站消失」,這次是**安安靜靜不上色** —— 更難發現的那一種,因為無色看起來就像正常。

修法:`_STATE_MAP` 蓋住格子生得出來的每一態,沒見過的態回 `NA`(灰)而不是無色。修後 **299 格上色**(`GREEN 290 · RED 3 · SKIP 5 · GATED 1`)。

## 新律

- **LL369** 兩個模組各有一套態字彙,接線的時候一定要有一張明擺著的對照表。沒有對照表的後果不是報錯,是**安安靜靜地不上色/不分類** —— 而「看起來正常」比「當場壞掉」難發現得多。
- **LL370** 驗規矩的檢,判準要跟規矩本身同一個脈絡。「零彈窗」是看**腳本脈絡**,不是看字串出現過幾次;拿字串數去當判準,第一個被判錯的就是那條寫著這件事的紀錄本身(LL133 的近親)。
