```

[後測] 加速缺 0 · 網路缺 0(0=全覆蓋)
```

**但那條尺是:**

```python
NET_IMPORT_RX = re.compile(
    r"^\s*(?:import|from)\s+(urllib|requests|httpx|aiohttp|yfinance|akshare|playwright|websockets?)\b")
```

它**看不見 `socket` / `ssl` / `http.client` / `smtplib` / `paramiko` / `pycurl`** ——

所以「全覆蓋」這句話在批646 之前為真的範圍,比它聽起來小很多。
而且**沒有人會發現**,因為報表上就是一個 0。→ **LL277**

## 第二層(v0102)

AST 掃(不看註解裡的字),逐件分類,**豁免一律附理由**(L87):

| 類別 | 意思 |
|---|---|
| `VENDORED` | 被複製進樹的三方件;掛 VIA 橋只會把它改壞 |
| `HOSTNAME_ONLY` | 只讀本機名字(`gethostname`),零封包出門 |
| `LOCALHOST_ONLY` | 連線目標字面值全為 `127.0.0.1`,本機 hub 探活 |
| **`NEEDS_BRIDGE`** | 其餘 —— **應掛正典網路橋** |

```
via-bridge-sweeper --net2        ← 零寫入,只報不改
```

**實測:活件 2,362 · socket 31 / http 7 · 本機名 23 · 本機連線 14 · NEEDS_BRIDGE 0**

> **結論:真的出門而沒掛正典橋的 = 0。**
> 不是因為我說的,是因為**檢⑪ 每跑一次全格子就重驗一次**。

`--net2` 預設**只報不改**:把正典橋硬掛到一個 `gethostname()` 上,是為了好看而說謊,不是治理。

## 這把尺我連改五版才乾淨(22 假紅 → 0)

| 版 | 錯在哪 | 後果 |
|--:|---|---|
| 1 | `connect` 無條件算開 socket | `duckdb.connect(":memory:")` → **22 件假紅** |
| 2 | 目標是參數名就回「判不出」 | `def _port_open(port, host="127.0.0.1")` 純本機探活被判缺橋 |
| 3 | 把 `(host, port)` 攤平逐項收 | **埠號被當成主機**,已解析出 127.0.0.1 的件照樣紅 |
| 4 | 兩輪都用 `ast.walk`(它是攤平的) | **同一個呼叫數兩次**,模組層 env 是空的又補一個「?」 |
| 5 | 收乾淨 | **22 → 0** |

**前四版如果直接上線,就是一面長期亮著的假紅牆。**
而假紅跑久了沒人看紅燈(LL272)。→ **LL278**

> 律:新的分類尺一律**先把全部命中逐件看過再定案**。
> 命中數從幾十掉到個位數是正常的,反過來才要警覺。
