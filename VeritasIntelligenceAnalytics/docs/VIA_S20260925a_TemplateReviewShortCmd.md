### 1 · SAME 分支:沿用舊記錄可以,但現況要重驗

**你說的對**:沿用上一版的比對基準、數字、錯誤碼是合理的。v0101 ⑥ 就是修「SAME 回值要整組照上一版」,這一點不變。
但「檔案現在在不在、讀不讀得動」每一次都要重驗。v0103 逐檔重驗五樣:連結冊、三張頁、上游報告、引擎、模板。

- **連結冊**(或指定的上一輪基準)在,卻讀不動或壞 → `BLOCKED` rc1。
  不當首建重寫,因為那樣會把比對基準洗成「首建」,也會蓋掉上一版的記錄。
- **頁**讀不動 → 不算完好 → 照建、換上新頁,回值 `healed` 點名是哪一張。
- **上游引擎**讀不動 → 簽章記「讀不動」,不當成「不在」。
  頁照建,但 rc1;只要還讀不動,就永遠不走 SAME;check 判 STALE 並講讀不動。
- **寫檔改兩段**:三張頁與連結冊先各寫一個暫存檔,全寫得進去才逐一換名換上(同一個夾內換名是原子的),連結冊最後換。
  - 寫不進去 = BLOCKED,一張都不換,也不留暫存檔。
  - 萬一換到一半被擋:連結冊沒換 → 下次 check 不給 OK、build 會重建,不會被當成 SAME。
- **check**:
  - 連結冊不在 = NONE rc2(沒建過)。
  - 在卻讀不動或壞 = DRIFT rc1,講原因。
  - 態仍只有 OK · STALE · DRIFT · NONE。VCGC ㊳ 只認這幾個,所以只多原因、不多態。

### 2 · 只讀最新 5 本 → 建構時間索引 + 窗外處理規則

**索引**:每個「一輪一夾」的上層夾放一本 `VRN_TEMPLATE_INDEX.json`,記每一輪的「夾名 → 建構時間 · 大小 · 檔案時間」。
- 存夾名、不存全路徑:OneDrive 換機、磁碟代號不同,照樣對得上。
- 找最新一版、找上一輪,一律照**建構時間**排,不再照檔案時間取前 5 本。

**候選範圍外的處理規則**:

| 情況 | 怎麼辦 |
|---|---|
| 索引擔保得了:同夾名、同大小、檔案時間差 ≤2 秒(OneDrive 只留到秒、FAT 兩秒) | 用索引的建構時間,不開檔 |
| 其餘:索引沒有的新一輪 · 複製進來的 · 還原的 · 同步改過時間的 · 舊版建構器建的 · 索引壞了或讀不動 | **全部打開讀**,不設「前幾本」的窗。候選範圍 = 索引擔保不了的全部,所以窗外有新版也不會漏。正確性不靠索引,索引只省 I/O |
| 打不開的 | 照報讀不動,並註明「那裡可能有更新的一版」;交接的態不給 OK |

**誰寫索引**:
- `build` 建在「一輪一夾」底下時寫。條件:夾名是 template,而且上層夾是正式的 vrn_autotest、已經有索引、或還有別的一輪。
  它把這一次掃描讀得動的每一本都登進去(原子寫;寫不動不影響建構,回值 `index` 註明)。
- `reindex` 動詞手動重建,用在換機、大量還原、OneDrive 重新同步之後。
- 交接、找上一輪、status 只讀不寫。

**I/O**:25 輪、都登過索引時,找上一輪零開檔、交接開 ≤2 本(最新那一本 + check)。
沒有索引時,25 本全開、但挑得對。這是正確性的代價,build 或 reindex 一次就回到零。

### 3 · ⑦ 讀不動:三件都驗

v0102 的修法是「交接開頭清空模組層字典再量」:根這一層對,細一層不對(見 M6、M7、M8′)。
v0103 改成**每次呼叫自己的量表**:`_scan` 一處定義,不靠模組層字典。
- 三層都照實記:根列不出 · 某一輪的夾 stat 被拒 · 連結冊打不開。
- 一個讀不動不拖垮整個交接。
- 全部都讀不動 = DRIFT,不是 ABSENT「還沒有任何一版」。
- 模組層 `UNREADABLE` 只留給舊讀者:內容 = 最近一次交接量到的,整份換掉。

自測 ⑮ 驗你要的三件:
1. 本次讀不到會報(A、B 兩根都點名,態不給 OK,模組層副本同一份)。
2. 權限恢復後,下次交接不殘留(A 恢復 → A 不再報)。
3. 其他仍讀不到的根不被一起清成正常(B 仍報、態仍不給 OK)。

另外還驗:
- 細一層兩種:某一輪的夾讀不動;最新那一本打不開(有索引 / 沒索引兩條路)。
- 找上一輪量到的讀不動,不會漏進之後的交接。
- 全部讀不動 = DRIFT。

**怎麼造「讀不動」**:
- POSIX 非 root → 真的 chmod,作業系統真的拒絕(`nobody` 身分實跑 13 OK · 2 SKIP;SKIP 是 node 那兩檢,那次故意不給 node)。
- root / Windows(chmod 擋不住)→ 包讀寫口 `_ls/_st/_rb/_wb` 模擬。
- 兩條路驗同一組斷言。
