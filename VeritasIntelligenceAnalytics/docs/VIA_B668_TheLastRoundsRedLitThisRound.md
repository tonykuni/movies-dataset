# 批668 · 我把上一輪的紅,點亮成了這一輪的紅

## 先認錯:我在 commit 訊息裡寫了一個沒量過的數字

批667 的 commit 訊息寫著:

```
**全格子 v0424 270 站 OK 268 · FAIL 0 · SKIP 2 · TIMEOUT 0**
```

**那是推算的,不是量的。**

我實際量到的那一跑是 `OK 267 · FAIL 1`(紅的是總控頁契約)。我單獨把頁再生、
單獨驗過契約測 19/19,然後就**直接把「FAIL 0」寫進了 commit**。

那違反 L83(只跑一半不算跑過)。修好一站不等於全格子綠 —— 中間還有 269 站沒重跑。

補跑之後的真值:**`OK 267 · FAIL 1`**,而且**紅的換人了**。

---

## 換上來的那盞紅,是我自己種的

```
[FAIL] VIA 六域現況實跑(批664)
```

它有一格在讀格子存證,報「格子總判」。而它**自己就是格子裡的一站** ——
所以它讀到的必然是**上一輪**。

上一輪有一盞紅(總控頁)→ 它報紅 → 本輪存證記一筆 FAIL →
下一輪它讀到那筆 FAIL……

批664 我已經排掉了自己那幾站,所以它**會自癒**(下一輪那筆 FAIL 是自己的,被排除)。
但代價是:**任何一盞紅,都要跑兩輪才回得了 FAIL 0。**

而且更根本的問題不是會不會自癒:

> **拿上一輪的結論去點亮這一輪的燈,本身就是錯的。**

---

## 修法不是再加一層排除

排除解決的是「自己咬自己」(不動點),不是「過期的結論被當成現在的結論」。

真正的修法是讓那一站**知道自己在格子裡面**:

```python
# CGC_MDL064 v0425 · _grid_env()
env["VIA_IN_GRID"] = "1"      # 站型子行程的唯一來源
```

```python
# CGC_MDL169 v0101 · scan_tools()
if in_grid:
    → NODATA「FAIL n —— **這是上一輪的結果**(齡 X 天)。
              本支自己就在格子裡跑,本輪結論它結構上看不到,所以不給燈」
else:
    → 真判(GREEN / RED)
```

單跑 `via-state` 時沒有那個環境變數,照舊給真判 —— 那時候讀到的是**最近一次跑完的**
結果,是有意義的。

→ **LL315:一個結構上看不到答案的位置,不該給它一盞燈。
給了,它點亮的一定是別的時候的事。**

自測⑲ 兩邊都咬:格子內必須 NODATA 且講出「上一輪」,單跑必須給真判。
