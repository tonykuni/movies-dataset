## 一、19 個洞不是同一種洞

逐欄攤開之後,分成四條車道:

| 車道 | 欄 | 意思 |
|---|--:|---|
| **BRIDGE** | 10 | 冊上已經有一個「同一件事」而且帶辨識式 → 接過去 |
| **SYNTH** | 5 | 冊上沒有對應的有式鍵 → 用**這一欄自己既有的同義字**合成(零新造詞) |
| **DERIVED** | 3 | 推導欄:算出來的,頁面上本來就沒有那一行 → **不給辨識式** |
| **DIMENSION** | 1 | 維度欄:不是財務數字 |

**關鍵的一條是 DERIVED。**

`ebit` / `eps_qoq` / `sales_qoq` —— 台灣財報**沒有「EBIT」那一行**,季增率也沒有一行印在那裡。
給它們辨識式,等於宣稱認得出一個不存在的東西。**那是假綠。**

所以「待裁定 0」不是因為全部填滿了,是因為**其中四欄判的是「不該填」**。

> 年增率相反:`eps_growth` / `revenue_growth` 在冊上是有式的,研報真的會印「每股盈餘成長率」。
> 所以 `eps_yoy` / `sales_yoy` 走 BRIDGE,`eps_qoq` / `sales_qoq` 走 DERIVED。
> **同一個欄位家族,一半有門一半沒有 —— 因為報表上就是這樣。**

## 二、兩筆機器判不出來的,我判了

### ① `non_current_liabilities` —— 候選演算法給錯了

自動比對算出來最像的是 `other_noncurrent_liabilities`「**其他**非流動負債」,
因為這一欄的 `synonyms_zh` 誤收了那五個字。

**把總額接到子科目會算錯。** 正解是 `total_non_current_liabilities`「非流動負債合計」(3 式)。

### ② ROE 的分母那一對

```
shareholders_equity  → total_equity   「權益總計」= **含非控制權益**
parent_equity        → 不接,自己合成  「歸屬母公司業主權益」
```

拿總權益當 ROE 分母,數字會偏低而且**看起來完全正常** —— ENG074 v0112 的 docstring 記過這個坑。
所以 `parent_equity` 刻意不併進去,它走 SYNTH 自己有式。

## 三、SYNTH 怎麼保證零新造詞

合成式的每一個字,都必須在這一欄**原本就有的** `synonyms_zh` / `synonyms_en` /
`field_map` / `mops_official` 裡找得到。自測⑱ 逐字咬:

```
parent_equity → (equity\ attributable\ to\ owners\ of\ parent|Parent\ Equity|
                 歸屬母公司業主權益|母公司業主權益|parent\ equity)
```

**長的排前面。** 不然交替比對會讓「母公司業主權益」先吃掉「歸屬母公司業主權益」,
而短的那個常常是錯的科目。自測⑲ 驗排序。

## 四、same_as 要迭代,不能只跳一手

```
cfps → cashflow_per_share → operating_cf_per_share
```

第一版只認「指到的那個有式」,於是 `cfps` 永遠接不上 —— 它指到的那個自己也沒式。
改成**迭代到不動點**,而且 `patterns_of` 回**整條路徑**不是只回終點:

```
cfps 借道 cashflow_per_share→operating_cf_per_share
```

借了幾手要看得見。

## 五、層名覆核:錯的不是層名

冊上掛著「請操作員覆核層名與歸屬」。我提過兩個怪處,量過之後發現 ——
**錯的不是那六個名字,是「一支引擎只能站一層」這個假設。**

### ① L2「結構與知識」混著加工站與參考書

```
ENG074 財報頁   把 PDF 變成一列一列的數字   ← 加工站
ENG063 詞庫     一本字典                   ← 參考書
```

不是層名錯,是節點少了一個欄位。補 **`role_kind`**(加工 / 參考 / 落庫),層不動。

> 加工站壞了會吐錯數字,參考書壞了是查不到。用同一盞燈看它們,兩邊都看不準。

### ② L5「儲存」的正典那一格 —— **它不是空的**

我上一批說「正典儲存那一格是空的」。**去量,不是。**

```
VRN_ENG073_ReportStructuredDB:
  CREATE TABLE IF NOT EXISTS vrn_report_basic
  CREATE TABLE IF NOT EXISTS vrn_report_analyst
  CREATE TABLE IF NOT EXISTS vrn_report_metrics
  → vdf_tw_market.duckdb
```

L90 裁定:「正典是 `vdf_tw_market.duckdb` 的 `vrn_*` 七張表」。**承載者就是 ENG073。**

它只是被歸在 L2 —— 因為它同時做結構化與落庫,**它真的跨兩層**。
補 **`also_layers`**,L5 的空格當場被填上,憑據是可查的建表語句。

### 裁定

**六層層名維持,層數維持,不搬動任何一支的歸屬。**

改層名/改層數要重做 50 個指標與 15 支歸位,**換不到任何一個新的判斷力**。
兩個新欄位都是只增不減。要推翻哪一支,看它的 `role_kind_why` / `also_layers_evidence` 那一行就夠。

## 六、兩道舊檢擋住了「合法的裁定」

覆核落冊之後,兩處當場報紅:

```
自測⑤   待裁定一律 PENDING_OPERATOR(索引冊不代操作員裁定;LL90)
守門     [待裁定被動過] 1  ← 裁定權在操作員,本工具不自己裁
```

**那是「裁定權沒轉手」時代的規則。** 但規矩的精神不是「AI 不准裁」,是「AI 不准**默默**裁」。

兩處都改成:**要嘛還掛 PENDING_OPERATOR,要嘛已裁但帶得出署名(`ruled_by`)與憑據(`why`)。**

新檢比舊檢**嚴**:舊檢分不出「裁了沒署名」和「裁了有署名」,它把兩者一起擋掉;
新檢真的去看有沒有留痕。守門也分兩堆講 ——
一個「被動過 1」會把「裁得清清楚楚」和「偷偷改掉」講成同一件事。

→ **LL312:一條「AI 不准裁」的規矩,在裁定權轉手那天會把合法的裁定一起擋掉。
規矩要寫的是**留痕**,不是**禁止**。**
