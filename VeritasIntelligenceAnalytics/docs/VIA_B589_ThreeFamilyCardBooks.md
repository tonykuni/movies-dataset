## 一、先講更正:我批588 數的是檔案,不是家族

掃 CGC 族,`debt` 報出來:

```
misc.newest    451 份
battery()      258 份
run_one()      258 份
```

258 不是「258 個地方各寫一份」。是 **`CGC_MDL064_SelftestGrid` 有 258 個歷史版號**,
每一版的檔案裡都有同一支 `battery()`。

**那是版本史,不是重複實作。**照那個數字去「整合」,等於叫人去整併自己的版本歷史。

回頭看 VDF 也一樣:144 檔裡只有 45 支是尾版,其餘 99 支是舊版號。
所以批588 我報的「VDF 真債 272 類 / 1186 份」,**絕大部分是同一支引擎的前世**。

| | 批588 報的 | **更正後** |
|---|---|---|
| VDF 真債 | 272 類 / 1186 份 | **56 類 / 90 跨家族** |

**差了 13 倍。**

改法:債的單位從**檔**換成**家族**(路徑去掉 `_vNNNN`)。分四層,前三層不計債:

```
① contract  律規定每檔都要有(批115 網路橋 · 法遵雙閘 · 統一調度契約)
② generic   語意空殼(build.any / misc.tuple)
③ history   **同一家族的不同版號** ← 批589 新增這一層
④ real      跨家族重複 ← 只有這層是債,以家族數計
```

→ **LL142:數重複之前,先問你數的是檔案還是家族。**
這跟 LL131(分母灌水/縮水)、LL138(假的零)是同一個病灶的第三種長相:
**尺量的單位不對,數字就整個沒有意義,而且方向是往「看起來更該做事」那邊偏** ——
這種偏差最危險,因為它會被照做。
