# 批695 · 治理層不在場的時候,閘自己打開

批691B–692 當場量到兩件同意閘的事,兩件的**修**都在 `.ps1` 裡,

**躺在任務清單上的缺陷,跟沒發現的缺陷,可靠度是一樣的。**
所以這一批不修它們,而是**把它們變成量得到的數** —— 第四把尺。

## 二 · 量到什麼

```
期望值種數 3 · fail-open 29 支 · 雙態 1 支

  'YES'                            ← 14 處(全樹尾版、錨在真的讀環境的動作上)
  'I_ACCEPT_RESPONSIBLE_SCRAPING'  ←  1 處(Register v0242 的 via-gates 印給操作員看的)
  'OFF'                            ←  1 處

  **雙態** Register-VIA-Commands-v0242.ps1 · 開 ['YES'] / 關 ['', 'OFF']
```

三欄各說各的,永不相加(LL327):

* **期望值分裂** —— `via-gates` 在畫面上叫操作員設 token,而 14 個真的讀環境的檢查點只認 `"YES"`。
  **照畫面上的指示設,那 14 個點全部 fail-closed。** 操作員會以為自己開了閘。
* **fail-open** —— 29 支尾版 `.ps1` 會把閘設成放行值。
* **雙態** —— 同一支檔裡兩條分支**方向相反**。批691B 的對照實驗(`-Dry`,零擷取)量過:

  ```
  不點源 Register   ③ 同意閘:NET=YES  SCRAPE=YES     ← fail-OPEN
  有點源 Register   ③ 同意閘:NET=OFF  SCRAPE=OFF     ← fail-closed
  ```

  同一支腳本、同一組旗標,**閘態相反**。差別只是治理函式在不在 scope。

## 三 · 這把尺自己先錯了三次

寫檢是一回事,**檢對不對是另一回事**。三個錯都是量出來的:

### 錯一 · 假陽:把回報標籤當成期望值

```python
out["consent"]["VIA_NET_CONSENT"] != "OPEN"     # ← 這是**回報用的標籤**,不是環境變數
```

第一版的式子只看變數名出現,於是把它算成「有一種期望值叫 OPEN」。
→ 檢查端一律**錨在真的讀環境的那個動作上**(`environ.get` / `getenv` / `$env:`)。

### 錯二 · 假陰:漏掉隔了兩行的變數轉手

```powershell
$g1 = $env:VIA_NET_CONSENT; $g2 = $env:VIA_SCRAPE_CONSENT
$tok = "I_ACCEPT_RESPONSIBLE_SCRAPING"
if ($g2 -eq $tok) { ... }        # ← 比的是 $g2,跟 $env: 隔了兩行
```

第一版只看同一行,於是**整個漏掉 `via-gates` 真正的期望值** —— 而那正是這一批要報的重點。

> **而錯一與錯二剛好互相抵銷:** 多算一種(OPEN)、少算一種(token),總數還是 3。
> **靠兩個錯抵銷出來的對,是最糟的一種綠** —— 它連「哪裡不對」的線索都不留。
> 只有逐項印出來對過,才看得見。

### 錯三 · 自己數自己

修完前兩個之後,期望值裡冒出一種叫 `'值'` 的 —— 出處是**本檔自己的註解**
(`$env:VAR -eq "值"` 那行說明文字)。這就是 LL133:

> **判定器一定要排掉自己的家族。** 不排,它的說明文字就是它的發現。

→ 加 `_SELF_FAMILY` 自排。順帶讓 `CGC_MDL164` 的 ⑰ 自我指涉閘把本檔判成 SAFE。

### 附帶更正一個我報給操作員的數字

我先前說「75 處 Python 檢 `"YES"`」—— 那是 `grep` 把**退役版本**也數進去了。
這把尺走**尾版律**、而且錨在真的讀環境的動作上:**14 處**。
