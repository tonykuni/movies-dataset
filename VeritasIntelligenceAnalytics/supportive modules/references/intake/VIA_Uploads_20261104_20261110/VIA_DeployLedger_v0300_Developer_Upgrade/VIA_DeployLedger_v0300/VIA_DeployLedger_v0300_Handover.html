先把 deploy_contract.example.json 轉成真實 deploy_contract.json。入口、source、Python、smoke、工具雜湊、VCGC probes、readiness、動態模組與資源必須以真實現場核定。範本中觀察到的 v0166 路徑只作定位，不等於已認證。

pipeline 依序 prepare → build → qualify → seal。任何一步失敗就停止，下游不產生成功狀態。qualify 使用該產品的合法 QA 裝置授權做真實 EXE 測試；QA 授權應短效並與客戶生產席次台帳分開，不應占用客戶唯一席次。

管理端金鑰與台帳置於只供供應商存取的位置。私鑰採加密 PKCS8；密碼透過互動輸入或 VIA_PRIVATE_KEY_PASSWORD，不能放進指令列／客戶 ZIP。

客戶真正可用時的體驗

  1. 收到經驗收的編譯版，啟動 VIA_Setup.exe，選安裝包，輸入產品 KEY。
  2. 初次啟用目前須取得管理端簽發的 license.json；這是離線往返，不能宣稱已達首次全自動線上啟用。
  3. 授權到位後，自動驗簽、解壓、快速功能測試及切換版本；可以立即啟動 VRN。
  4. 下次開啟 Setup 可啟動現有系統或安裝新版；各子系統可透過 run --unit 指定獨立入口。
VIA_Setup.exe --home "%LOCALAPPDATA%\VIA" activate --product-number XXXX-XXXX-XXXX
VIA_Setup.exe --home "%LOCALAPPDATA%\VIA" install --package VIA_release_CANDIDATE.zip --license license.json
VIA_Setup.exe --home "%LOCALAPPDATA%\VIA" test
VIA_Setup.exe --home "%LOCALAPPDATA%\VIA" run --unit VRN_CORE
VIA_Setup.exe --home "%LOCALAPPDATA%\VIA" rollback

這些 EXE 命令是編譯後的介面；本次交付並未包含 Windows EXE。

正式商業版仍須完成的具體工作

  1. 在 Tony 的 Windows 機器執行盤點，取得當前而非歷史的來源、工具／套件版本及 VCGC 結果。
  2. 處理 VRN 市場擷取 OPEN 與尚待人工核對的資料驗收；分開記錄外部資料源缺口。
  3. 補齊各獨立引擎可搬移的入口、資源及動態載入閉包；現有按 *.py 找舊版／解壓 PY 再執行的流程，必須在 staging 改為已編譯模組或授權入口解析。只勾 closure_reviewed=true 不能排除 native_hazards 的阻擋。
  4. 透過 VCGC 建立已鎖定的 Windows 編譯環境，包含 cryptography、Nuitka、Tcl/Tk 與可用 C 工具鏈。工具不存在時不直接繞閘下載。
  5. 實際編譯，完成合法與非法啟動測試；驗證每個工具／模型／語言包及重要功能都可離線定位。
  6. 簽署 Setup 並重新封包；乾淨 Windows 安裝、快速測試、升級失敗回復均通過後才核准出貨。
  7. 若要求第一次安裝也不經離線往返，需接上正式 HTTPS 授權服務；本次未建立公網服務或收費系統。

原生編譯與授權能提高未授權複製及程式提取的難度，但不保證面對客戶端系統管理員時絕對不可逆向。自有引擎授權與第三方開源工具的權利分開處理。
