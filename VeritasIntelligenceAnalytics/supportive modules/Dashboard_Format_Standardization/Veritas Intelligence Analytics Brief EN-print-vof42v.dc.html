01 · Origin

From a PM who
could not rest.

The origin — a weekend that could never switch off

The origin was not an AI product idea. It was a real operational burden.

A project manager at a leading electronic-components company — already running PM work — was asked to support a PLM rollout that had to coexist with legacy SAP and MS Project.

Every Monday meant a status briefing. Every weekend meant chasing data scattered across email, attachments, tables, charts, minutes, old systems and people's verbal accounts.

A
Multi-system coexistence — SAP, MS Project & a new PLM, none speaking the same language.
B
Scattered evidence across email, attachments, tables, charts and meeting notes.
C
Manual weekly rework — status rebuilt from zero, every single week.
D
No automatic reconciliation between PLM / SAP / MS Project.
E
No traceable SSOT — knowledge lived in human memory, not an auditable layer.

The real problem was never the report.
It was the absence of a governed single source of truth.

07 · Resilience Spec

The "doomsday" test is a requirement,
not an incident.

Whole team gone, no network, no AI — not a disaster story, but a resilience standard

Under degraded conditions — no network, no external AI, no clean handover — the system must not hallucinate certainty. It must degrade honestly into a deterministic rule engine.

No Network
Use local cache, last-sync state & offline SSOT for classification and reconciliation.
Never claim it fetched fresh cloud data.
No External AI
Fall back to a deterministic rule engine, template reports, fixed classifiers.
Never let the whole system collapse.
No Handover
Generate a handover pack: project list, responsibility / risk matrix, process map, gap list.
Never pretend to know un-handed-over context.

If it still produces a conservative report, a risk matrix and a handover pack offline — it is no longer an assistant. It is operational infrastructure.
