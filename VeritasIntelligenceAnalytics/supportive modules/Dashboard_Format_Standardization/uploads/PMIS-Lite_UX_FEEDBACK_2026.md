# PMIS-Lite 體驗規劃：20 驚艷點 × 20 失望點 × 補強方案 × 實測回饋功能

_把使用者真實感受拆成 40 個點，每個失望點配補強方案，並把這 40 點做成『點選式回饋標籤』——使用者測完點一下即回報，系統自動排出補強優先序。回饋功能已內建並測試（25/25）。_

## 三、實測回饋功能（已內建並測試，離線運作）

把上面 40 點做成**點選式回饋標籤**，使用者測完點一下即回報，不打字：

- **`feedback.py`**（已建，25/25 測試通過）：`record_feedback` append-only 寫入；`summarize` 彙整出「最被讚/最被嫌」+ 自動排補強優先序（附方案）。
- **離線、無 AI**：純本機 jsonl，斷網照收。
- **設計巧思**：回饋標籤 = 驚艷/失望點本身，所以收到的回饋天然對齊改進清單，不必再人工歸類。

**實測示意**（剛跑過）：11 筆回饋 → 最被讚 D03「完整性可信數字」×3、D05「全景+停滯」×2；最被嫌 X04「冷啟動偏低」×2 → 系統自動把 X04 排到補強第一位並附方案。

### 回饋閉環（mouse-first）
```
使用者測試 → 點驚艷/失望標籤（滑鼠，不打字）
   → feedback.jsonl（append-only，離線）
   → summarize 自動排序
   → 補強 roadmap（被嫌最多的先做）
   → 改版 → 再測 → 再點 → 看曲線是否好轉
```

### 建議的前台回饋 UI（下一步可做）
- 結果頁底部一排「👍 驚艷 / 👎 失望」卡片（即那 40 個標籤），點一下記一筆。
- 一張「回饋彙整頁」：長條圖顯示最被讚/最被嫌，紅色點自動帶出補強方案。
- 版本對比：第 N 版 vs 第 N+1 版的失望點數量曲線，證明「越改越好」。

## 四、一句話總結

驚艷點要「守住」（完整性可信、離線可跑、滑鼠三回合、自動爬升），失望點要「逐點消」（先打冷啟動/術語/白話/速度四個第一印象殺手）。而且**回饋不用問卷、不用打字、不靠網路**——點一下,系統就自己排出下一步該補什麼。
