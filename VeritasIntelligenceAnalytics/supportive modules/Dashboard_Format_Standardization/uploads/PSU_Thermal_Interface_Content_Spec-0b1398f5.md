## 1. 產業動能趨勢分析 · INDUSTRY DRIVERS

- **目的**:把族群/子產業動能訊號展開成趨勢,並下鑽到公司,對照資金流。
- **輸入**:VIA FIS/flow 引擎輸出(本機跑真資料)· T02(公司↔族群)· T03(公司↔應用)。
- **分群維度**:族群 → 子產業(電源/散熱→液冷/氣冷/均熱片…)→ 公司。
- **下拉+新增**:族群、子產業、時間窗(自動最新/全部,沿用 flow 系統 preset)、動能指標別。
- **指標/計算**:族群動能分數(z→tanh→EWMA,沿用既有引擎)· 動能排序 · 動能 × 資金流象限(流入且動能升 = 主流)· 動能加速度(Δ動能)。
- **鑽取**:族群 → 公司動能 → 該公司 BOM 品類集中度(接介面 3)。
- **輸出**:動能排序表 + 趨勢序列 + 象限分類。
- **證據/T-1**:籌碼/資金流 **T-1 紀律**(T+1 才可用,ASOF JOIN);動能訊號 T1–T2。
- **自動編號**:族群/子產業掛 VIA-DOM;綁定公司用 VIA-PEER。

## 2. 產品製程 × 資本支出分析 · PROCESS × CAPEX

- **目的**:各公司/BU 的製程站、關鍵設備、產能、capex、廠區分布,看擴產與需求缺口。
- **輸入**:T07(製程/設備/產能/capex/廠區)· T06.capex(財報)· T03(產品→製程對應)。
- **分群維度**:公司 → BU → 製程站(如水冷板:沖壓/CNC/釺焊/鍍金)→ 設備。
- **下拉+新增**:公司、製程站、廠區(台/中/泰/越/印/美/德)、capex 期別。
- **指標/計算**:capex 趨勢 · 產能 vs 客戶需求缺口 · 廠區產能分布(地理集中風險)· 製程瓶頸標記(對照 BOM 瓶頸料)。
- **鑽取**:廠區 → 製程站 → 設備 → 對應產品家族。
- **輸出**:capex 時序 + 產能分布 + 瓶頸熱點。
- **證據/T-1**:capex 用財報(T1,asof 發布日);製程/廠區 T2–T3(法說/新聞→不進數值計算)。
- **自動編號**:知識列 VIA-KNW。

## 3. 產品 BOM 分類分群展開 · BOM TAXONOMY / CLUSTER

- **目的**:把 BOM 依品類/階層/替代料分類分群,逐階展開。
- **輸入**:`super_bom`(公開三維骨架)· T03(產品×規格)· 機密 BOM(`sovereignty=confidential`,走公司分檔,不共池)。
- **分群維度**:品類(電源域:電晶體/磁性/電容…;散熱域:熱導管/均溫板/均熱片/水冷板/微流道/分歧管/CDU/快接頭/水泵/風扇/鰭片/TIM/機殼/導線架/冷卻液)× 階層 Level × MType(FERT/HALB/ROH)× 替代料 Alt_Group。
- **下拉+新增**:公司、BU、產品家族、品類、階層深度、只看瓶頸料。
- **指標/計算**:品類集中度 · 多階建樹 · where-used(某料被哪些產品用)· 二源覆蓋率(替代料)· RoHS/REACH/無鹵/衝突礦產 缺漏掃描。
- **鑽取**:產品家族 → BOM 樹 → 料號 → 供應商(接介面 4)。
- **輸出**:分群樹 + where-used + 合規缺漏清單。
- **證據**:公開骨架 T2;機密 BOM 各自主權,不入共池。
- **自動編號**:產品 VIA-PRD、子件 VIA-SUB。

## 4. 供應商 × 客戶 分類分群 · SUPPLY CHAIN BREAKDOWN

- **目的**:供應商與客戶雙邊分類分群,畫出關聯與出海口集中度。
- **輸入**:T01(供應商)· T04(客戶)· T05(關聯邊)。
- **分群維度**:供應商(國別/料類/上市否/二源)· 客戶(產業/出海口:NVIDIA/CSP/車廠/電信/衛星)· 邊(覆蓋率/二源風險)。
- **下拉+新增**:國別、料類、客戶產業、出海口、二源風險等級。
- **指標/計算**:出海口集中度(HHI)· 單一客戶依賴度 · 二源覆蓋率風險 · 供應鏈圖(networkx:供應商→料→客戶)。
- **鑽取**:客戶 → 依賴供應商 → 料號 → 替代料風險。
- **輸出**:雙邊分群表 + 關聯圖 + 集中度矩陣。
- **證據**:關聯邊多為 T3(新聞/推測)→ 圖上虛線,不進數值。財報附註確認者升 T1。
- **自動編號**:供應商 VIA-SUP、客戶 VIA-CUS、邊 VIA-EDGE。

## 5. 產品 × 規格 全展開 · PRODUCT × APPLICATION × SPEC

- **目的**:同一品類跨公司的規格/應用並排,看誰在哪個應用做到什麼規格。
- **輸入**:T03(產品×規格×應用×MType)。
- **分群維度**:應用(AI伺服器 GB300/VR200、EV、電信、低軌衛星)× 產品家族 × 規格類 × 公司。
- **下拉+新增**:應用、產品家族、規格類、公司(競品並排)。
- **指標/計算**:規格覆蓋矩陣(公司 × 規格)· 應用滲透(某公司切進哪些應用)· 高規格占比。
- **鑽取**:應用 → 產品家族 → 各公司規格對比 → 對應 BOM(介面 3)。
- **輸出**:規格覆蓋矩陣 + 應用滲透圖。
- **證據**:公開產品目錄 T2。
- **自動編號**:VIA-PRD/VIA-SUB。

## 6. 財務數據 · FINANCIALS（財報優先 / 法說次之）

- **目的**:營收/毛利/營益/EPS/capex 的財務結構與趨勢,綁到產品/製程解釋。
- **輸入**:T06(財報,`data_priority=財報` 優先,`法說` 次之)。
- **分群維度**:公司 × 期別(季/年)× 指標。
- **下拉+新增**:公司、期別區間、指標別、資料優先序(財報/法說)。
- **指標/計算**:營收/毛利/EPS 時序 · 毛利結構(液冷滲透 → GM 變化)· capex/營收比 · 可編輯 PER × EPS 估值(沿用 Unified HTML 財務模型)。
- **鑽取**:公司財務 → 產品組合(介面 5)/ 製程 capex(介面 2)交叉解釋。
- **輸出**:財務時序 + 估值模型 + 結構分解。
- **證據/T-1**:**財務 = T-1 紀律硬性**,每列必須有 `asof_release`(發布日)才可用;財報 T1,法說 guidance T2 且**不進估值數值、只作註解**。
- **自動編號**:VIA-FIN。

## 7. 產業知識體建構 · INDUSTRY KNOWLEDGE BODY

- **目的**:把製程/設備/PLM/PMBOK/SAP 知識沉澱成可查詢知識體,支撐上面各介面的名詞與方法對齊。
- **輸入**:T07(知識)· `sap_modules_ref`(SAP 模組/T-code)· `super_bom` 方法論(PLM/PMBOK 對齊)。
- **分群維度**:知識類(製程/設備/SAP/方法論)× 公司 × 主題。
- **下拉+新增**:知識類、主題、公司。
- **指標/計算**:知識覆蓋度(哪些公司/製程有登錄)· 名詞對齊表(外部術語 ↔ VIA 內碼)· 缺口清單。
- **鑽取**:主題 → 知識條目 → 引用來源 → 關聯 T 表。
- **輸出**:知識條目庫 + 名詞對齊表 + 覆蓋缺口。
- **證據**:T2–T3;來源必附。
- **自動編號**:VIA-KNW / VIA-IFC(介面契約)。
