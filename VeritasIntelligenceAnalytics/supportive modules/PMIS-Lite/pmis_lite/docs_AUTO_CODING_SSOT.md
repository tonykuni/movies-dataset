# VIS Workbench · AUTO CODING / AUTO SSOT（不知產業也能插上就用）

_泛用工具的靈魂：買回去插上，不知道客戶是哪個產業，也能自動編碼、自動 SSOT、自動演化、自動驗證。已測試（35/35）。_

---

## 核心思路：拋棄查表法，改用「自舉 + 確定性雜湊」

傳統做法遇採購編 `PO-`、遇研發編 `RD-`——**未知領域立刻失效**。VIS Workbench 的解法是編碼與分類**一起演化**：

```
[語義前綴]-[來源]-[年月]-[身分碼]
   ↑            ↑              ↑
自舉類別      郵件/SAP/MSP    標題+行為者雜湊（穩定身分）
（沒長出來前用內容中性雜湊）
```

四個「自動」串成插上即用：

| 能力 | 怎麼做（不需知道產業） |
|------|---------------------|
| **AUTO CODING** | 確定性語義雜湊：同一筆永遠同碼 → append-only 安全、**天然去重**。內容改了身分碼不變。 |
| **AUTO SSOT** | 零組態：桶自資料自舉、關鍵字自動生、碼自動鑄、完整性自動驗。 |
| **AUTO EVOLUTION** | schema-on-read：新欄位/新值只增不減，**永不因沒見過而崩**。前綴越跑越懂這家公司。 |
| **AUTO VERIFY** | 每筆都要有唯一碼才 PASS；完整性 gate + 自檢，錯了自己舉手。 |

**實測（故意混電子/醫療/餐飲三種完全不同產業，零預設）：** 每筆穩定編碼、重複自動同碼、桶自己從資料長出(EVT/DVT/MP)、全部 PASS。前綴會自我演化：分類出 EVT 後，碼變成 `EVT-M-2606-…`。

## 案例一：MS Project（單獨）· 詳列 → 驗證 → 註冊

**詳列** — `ms_project` 預設對照（標準欄位，已內建）：

| MS Project 欄位 | → Record | 說明 |
|---------|---------|------|
| UID | source_ref（原始不動） | 任務原生碼 |
| Name | title | 任務名稱 |
| ResourceNames | actor | 負責人 |
| Start | event_time | 開始日 |
| PercentComplete | status | 完成度→狀態 |
| WBS | thread_id | 工作分解（串接） |
| Text1 | raw_keys | 自訂欄位（常放料號/ERP 單號） |

**驗證** — 讀任務 → 對照 → 自動編碼（原始 UID 原封存 source_ref，系統另鑄碼）：
```
6CW-M-2606-0323798F  UID=1001  WBS=1.1  料號=PN-PSU-500  電源板 EVT 設計審查
22J-M-2606-BE524C77  UID=1002  WBS=1.2  料號=PN-PSU-500  電源板 DVT 測試
```
**註冊** — 3/3 全鑄碼、唯一 3、重複 0、**PASS**。

## 案例二：MS Project + PLM · 詳列 → 驗證 → 註冊（交叉串接）

**詳列** — 兩來源合併：MS Project 任務（進度骨架）+ PLM 工程變更（為什麼改）。新增 `plm_ecm` 預設：

| PLM ECM 欄位 | → Record | 說明 |
|---------|---------|------|
| ChangeNumber | source_ref（不動） | 變更主檔號 AENR |
| Description | title | 變更說明 |
| **Reason** | body | **變更原因——「為什麼改」** |
| Requester | actor | 提出人 |
| ValidFrom | event_time | 生效日 |
| AffectedMaterial | product | 受影響物料 |
| AffectedBOM | thread_id | 受影響 BOM（串接） |

**驗證** — 用**料號當錨點**交叉串接：
```
料號 PN-PSU-500：MS Project 有 2 個任務、PLM 有 1 筆變更
→ 還原：DVT 測試(60%) 進行中，因為 ECN-2026-088「客戶電話要求降溫」
```
**註冊** — 合併 4 筆全鑄碼、唯一、**PASS**。

**關鍵洞見：** MS Project 只知道「DVT 60%」，PLM 只知道「改銅質」，但**為什麼改(客戶電話)只有郵件知道**——三者用料號串起來才完整。這是 SAP/MS Project 單獨做不到的。

## 插上即用的完整流程（現場零設定）

```
客戶把任意資料丟進來（不管什麼產業）
  → 混沌收容（schema-on-read，先無條件接住）
  → 桶自資料自舉（自己發現有哪些類別）
  → 三道分類 + 關鍵字自動生成
  → 每筆自動鑄通用碼（前綴隨分類演化）
  → 完整性自動驗（每筆有唯一碼才 PASS）
  → append-only 入庫 = SSOT
```

全程確定性規則、斷網無 AI 照跑、只增不減。使用者不必告訴系統「我是電子業」——系統自己從資料長出理解。若客戶用了標準系統(SAP/MS Project/PLM)，對照更是**事先內建**，連自舉都省了。
