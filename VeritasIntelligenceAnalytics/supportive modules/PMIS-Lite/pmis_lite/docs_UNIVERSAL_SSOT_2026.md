## 一、核心架構哲學：引擎不變，載荷驅動（Engine Immutable, Payload-Driven）

帶去客戶現場的引擎永遠是同一顆標準品；客製化發生在「組態載荷(config.json)」，程式碼一字不改。
這正是 PMIS-Lite 已實作的方式：adapter 介面 + 資料驅動分類 + 桶從資料自舉。

```
[滑鼠①選行業] ┐
[滑鼠②選通道] ┼─→ config.json ──→ 熱載入 ──→ 泛用引擎（不改）
[滑鼠③按發佈] ┘                              ├ 收容 adapters（多源、備援鏈）
                                              ├ 治亂碼 + 文字修復
                                              ├ 雙軌編號（原始錨點不變 / 系統資產碼自動）
                                              ├ 多道分類 + 自動關鍵字（核可制）
                                              ├ 完整性 gate（不可遺漏）
                                              └ append-only 倉儲 + 產出
```

**2026 本地主權資料棧（查證後）**：dlt 1.0 負責收容（自動 schema 演化、增量），DuckDB 為進程內 OLAP 倉儲，Polars 做高速清洗——三者經 Apache Arrow 零拷貝串接，是 2026 年公認的 in-process 分析組合，免雲端、免伺服器。

## 三、20 個失敗模式 × 雙重內建備援（主線防禦 → 降級備援）

### A. 連線與傳輸層

**1. 企業防火牆 SSL 檢測置換憑證（DPI）** — 腳本報 `CERTIFICATE_VERIFY_FAILED`，瀏覽器卻正常。
- 主線：用 `truststore` 讓 Python 繼承作業系統已信任的根憑證（含公司私有 CA）。
- 備援：仍失敗 → 標記 `SSL_DPI_BLOCK`、改走「本機 Outlook 軟體橋接」。
- ⚠ **不建議**關閉憑證驗證或強制降到 TLS 1.0——那是把安全打開後門，僅在你完全理解風險且有授權下為最後手段，並須留紅色日誌。

**2. 對外埠封鎖（只放行 80/443）** — IMAP 993 逾時。
- 主線：埠自適應探針 993 → 143+STARTTLS。
- 備援：全失敗 → 切「本機檔案 Drop-zone 模式」，改讀匯出檔。

**3. 廉價 NAT 靜默斷流（閒置被踢、不發 FIN）** — Daemon 不報錯但不再進帳。
- 主線：`socket.setdefaulttimeout(45)` + 每 180 秒送 IMAP `NOOP` 保活。
- 備援：偵測無回應 → 銷毀連線池、重新 login。

**4. 訪客 Wi-Fi 登入攔截頁（Captive Portal）** — 下載到的是 HTML 登入頁。
- 主線：連線前探針 `GET /generate_204`，非 204 即判定被劫持。
- 備援：轉「離線佇列」，待網路恢復再補抓；存檔前驗證檔頭非 `<!DOCTYPE html>`。

### B. 授權層

**5. App Password 被 IT 撤銷** — 中途 401。
- 主線：捕捉認證錯誤，**不崩潰**，游標停在最後成功筆數。
- 備援：UI 紅燈「授權失效，請重貼新密碼」；期間用本機快取不中斷。

**6. OAuth 強制 MFA、停用 IMAP basic auth** — 根本生不出 App Password。
- 主線：改走官方 OAuth readonly（個人帳號）。
- 備援：仍不行 → 指引匯出 .pst，改 libpff/extract-msg 讀本機檔。

### C. 解析與內容層

**7. 無限轉發引文地獄** — 抓到三個月前舊單號當主鍵。
- 主線：引文樹修剪，只取最上層區塊（`-----Original Message-----` / `On … wrote:` 之前）。
- 備援：修剪後若空 → 全文掃描但對單號做「歷史出現率去重」。

**8. 空殼正文、精華在內嵌圖** — Body 純文字長度 0。
- 主線：偵測 `len(body)<10` 且有內嵌圖 → 導向 OCR。
- 備援：OCR 信心低 → 標記 `IMAGE_ONLY_REVIEW`，封存原圖待人工複核。

**9. 純黑白掃描傳真 TIFF/PDF（大小章）** — 一個數位字元都沒有。
- 主線：PDF 無文字層 → OCR 接力 Tesseract → RapidOCR。
- 備援：辨識率低 → 標記 `SCANNED_ASSET`、封存二進位、註明需肉眼複核。

**10. 造字/罕見 CJK/mojibake** — 解碼崩潰。
- 主線：`ftfy.fix_text` 多重編碼自癒。
- 備援：解碼綁 `errors='replace'`，異常碼靜默轉 `[?]`，絕不中斷整批。

### D. 雲端硬碟連結層

**11. Drive 連結權限牆** — 下載到登入頁。
- 主線：用**你自己授權**的憑證存取；存檔後驗檔頭，是登入頁就刪。
- 備援：標記 `DRIVE_AUTH_WALL`，把連結前後 40 字當「意圖快照」留存。
- ⚠ **不採用**偽裝瀏覽器/輪替 UA 去規避存取控制或反爬蟲——那可能違反服務條款與資安規範；遇阻就誠實標記、請有權者開權限。

**12. 連結過期失效（Link Rot）** — 404。
- 主線：抓取前先 HEAD 檢查存活。
- 備援：失效 → 標記 `LINK_EXPIRED` + 周邊文字備份，讓追蹤者知道原本有什麼。

### E. 附件層

**13. 加密保護的 PDF/Excel** — 有密碼。
- 主線：偵測加密 → UI 請有權者輸入密碼解鎖。
- 備援：未提供 → 標記 `ENCRYPTED_SKIPPED`、不影響完整性 gate（結構性略過）。
- ⚠ **不內建**自動猜密碼（統編/身分證等字典試探）——那等同對受保護檔案做暴力破解，有法律與資安風險，本系統一律不做。

**14. ERP 匯出 50 萬空白尾列 Excel** — 撐爆記憶體。
- 主線：用 Polars 惰性掃描，載入前 `.filter(不全為 null)`。
- 備援：仍過大 → 分塊串流讀取 + 上限截斷並標記。

### F. 編號與資料層

**15. 手打單號筆誤** — `PO-2026-0629-088` 對不上 ERP 原生碼。
- 主線：嚴謹單號正則（含排除 2021–2030 年份誤判）。
- 備援：未命中 → rapidfuzz 萊文斯坦距離 ≥0.9 自動對齊現有 canonical ID（仍標「疑似」待確認）。

**16. 一封信核准多張單** — 「PO-001、002、003 都准」。
- 主線：adapter 用 `yield` 產生器，一封拆 N 筆。
- 備援：主鍵表 N:1 外鍵，N 個系統資產碼指向同一 Message-ID。

### G. 倉儲與並發層

**17. DuckDB 檔案被前台查詢鎖死** — `File is locked`。
- 主線：撞鎖時改寫 `/staging/buf_*.parquet`。
- 備援：前台查詢前先 `INSERT INTO vault SELECT * FROM staging` 再清空。

**18. 磁碟爆滿 / 檔案控制代碼耗盡** — 跑全景下載 80GB / `EMFILE`。
- 主線：每次同步前 `disk_usage` 預檢，<3GB 阻斷；全程 `with` 上下文管理。
- 備援：自動回收超過 X 月且未鎖定的暫存；每 100 筆 `gc.collect()`。

### H. 利害關係人與組織層

**19. 同名撞車 / 別名分身** — 兩個「Tony」；`tony@` 與 `tony.huang@`。
- 主線：主鍵用 `Hash(姓名+網域+簽名檔部門)`，不用人名。
- 備援：查 In-Reply-To 鏈，回信 From 與原收件不同但同串 → 綁為同一實體（標信心）。

**20. 黑箱老闆 / 離職帳號借屍還魂** — 只被 CC 不發信；簽名檔人名突變。
- 主線：`CC_Received>50 且 Sent==0` → 標 `EXECUTIVE_BLACKBOX`，催辦改指派部門代理人。
- 備援：偵測簽名檔人名穩定突變 → append 新紀元（Epoch），節點時空分裂為 A/B 兩期，歷史不覆寫。

## 四、台灣 B2B 現場「規格書外」的隱藏意外（補充警示，非程式能全解）

1. **線下決策斷層**：信只寫「如電話/LINE 所述，請照辦」→ 系統標 `CONTEXT_GAP` 黃旗，提醒人補關聯，不假裝資訊完整。
2. **大小章傳真件**：純圖無字 → 走 OCR + 人工複核旗，不靜默當空白。
3. **帳號繼承**：簽名檔突變 → Epoch 分裂，不讓歷史歸屬錯亂。
4. **Outlook 快取時差**：COM 讀到未同步的舊 .ost → 讀取前先 `SendAndReceive` 強制同步握手。

## 五、誠實結語

工程的奧義不是追求 100% 不出錯，而是**「出錯時系統自己知道哪裡錯、並留下無可賴帳的客觀證據」**。本系統的完整性 gate（結構略過/可救回/錯誤三分）正是這個精神：每個失敗都有原因、可稽核、不偽裝。

三個 ⚠ 校正（不猜密碼、不規避存取控制、不弱化 TLS）不是能力不足，而是**讓你把這套工具攤在客戶資安長面前都站得住腳**——這比多一兩個取巧功能更值錢。
