# PMIS-Lite 介面哲學：越簡單越高整合 × 改善再改善計畫

_設計信條：圖像化介面越簡單，代表底層整合度越高。複雜留給引擎，簡單留給使用者。把每個操作降到「點/拖/勾/確定」。_

---

## 一、為何「越簡單 = 越高整合」

介面上每多一個欄位、每多一次打字，都是「底層沒整合好、把工作丟回給使用者」的證據。
- 要使用者打路徑 → 代表沒做自動偵測 → **改用拖曳 + 原生檔案視窗**。
- 要使用者填伺服器 → 代表沒做通道抽象 → **改用下拉選通道**。
- 要使用者寫關鍵字 → 代表沒做自動生成 → **改用核可制點選**。

**結論**：簡單的介面是「整合度的成績單」。每消滅一個輸入框，就是把一塊複雜吃進引擎。

## 二、零鍵盤互動清單（已做成 `launcher_minimal.html`）

| 動作類型 | 用在哪 | 取代了什麼打字 |
|---------|-------|--------------|
| **拖曳** | 把資料夾/檔案丟進拖曳區 | 打檔案路徑 |
| **原生檔案視窗（window I/O）** | 「選資料夾/選檔案」鈕叫出 Windows 檔案對話框 | 打路徑、記目錄 |
| **下拉 / 卡片點選** | 選行業、選通道 | 打行業名、伺服器位址 |
| **搜尋確認（勾選）** | 偵測到的來源逐筆點 ✓/○ 確認納入 | 手動列清單 |
| **勾勾勾（複選）** | 選項（附件/gate/關鍵字/PPT） | 打開關設定 |
| **確定 / 返回** | 步驟前進後退 | — |
| **一鍵產生 ⬇** | 下載 config.json | 手寫設定檔 |

**全程零鍵盤**（唯二例外：貼一次 Gmail App Password、必要時輸入加密檔密碼）。
**拖曳式搜尋確認**：拖入 → 系統自動分類來源型別（Excel/MS Project/郵件/CAD）→ 逐筆點選確認，所見即所得。

## 三、四步互動流（滑鼠三回合的具體化）

```
STEP1 拖曳/選檔（1 動作）
STEP2 點行業 + 點通道（2 點）
STEP3 偵測結果逐筆確認（預設全收，只點掉不要的）
STEP4 勾選項 → 按產生 ⬇（1 點下載 config.json）
```
核心：**預設即最佳**——每步都有合理預設，使用者「不動」也能完成；要調整才點。這是「最少動作」的關鍵。

## 四、改善再改善計畫（Kaizen 閉環，數據驅動）

改善不靠感覺，靠**可量測指標**與**內建回饋**（接已建的 `feedback.py`）。

### 4.1 核心量測指標（越低越好的「動作數」）
| 指標 | 現況 | 目標 |
|------|------|------|
| 完成設定的**鍵盤輸入次數** | 0–1（僅權杖） | 維持 0–1 |
| 完成設定的**滑鼠點擊數** | ~6–8 | ≤5 |
| 從開啟到第一份報告的**步驟數** | 4 | ≤4 |
| 首次見效時間（first value） | 一次跑完 | 縮短（增量先給近月） |
| 失望點回報數 / 版 | 基準 | 逐版下降 |

### 4.2 PDCA 循環（每版一圈）
```
Plan  ── 看 feedback.summarize 排出的補強優先序（被嫌最多的先做）
  ↓
Do    ── 只改最高優先 1–3 項（避免一次動太多 = 九頭龍風險）
  ↓
Check ── 重跑 25 測試 + selfcheck 全綠；量測動作數有無下降
  ↓
Act   ── 達標就鎖版；未達標退回 Plan，標記為下一圈
```

### 4.3 內建回饋閉環（無問卷、無打字、離線）
```
使用者點 👍驚艷 / 👎失望 標籤（滑鼠）
   → feedback.jsonl（append-only）
   → summarize 自動排補強優先序 + 附方案
   → 改 → 再測 → 再點 → 看失望數曲線下降
```

### 4.4 改善優先序（先打「第一印象殺手」）
1. **冷啟動引導（X04）**：第一次就核可前幾個自動關鍵字，當場見效。
2. **雙模式（X14）**：簡單模式藏術語，門外漢不怕。
3. **白話失敗（X15）**：失敗清單講人話 + 建議動作。
4. **增量+進度條（X01）**：首跑只抓近月、有進度感。
5. **動作數再降**：把 6–8 點壓到 ≤5（合併步驟、強化預設）。

### 4.5 「再改善」的紀律（避免越改越亂）
- **每圈只動 1–3 項**，且每動一項都要 25 測試 + selfcheck 全綠才算數（九頭龍互依風險意識）。
- **append-only**：舊版設定/詞庫只增不減，可回溯。
- **動作數是硬指標**：任何改版若讓滑鼠點擊或鍵盤輸入「變多」，視為退步，需重新設計。

---

## 五、一句話總結

把複雜全吃進引擎，介面只剩「拖、點、勾、確定」——**介面越簡單，是整合越深的證明**。而改善要靠內建回饋與動作數指標,一圈一圈地把使用者要動的手指越減越少。
