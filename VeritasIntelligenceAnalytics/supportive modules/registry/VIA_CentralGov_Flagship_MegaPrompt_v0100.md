中文版本(正式核心大腦指令)

請啟動「VIA Central Governance Console 全自動沙盒測試修正系統」,啟用全部 20 個加速器,掛載「中央 SSOT 規範庫與同義字/Regex 治理中心」,對所有已註冊及動態擴充之子系統(VRN / VDF / VAP / 新增子系統)執行三輪全景式分析、自動修正、自動部署、自動整合與穩定化流程。

【核心治理原則與執行指令】
全景式分析後,識別所有指令、代碼與架構錯誤,透過 AST 彈性或精準定位;在「不傷害系統健康、不引發九頭龍連鎖破壞風險(Zero-Hydra Risk)」的絕對前提下:
1. 可同步解決的問題一口氣全數並行解決;
2. 不可同步的問題嚴格依賴拓撲順序逐步解決;
3. 後續六個獨立流程若無阻礙則無限制全力向前推進到底;若偵測到指令錯誤或高風險節點,即刻觸發三輪全景式分析錯誤識別機制,確保系統在最高安全邊界內自動收斂至完美穩定狀態。

## 一、VIA Central Governance Console 核心架構與 SSOT 規範庫
1. **SSOT 規範與同義字 / Regex 治理中心**:
   - 集中管理跨子系統命名實體、欄位定義、語意對照表與正則表達式庫(Regex Library)。
   - 自動消除同義異名、格式衝突與跨模組語意歧義,確保全域資料契約(Data Contracts)一致性。
2. **可擴充子系統模組化介面(Pluggable Subsystem Architecture)**:
   - **VRN** (Veritas Resonance Network)
   - **VDF** (Veritas DataForge)
   - **VAP** (Veritas AutoPlot / Analysis Platform)
   - **新增子系統熱插拔槽**:支援自定義模組(如 VCG-Governance、VEM-Execution、外部 Connector 等)動態掛載、註冊與同步治理。
3. **全函式庫自動註冊與 Python Engine 整合**:
   - 自動掃描、擴充並註冊所有底層函式庫,整合成單一高性能 Python Engine。
4. **非阻塞 PowerShell 啟動器**:
   - 生成專用啟動腳本(launch.ps1),確保背景非同步運作「不關閉、不阻塞、不卡斷」。
5. **自動化環境與路徑配置**:
   - 一鍵自動部署所有模組目錄、環境變數與依賴路徑。
6. **自動跳出 HTML UI Matrix 報告**:
   - 採用 **略小字體(small font)** 呈現高資訊密度。
   - 表格高度與寬度具備 **自適應最佳化佈局(Auto-Optimized Layout)**。
   - 表格文字過長時強制 **自動換行(wrap)**,排版整齊不溢出。
   - 清楚劃分四大標準分區:`MODULE` / `ENGINE` / `FUNCTION-LIB` / `OTHERS`。
7. **即時反饋機制**:內建動態進度條(Dynamic Progress Bar)與動態情境說明(Dynamic Status Narration)。

## 二、三輪全景式分析(每輪循環必做)
每輪修正前後均必須完整執行:
1. **Panoramic Analysis(全景式分析)**:全系統代碼、配置與跨模組呼叫無死角掃描。
2. **Error Identification(全錯誤識別)**:語法、語意、類型、正則匹配與執行期異常全面標記。
3. **AST Elastic / Precision Locating(AST 彈性/精準定位)**:依問題層級切換語意模糊匹配或 AST 精準節點定界。
4. **Optimization Points(優化點定位)**:複雜度、效能瓶頸、記憶體洩漏與冗餘路徑定位。
5. **SSOT & Regex Alignment(SSOT 與正則對齊檢查)**:比對中央同義字庫與 Regex 規則,校正資料歧義。
6. **Hydra Risk Detection(九頭龍風險偵測)**:鎖定高耦合、修改易引發連鎖崩潰之脆弱節點。
7. **錯誤分類與分流**:
   - `Parallel-Fixable`:無副作用、可一口氣同時解決之問題。
   - `Sequence-Dependent`:具相依性、必須依拓撲排序逐步解決之問題。
8. **多子系統同步檢視(Multi-Subsystem Synchronization)**:跨 VRN / VDF / VAP 及動態模組同步治理。
9. **自動產生 HTML UI Matrix**:即時更新紅黃綠燈(RYG)指標、動態進度條與情境說明。

## 三、六個獨立流程無限制同步推進規範(Six Independent Parallel Pipelines)
在隔離沙盒與零九頭龍風險保護下,六大獨立流程若無限制條件則全力推進到底:
- **Pipeline 1: 代碼層 AST 重構與修復流程**(Code AST & Syntax Repair Pipeline)
- **Pipeline 2: 中央 SSOT 與同義字 Regex 校準流程**(SSOT & Regex Normalization Pipeline)
- **Pipeline 3: 子系統依賴解耦與模組註冊流程**(Subsystem Pluggable & Decoupling Pipeline)
- **Pipeline 4: 性能優化、死碼清理與資源回收流程**(Performance & Dead-Code Elimination Pipeline)
- **Pipeline 5: 沙盒多重驗證與回歸測試流程**(Sandbox Verification & Regression Pipeline)
- **Pipeline 6: UI Matrix 渲染與非阻塞部署監控流程**(UI Matrix & Persistent Deployment Pipeline)

## 四、三輪精準修正策略(嚴格限制最多三輪)
- **第 1 輪:全面性修正(Comprehensive Fix)**
  - 一口氣並行解決所有 `Parallel-Fixable` 問題。
  - 嚴格避開並隔離高 Hydra 節點,防範初始崩潰。
- **第 2 輪:順序性修正(Sequential Fix)**
  - 嚴格依照「依賴拓撲排序」逐步修正。
  - 每一修正步驟強制通過沙盒驗證;高風險節點僅輸出安全重構建議,不自動盲修。
- **第 3 輪:收尾與硬化(Final Polishing & Hardening)**
  - 微調、格式化、刪除死碼、性能極致優化,確保系統穩定、乾淨、可維護。
